## 1. 文档说明

### 1.1 一句话业务

排餐计划排好后天，采购员按**一段周期区间**建一份采购计划，系统把这些天菜谱要用的投料汇总成“用料清单”，采购员把每个标准食材映射到具体商品、按天填好预计采购量，然后发给供应商询价，收完报价逐个商品定标。

### 1.2 本期范围

| 在范围内 | 不在范围内（见 §9） |
| --- | --- |
| 采购计划（草稿态可编辑）、商品映射、采购明细、发起询价、询价单、报价比较、定标 | 采购订单、供应商端报价界面、撤回/延长/补报、克→箱袋换算、自动比价推荐与自动定标、多档口合并采购、餐次维度 |

### 1.3 事实来源标注

| 标记 | 含义 |
| --- | --- |
| 【规则】 | 业务规则，开发必须实现 |
| 【原型】 | 原型已实现，照原型做 |
| 【本期新增】 | 原型没有、本轮决策新增，需开发改造 |
| 【改造】 | 原型行为与本文不一致，按本文改造 |

### 1.4 术语

| 术语 | 定义 |
| --- | --- |
| 标准食材 | 平台标准食材库中的食材（如“土豆”“生抽”）。菜谱用料里未直挂商品的即标准食材 |
| 商品 | 商户端商品中心的商品，有加工形态（毛菜／净菜／半成品）与「关联标准食材」 |
| SKU | 商品下的规格单元，有采购规格与下单单位（箱／袋／桶／吨…）。采购侧真正下单的对象 |
| 映射 | 把一条标准食材用料指定到一个 SKU；也是“商品映射”页签的名字 |
| 材料行 | 商品映射与采购明细里的业务行，一个用料一行 |
| 按天覆盖 | 在采购明细里对某一天单独指定商品，只影响那天 |
| 按天填量 | 在采购明细里逐天填的“预计采购量”，单位是 SKU 的下单单位 |
| 同期 | 同一档口下，**需求起始日与结束日完全相同**的多份采购计划 |
| 在途 | 报价还没结束：询价单处于「询价中」或「已截止」。“已定标”“已流标”都不算在途【本期新增】 |
| 流标 | 定标提交时**一个商品都没选定供应商**（0 成交），本轮询价作废，计划置「已流标」终态【本期新增】 |
| 快照 | 发起询价时冻结的询价单内容，之后不随计划变化 |

### 1.5 角色、数据范围与入口

| 角色 | 在本模块做什么 |

| 系统 | 派生用料、按截止时间置状态、超时置未报价；不做任何自动定标 |

| 项 | 口径 |
| --- | --- |
| 数据归属 | 采购计划、映射记忆、询价单**全部挂在档口**上；组织层只做汇总入口 |
| 权限 | 沿用商户端既有角色与按钮权限体系，本文不另设权限点 |
| 菜单入口 | 计划管理 › 采购计划。询价单、比价、定标都是详情页里的页签／抽屉，**不单开菜单** |
| 上游依赖 | 排餐计划（已保存）＋ 菜谱 BOM 用料（含“计入投料”标记与直挂 SKU） |
| 商品依赖 | 商品中心：商品状态、加工形态、关联标准食材、SKU 规格与下单单位 |
| 供应商依赖 | 供应商管理：启用中的供应商 |

## 2. 业务流程图

> 一条主线、六个出口，用表说清；需要泳道图时照 §2.1 三列转绘即可，节点名不要另起。

### 2.1 主线：谁在哪一步做什么

| 步骤 | 采购员 | 系统 | 供应商 |
| --- | --- | --- | --- |
| F1 上游 | — | 读该档口**已保存**的排餐，按菜谱 BOM 汇总投料；没保存的周不产生用料 | — |
| F2 新建 | 选档口 → 「新建采购计划」，填起止日 | 校验必填 / 起始≤结束 / ≤31 天；有交集**只提示不阻断** | — |
| F3 派生用料 | — | 只取「烹饪投料（计入）」，单位克；同一用料合并成一行 | — |
| F4 映射 | 逐个标准食材选商品；找不到就整段忽略 | 候选只给「关联了该标准食材的已发布商品」，不兜底全量 | — |
| F5 填量 | 进入「采购明细」，按天填预计采购量 | 拦截未映射、任一天未填量 | — |
| F6 发起询价 | 选供应商、设截止时间（≥1 小时后） | 校验通过 → 生成询价单快照，**计划立即锁定** | 收到询价 |
| F7 报价 | — | 询价中；同一时刻只允许 1 份在途询价单 | 可报全、报部分、不报 |
| F8 截止 | — | 到点自动置「已截止」，未报的置「超时未报价」 | 不可补报 |
| F9 比价 | 打开「报价比较」看矩阵 | 只摊开价格并标最低价，**不做推荐** | — |
| F10 定标 | 逐个商品选供应商 → 确认定标 | 记录定标结果，锁为终态；**0 个成交则置「已流标」** | — |
| F11 收尾 | 关闭计划 | 本期**不生成订单**、不推送供应商 | — |

### 2.2 分支与出口

| 分支 | 触发 | 结果 |
| --- | --- | --- |
| 区间内没有排餐 | 整段区间都没排餐 | 允许创建，但没有用料行，发起时被 A1 拦下（§6.5.1） |
| 食材没有关联商品 | 标准食材行的候选为空 | 抽屉只给说明 + 取消；该行只能整段忽略，否则被 A2 拦下 |
| 用量没填完 | 某天某行数量为 0 或留空 | 被 A3 拦下，并列出涉及的天与项 |
| 0 家报价 | 到点没有任何供应商报价 | 比价全 `-`；仍可提交定标，提交后置「已流标」；重来只能另建**同期**计划 |
| 要改已发出的询价 | 询价中 / 已截止 / 已定标 / 已流标 | 不能撤回、不能延长截止、不接受补报，只能另建同期计划 |
| 已定标／已流标后又想改 | 终态 | 整份计划只读，不可删除、不可再发起询价 |

## 3. 选档口（组织层）

采购计划只挂在**档口**上。进入本页先落在组织层的档口总览，选到具体档口才进列表干活。

### 3.1 两种形态

| 形态 | 触发 | 页面 | 能做什么 |
| --- | --- | --- | --- |
| **组织层总览** | 档口选择器选「全部档口（总览）」；首次进入本页的默认 | 总览页 | 看该组织各档口卡片、点卡片进档口；**没有新建按钮** |
| **档口层** | 在总览点某个档口卡片；或切换器选到具体档口 | 列表页、详情页 | 新建、编辑、发起询价、比价、定标 |

### 3.2 档口卡片

卡片内容（自上而下）：档口名称 → 负责人 → 营业餐次标签 → 底部提示行 → 「进入采购计划 ›」。点整卡进入该档口列表。

**底部提示行文案规则**【规则】

| 条件 | 文案 |
| --- | --- |
| 该档口计划数 N = 0 | `暂无采购计划` |
| N > 0 且 在途 M = 0 | `N 份采购计划` |
| N > 0 且 在途 M > 0 | `N 份采购计划 · M 份询价在途` |

- 例如 14 份计划、8 份在途，显示 `14 份采购计划 · 8 份询价在途`（数字与汉字间半角空格，两项之间用 ` · `）。
- N = 该档口**全部**采购计划（不分状态）。
- M = 该档口**最新一份询价单**状态为「询价中」或「已截止」的计划数。**「已定标」「已流标」都不计入在途**。
- 其他文本：负责人取档口负责人，格式 `姓名 · 电话`，未指定时显示 `未指定负责人`；餐次取档口管理里配的营业餐次，格式 `午餐 11:00–13:00`。
- 页头说明固定：`由排餐计划自动派生这些天的用料；采购计划只挂在档口上，先选档口再看清单`；区头标题 `${组织名}的档口`。

### 3.3 切换动作与结果

| 动作 | 数据范围 | 视图 | 其它 |
| --- | --- | --- | --- |
| 选「全部档口（总览）」 | 当前组织全部档口 | 回到总览页；退出详情 | 返回总览后不再被默认值拉进某个档口 |
| 选具体档口 | 换成该档口 | 若当前在详情 → **退回列表**；页签回「商品映射」、日期 tab 清空 | 状态筛选重置为「全部」【本期新增】 |
| 点档口卡片 | 同“选具体档口” | 同上 | — |
| 切组织（当前在总览） | 新组织全部档口 | 停在总览 | 无档口 → 空态 |
| 切组织（当前在某档口） | 新组织 | **回到新组织的总览**（不要自动跳第一个档口）【改造】 | 需一次性标志位避免递归触发 |

### 3.4 全局影响与空态

| 项 | 口径 |
| --- | --- |
| 跨页联动 | 切换器状态全局共享：在本页换了档口，排餐计划、生产计划的当前范围一起变 |
| 未保存内容 | 采购计划的改动**即时保存**，切换范围不弹“未保存”拦截；排餐计划的拦截不作用于本页 |
| 组织层汇总口径 | 卡片统计按档口分别计算，不跨档口合并 |
| 无次级组织 | 组织下拉禁用，展示“暂无次级组织” |
| 该组织无档口 | 档口下拉禁用，展示“该组织暂无档口”，并提供「去建档口」入口；总览显示“暂无档口，请先创建档口” |
| 档口被删除 | 该档口的计划与询价单一并处理：**有在途询价单、或有已定标计划时禁止删除档口**；仅有草稿计划时提示“该档口有 N 份采购计划，删除后一并删除”【本期新增，见 §8.2】 |

## 4. 采购计划列表（档口层）

### 4.1 页头与操作

| 区块 | 内容 |
| --- | --- |
| 页头 | 标题「采购计划」+ 说明 `按「档口 × 周期区间」各一份计划；同一档口的多份计划可以区间重叠，互不覆盖` |
| 操作 | 右上角「＋ 新建采购计划」 |
| 位置提示 | 筛选行右侧显示 `当前档口：档口名` |

### 4.2 筛选与排序

| 项 | 口径 |
| --- | --- |
| 筛选 | `全部 N` / `草稿` / `询价中` / `已截止` / `已定标` / `已流标`（只有“全部”带数量） |
| 排序 | 更新时间倒序，其次起始日倒序 |

### 4.3 表格列

| 列 | 取值 |
| --- | --- |
| 需求周期 | `起始日 ~ 结束日`，天数 = 结束−起始+1；同期第 2 份起追加标签 `同期第 X 份`（§5.5） |
| 状态 | 由最新询价单派生（§6.2）；无询价单=草稿 |
| 当前询价单 | 有：单号；状态为询价中／已截止时追加 `截止 YYYY-MM-DD HH:mm`；无：`尚未发起` |
| 明细行 | 材料行数量（含菜谱直挂、手工添加） |
| 更新时间 | 最后一次编辑时间；只读查看不刷新 |
| 操作 | 「查看」；**仅草稿**额外给「删除」 |

### 4.4 空态

`暂无采购计划` + `点击右上角「新建采购计划」，选一段周期区间即可由排餐计划自动生成商品映射。`

### 4.5 删除计划【规则】

| 场景 | 结果 |
| --- | --- |
| 可删条件 | **只能删草稿**（没有任何询价单）。询价中／已截止／已定标／已流标不显示删除入口 |
| 删除确认 | 原生 confirm：`确认删除采购计划「起始 ~ 结束」？` |
| 删除动作 | 删该计划及其按天填量、材料行、映射覆盖；连带删该计划的询价单数据（草稿态本来没有） |
| 对其他同期计划 | **无影响**，其余计划编号不变、不重排、不回收空号。可能出现「同期第 1 份」与「同期第 3 份」并存 |
| 对档口卡片 | 计划数减 1；若减到 0 → 卡片回到 `暂无采购计划`；在途数按最新询价单重算 |
| 对上游/记忆 | 不改排餐计划；不删“档口 × 标准食材”的映射记忆 |
| 对新计划编号 | 后续新建取现有最大序号 + 1，**不复用被删掉的号**（§5.5） |
| 反向约束 | 已删计划无法恢复；若想复购同区间，就是新建一份新的同期计划 |
| 服务端防呆 | 绕过界面删除非草稿计划时，系统应拒绝并返回原因。**这句只作后台校验，界面不展示**（界面本来就没有删除入口） |

## 5. 新建采购计划

### 5.1 入口与填写项

- 仅档口层列表有「＋ 新建采购计划」；组织层总览没有。
- 抽屉填写项：「需求起始日 *」「需求结束日 *」，默认**本周一 ~ 本周日**。

### 5.2 校验【规则】

| # | 校验 | 不通过提示 |
| --- | --- | --- |
| 1 | 起止日必填 | `请填写需求周期` |
| 2 | 起始日 ≤ 结束日 | `起始日不能晚于结束日` |
| 3 | 区间天数 ≤ 31 天 | `周期最长 31 天，请缩小范围` |

### 5.3 范围预览【本期新增】

选完日期后实时展示：

`区间内：命中 5 天 · 无排餐 2 天 · 菜品 18 道`

| 指标 | 口径 |
| --- | --- |
| 命中天数 | 区间内至少有一道菜的日期数（取该档口**已保存**的排餐，逐餐次累加菜品） |
| 无排餐天数 | 区间内一道菜都没有的日期数 |
| 菜品数 | 区间内所有菜次里的菜品总道数（同一道菜不同天各算一次） |

- 无排餐天数 > 0 时补一句：`这几天不会生成用料，确认这些天不需要采购吗？`（只提示，不阻断）。
- 预览只读已保存排餐；原型里“没保存就自动种一份演示排餐”的行为**正式版必须去掉**【改造】。

### 5.4 重复与交集【规则】

| 判定 | 条件 |
| --- | --- |
| 完全重复 | 同档口，起止日都相同 → 属于“同期” |
| 区间有交集 | 同档口，`起始1 ≤ 结束2 且 起始2 ≤ 结束1`（含完全重复） |

处理：

1. **都不阻断创建**，只在点「创建并生成商品映射」时弹交集提醒。
2. 弹窗标题：`已有相似时间的采购计划`；正文：`档口名 在 起始 ~ 结束 这段需求周期已有 N 份采购计划（其中 M 份区间完全相同）`；区间只交集时写 `（区间存在交集）`。
3. 弹窗列表每项：区间、天数、状态、询价单号（无则 `未发起询价`）。
4. 弹窗说明固定：`同一档口的多份计划可以同时存在，互不覆盖：各自独立询价、独立定标，重叠天数不会自动合并或作废已定标结果。若只是想改已有计划，建议直接打开它编辑。`
5. 按钮：`否，先看看已有的` / `是，仍要新建`。选后者才真正创建。
6. 其它档口同区间的计划不算冲突。

### 5.5 同期第 X 份（编号与显示）

| 项 | 口径 |
| --- | --- |
| 同期 | **同一档口 + 起始日与结束日完全相同**。只是有交集不算同期 |
| 编号 | 同区间已有计划的最大序号 + 1；首份 = 1【本期新增，永不复用】 |
| 显示 | 同期第 2 份起显示「同期第 X 份」；第 1 份不显示标签 |

显示位置（三处，文案一致 `同期第 X 份`）：列表“需求周期”列（§4.3）、详情页标题旁（§6.1）、创建成功的 toast（§7.4）。

删除对编号的影响：只删被删的那一份，不重排、不回收空号，后续新建取现有最大序号 + 1（§4.5）。

### 5.6 创建结果

1. 生成材料行（§6.3.1）与空的按天层。
2. 若为同区间第 N 份（N≥2）：编号追加（§5.5），toast `已新建同期第 N 份计划，商品映射已生成（与原计划互不覆盖）`。
3. 首份：toast `商品映射已生成，先选商品，再到「采购明细」按天填预计采购量`。
4. 直接进入该计划详情，停在「商品映射」页签。

## 6. 采购计划详情

详情页由「页头 + 统计条 + 三个并列页签」组成：商品映射 → 采购明细 → 询价单。

### 6.1 页头与统计

| 元素 | 内容 |
| --- | --- |
| 返回 | `‹ 返回列表` |
| 标题 | `起始日 ~ 结束日` + 状态标签 + （同期第 2 份起）`同期第 X 份` |
| 副标题 | `N 天　·　档口：档口名　·　全部餐次` |
| 统计条 | `N 项用料 · M 个商品 · 已映射 x/N`（口径见 §6.3.2） |
| 右侧 | 「发起询价」按钮；已锁定时禁用（§6.5.1） |

页签：`商品映射`、`采购明细`、`询价单`（未发起时标题写 `询价单（未发起）`）。两个页签各带一个 `?` 说明：

- 商品映射：`这里你可以决定「这个用料买哪个商品」，一次决定作用于所有日期（「采购明细」也可按天微调）；具体哪天买多少，到「采购明细」按天填写。`
- 采购明细：`这里你可以调整当天要采购的商品和填写预计采购量，全部填写好后，您点击右上角「发起询价」按钮，选择供应商发起询价`。

### 6.2 状态与锁定

#### 6.2.1 采购计划 5 态（由询价单派生）

| 状态 | 判定 |
| --- | --- |
| 草稿 | 该计划没有任何询价单 |
| 询价中 | 最新询价单状态=询价中，且当前时间 < 截止时间 |
| 已截止 | 最新询价单状态=询价中，且当前时间 ≥ 截止时间；或系统已置为已截止 |
| 已定标 | 最新询价单状态=已定标（终态）：定标提交时**至少 1 个商品**选定供应商 |
| 已流标 | 最新询价单状态=已流标（终态）：定标提交时**0 个商品**成交【本期新增】 |

【规则】状态由**最新一份询价单**决定。因为发起后不可撤回、不可重复发起，实际上一份计划最多只有一份询价单。
【规则】「已定标」与「已流标」都是终态，二者的区别只在**有没有成交商品**：有成交=已定标，全无成交=已流标。

#### 6.2.2 状态对交互的影响【规则】

| 状态 | 商品映射 | 采购明细 | 发起询价 | 删除 | 比价 | 定标 | 重新生成 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 草稿 | 可编辑 | 可编辑 | 可（校验通过） | 可（二次确认） | — | — | 可 |
| 询价中 | 只读 | 只读 | 按钮禁用 | 不显示删除入口 | 可看 | 可（0 成交走流标） | 不可 |
| 已截止 | 只读 | 只读 | 按钮禁用 | 不显示 | 可看 | 可（0 成交走流标） | 不可 |
| 已定标 | 只读（终态） | 只读（终态） | 禁用 | 不显示 | 可看 | 不可 | 不可 |
| 已流标 | 只读（终态） | 只读（终态） | 禁用 | 不显示 | 可看 | 不可 | 不可 |

- 锁定粒度是**整份计划**（两个页签一起锁），不是只锁与询价相关的部分。
- 锁定后仍可看：「依据」抽屉、报价比较。
- 锁定提示条文案见 §7.3。

#### 6.2.3 供应商应答 3 态（询价单内，每家一份）

| 状态 | 含义 | 后果 |
| --- | --- | --- |
| 待报价 | 已发出，未到截止 | 可被催（本期不做，见 §9） |
| 已报价 | 已提交报价 | 参与比价、可被定标 |
| 超时未报价 | 到截止仍未提交，系统自动置位 | 不参与比价、不可被定标、**不接受补报** |

「已作废」状态保留在数据模型里但本期不产生（无撤回机制）。

#### 6.2.4 到点生效规则

【改造】「已截止」与「超时未报价」必须在到达截止时间时自动生效，不能等用户打开页面才变；到点判定以服务端时间为准。

### 6.3 页签一：商品映射

#### 6.3.1 这是什么

材料层：**一行 = 一个用料**，只回答“这个用料买哪个商品”。不填量、不管哪天。数据来自排餐计划 + 菜谱 BOM，由系统派生。

| 行类型 | 出现条件 | 示例 |
| --- | --- | --- |
| 标准食材行 | 菜谱用料未直挂商品 | 土豆、生抽 |
| 菜谱直挂行 | 菜谱用料已直挂商品 | 海天生抽 500ml×12 |
| 手工添加行 | 采购明细里「添加商品」 | 临时加购的饮用水 |

派生口径（只讲结果，不讲过程）：**逐日 → 逐餐次 → 逐菜品 → 逐投料行**，用量（克）= 投料量（克）× 锅数，只取「烹饪投料（计入）」，过程用料（不计入）不取；单位恒为克；不做克→箱/袋换算。

【规则】只统计能折算成克的投料；不可折算为克的行本期不进采购计划。

#### 6.3.2 页面布局与列数据源

页头统计：`N 项用料 · M 个商品 · 已映射 x/N`。N = 未被整段忽略的材料行数；M = 最终会用到的 SKU 去重数（只算“当天真的用到且没被忽略”的行）；x = 其中已映射的行数。

| 列 | 数据源 |
| --- | --- |
| 用料 / 商品 | 标准食材行显示食材名 + 标签`标准食材`；直挂/手工行显示商品名 + 标签`菜谱直挂`／`手工添加` |
| 合计克数 | 该行所有依据明细的克数之和；手工添加行显示 `—` |
| 当前商品 / 规格 | 该行已选的商品 → 商品名（+形态标签）、SKU 规格、下单单位；未选显示 `待选择` |
| 操作 | `选择商品`（未选）/ `更换`（已选）/ `依据` / `删除`（仅手工添加行）/ `整段忽略`（标准食材行与直挂行）【本期新增，**原型没有这个按钮**，见 §6.3.6】 |

分组与排序：标准食材行在前，按合计克数倒序；分隔行 `菜谱直挂商品`（说明：`菜谱用料已直接绑定 SKU，采购侧无需选择；手工添加的行也归在这里`），其后是直挂与手工行，组内同样按克数倒序。

#### 6.3.3 候选商品规则（本页最重要的一条）【规则】

| 行类型 | 候选商品范围 |
| --- | --- |
| 标准食材行 | 本组织商品中心中**状态=已发布**的商品，且该商品的「关联标准食材」**包含这个食材** |
| 菜谱直挂行 | 不可更换（菜谱已绑定 SKU），无候选 |
| 手工添加行 | 本组织商品中心中状态=已发布的所有商品（没有食材语境，允许任选） |

- 「关联标准食材」是商品上的属性：毛菜关联 1 个、净菜关联 1 个或多个、**半成品不关联**。因此半成品永远不会出现在标准食材行的候选里；要用半成品只能走菜谱直挂或手工添加。
- 草稿／已下架商品不可选。
- 找不到关联商品时，选商品抽屉不展示列表，只显示：`该标准食材暂无已发布的关联商品，请到「商品中心」补充关联关系；或对本行执行「整段忽略」。` 并只保留「取消」。
- 这一行如果不能映射，就**不能发起询价**（§6.5.1 A 类校验）；唯一出路是「整段忽略」或去商品中心补关联。

#### 6.3.4 选商品抽屉

两步：①按名称／加工形态／分类筛选商品 → ②点 SKU 卡片即时生效（无“确定”按钮）。

| 元素 | 说明 |
| --- | --- |
| 搜索 | 商品名称模糊匹配 |
| 加工形态 | 全部／毛菜／净菜／半成品（只在候选池里出现的值内筛） |
| 分类 | 二级分类，取自候选池，不列无关品类 |
| 列表列 | 商品名称（+编码）、分类路径、加工形态、SKU 数、操作`选择` |
| SKU 卡片 | SKU 名称、`采购规格`、`下单单位`；当前在用的标「当前」 |

副标题带上下文：`标准食材名　合计用料 X 克`。

#### 6.3.5 操作反馈

| 操作 | 结果 |
| --- | --- |
| 选择 / 更换（全局） | 记住该行选中的商品；标准食材行同时记住“档口 × 食材”，下次新建计划自动带出（优先级：本计划已选 > 档口记忆） |
| 依据 | 打开「依据」抽屉：列 日期、星期、餐次、菜品、锅数、用量（克）、当日合计；底部固定口径说明 |
| 删除（手工行） | 删该行及其按天填量 |
| 整段忽略（标准食材行与直挂行）【本期新增，按钮待开发新增】 | 整份计划所有天都不采购这个用料（§6.3.6） |
| 重新生成【本期新增】 | 草稿态可用，按当前已保存排餐重算材料行（§6.3.7） |

#### 6.3.6 「整段忽略」是新增按钮（与「按天忽略」的区别）

**原型现状（重要）**：商品映射页每行只有 `选择商品`／`更换` + `依据`（手工添加行多一个 `删除`），**没有任何忽略按钮**；忽略目前只存在于采购明细页的“当天行”上。所以「整段忽略」是**本版新增的行内按钮，开发要新加**，不是改现有按钮。

| 对比项 | 整段忽略【新增】 | 按天忽略【原型已有】 |
| --- | --- | --- |
| 位置 | 商品映射页，行操作 | 采购明细页，当天行操作 |
| 原型 | **无**（需新增） | 有（`忽略（仅当天）`） |
| 作用范围 | 整份计划的所有天 | 仅当天 |
| 数据 | 整段忽略标记 | 当天忽略标记 |
| 影响 | 该行不进明细、不进询价、不参与校验；统计里不再算“待映射” | 仅当天为 0，其他天照常；当天进入“当日已忽略”区，可恢复 |
| 恢复 | 表格下方“已整段忽略”分组里的「恢复」 | 当日已忽略区的「恢复当天采购」 |

**为什么需要它**：标准食材行如果**没有任何已发布商品关联**（或本档口明确自采，如水、时令菜），采购员既不能映射、也不能发起询价。按天忽略要一天一天点，跨 30 天就是 30 次；整段忽略一次解决。

**新增按钮的交互规格**：

| 项 | 规格 |
| --- | --- |
| 位置 | 商品映射表格“操作”列，放在 `依据` 之后（手工行放在 `删除` 之前） |
| 文案 | `整段忽略`（危险色文字按钮，与现有 `删除` 同级样式） |
| 可见性 | 标准食材行、菜谱直挂行可见；手工添加行不显示（用 `删除`）；锁定态隐藏 |
| 二次确认 | 原生 confirm：`整段忽略「食材名」？本计划所有日期都不再采购该用料，可随时恢复。` |
| 忽略后 | 该行从主表移到表格下方「已整段忽略（N 项）」分组，列同主表，操作只留 `恢复`；合计克数照常显示（便于事后核对） |
| 恢复 | 点 `恢复` 即回到主表，原已选商品保留 |
| 统计 | 页头 `N 项用料`、卡片 `x 项待映射` 都不再计入已整段忽略的行 |
| 与明细联动 | 采购明细里该行的所有日期不再出现；若因此某天没有其它用料，该天的 tab 也一并消失 |

使用场景：某个食材本档口自采（如水、时令菜）、或商品中心还没维护好关联商品。

> 如果本期不想新增这个按钮，替代方案是“只能逐天在采购明细里忽略”，但无关联商品的食材在跨多天时会很麻烦；建议按上表新增。

#### 6.3.7 重新生成【本期新增】

- 入口：商品映射页卡头右侧按钮「重新生成」，仅草稿态可用。
- 作用：按**当前已保存排餐**重算材料行与依据克数。
- 保留：本计划已选商品、整段忽略标记、按天覆盖、按天填量（按材料行对齐）。
- 清除：材料行消失后，其按天填量与覆盖一并清除。
- 若排餐口径未变化（材料行键与克数签名一致）：toast `排餐没有变化，无需重新生成`。
- 成功：toast `已按当前排餐重新生成：新增 X 项、移除 Y 项、保留 Z 项`。

#### 6.3.8 锁定态

只读时隐藏所有编辑按钮（选择／更换／删除／整段忽略／重新生成／添加商品），保留「依据」。页顶提示条见 §7.3。

### 6.4 页签二：采购明细

#### 6.4.1 日期 tab

| 项 | 口径 |
| --- | --- |
| 有哪些天 | 未被整段忽略的材料行的依据明细日期 ∪ 手工添加行所在的日期；**没有用料的天不出现** |
| 排序 | 日期升序 |
| 标签 | `MM-DD 周X`；当天还有几项已映射的行没填量时，右上角显红色数字角标 |
| 默认选中 | 今天在范围内则选今天，否则选第一天 |
| 当天无行 | 显示空态：`这一天的用料都被忽略了，可在下方恢复。` 或 `这一天没有用料。可以点右上角「添加商品」补一行。` |

角标数 = 当天“已映射商品且预计采购量 ≤ 0”的行数。

#### 6.4.2 表格列数据源

| 列 | 数据源 | 说明 |
| --- | --- | --- |
| 当日用料（克） | 该行当天依据克数之和 | 手工添加行显示 `—` |
| 映射商品 | 当天单独指定过就用当天的商品，否则用该行全局商品；两者都没有=未映射 | 显示商品名 + 形态标签；当天单独指定的加标签`当日指定`；未映射显示食材名 + `待映射` |
| 规格 | SKU 采购规格 | — |
| 下单单位 | SKU 下单单位 | — |
| 预计采购量 * | 人工填写的预计采购量 | 必填；单位=下单单位；未映射时输入框禁用，占位 `必填` |
| 操作 | `依据`／`更换商品（仅当天）`／`恢复默认`／`忽略（仅当天）` | 直挂行不提供“更换商品” |

排序：按当日克数倒序（手工行无克数，排最后）。

表尾：`当日合计` + 当天克数合计；右侧 `已填 X/Y 项`（Y = 当天已映射商品的行数，X = 其中填了量的行数；未填满时数字变橙）。

#### 6.4.3 按天覆盖与填量规则【规则】

| 项 | 口径 |
| --- | --- |
| 当天换商品 | 只改当天的商品，其他天仍用该行全局商品；标 `当日指定`，可「恢复默认」 |
| 直挂行 | 商品由菜谱绑定，采购侧不可更换，只能整段忽略或当天忽略 |
| 填量必填 | **每天、每条已映射商品的行都必须填**，且 > 0，最多 2 位小数。留空等于没填，会被拦在发起询价之前 |
| 不买的写法 | 用「忽略（仅当天）」，不要留空 |
| 当天忽略 | 该行当天移入下方“当日已忽略”区（显示 `不计入`），可「恢复当天采购」；不影响其他天 |
| 添加商品 | 当天加一行手工商品（可选全部已发布商品），无克数依据；加完必须填量 |
| 数量口径 | 数量是**该 SKU 的下单单位数量**（箱／袋／桶／吨），系统不换算，只把克数摆在旁边供判断 |

#### 6.4.4 按天覆盖如何影响询价（举例）

10-22 用 A 商品的 3 箱，10-23 单独换成 B 商品的 2 箱 → 发起询价时同一食材会拆成**两条询价行**（A 合计 3、B 合计 2），每条都带自己的按天需求。

### 6.5 页签三：询价单

#### 6.5.1 发起询价

**入口**：详情页右上「发起询价」（锁定态禁用，原因见提示条 §7.3）。

**A 类：状态类，打开抽屉就算好，不通过则「确认发起」禁用并列出原因**

| # | 校验 | 提示文案 |
| --- | --- | --- |
| A1 | 存在至少一条“至少有一天要采购”的材料行；整段忽略的行、所有天都被忽略的行不算 | `没有可采购的用料，无法发起询价` |
| A2 | 所有生效的标准食材行都已映射商品 | `还有 N 项标准食材未选择商品：甲、乙、丙（最多列 5 个，超出加“等”）` |
| A3 | 每天、每条已映射商品的行都填了量（> 0） | `预计采购量为必填：还有 N 项没填（MM-DD 商品名…最多 5 个），涉及 M 天` |
| A4 | 至少有一个可询价的 SKU | `没有任何可询价的商品` |

**B 类：抽屉输入类，点「确认发起」时校验**

| # | 校验 | 提示 |
| --- | --- | --- |
| B1 | 截止时间必填 | `请填写报价截止时间` |
| B2 | 截止时间 ≥ 当前时间 + 1 小时（默认 +24 小时） | `报价截止时间需晚于当前时间 1 小时` |
| B3 | 至少选 1 家供应商 | `请至少选择 1 家供应商` |

A 类决定「确认发起」按钮是否可用；B 类在点「确认发起」时校验，不参与按钮置灰（否则勾选供应商前后按钮状态会不一致）。

**抽屉内容**

| 元素 | 说明 |
| --- | --- |
| 标题 | `发起询价`；副标题 `起始 ~ 结束　共 M 个商品` |
| 未通过的校验 | 以红框列出 A 类原因 |
| 报价截止时间 | 日期时间选择器，必填；最小值=当前+1 小时；默认=当前+24 小时；下方说明：`报价截止时间规则：必须选择当前时间 1 小时以后的时间，以便给予供应商报价缓冲时间。` |
| 受邀供应商 | 复选框列表；本期候选=**全部启用中的供应商**（不按商品覆盖过滤）【本期新增】；默认勾选上次为该计划选过的供应商 |
| 按钮 | `取消` / `确认发起`（A 类不通过时禁用） |

**提交结果**【规则】

| 项 | 口径 |
| --- | --- |
| 唯一在途 | 同一计划同一时刻只能有 1 份在途询价单；已有则阻断，提示 `该计划已有询价单，不能再发起` |
| 幂等 | 重复点击/并发提交只允许成功一次（同一计划只有 1 份在途询价单） |
| 快照 | 生成询价单，冻结：受邀供应商、每个 SKU 的合计数量、按天需求、商品名/形态/规格/下单单位；之后计划再怎么变都不影响已发出的询价单 |
| 供应商合并 | 按“生效 SKU”合并：同一天被覆盖成另一个 SKU 会拆成两行；同 SKU 多行数量相加 |
| 计划变化 | 状态→询价中；两个页签变只读；删除入口消失；按钮变禁用 |
| 跳转 | 自动切到「询价单」页签 |
| 提示 | `询价单 INQ… 已发起，已通知 N 家供应商` |
| 不可撤回 | 询价中／已截止／已定标都不能撤回，截止时间不能延长；要重来只能另建一份**同期**计划（§5.5） |

**询价单号**：原型 `INQ + yyyyMMdd + 2 位流水`（如 `INQ2026102201`）。正式版由后端生成并保证全局唯一，前端只展示。

**按钮显隐**

| 按钮 | 显示条件 |
| --- | --- |
| 报价比较 | 有询价单即可 |
| 定标 | 状态=询价中或已截止即可点，**不要求有报价**（0 家报价也能提交，提交即流标）；已定标／已流标无入口 |
| 模拟供应商回价 | 仅原型演示用，**正式版删除**【改造】 |

**空态与异常**

| 场景 | 处理 |
| --- | --- |
| 还没发起 | 空态 `尚未发起询价` + 引导文案（先选商品、再按天填量、再发起）+ 按钮「前往商品映射」 |

#### 6.5.3 报价比较

**入口**：询价单页签「报价比较」→ 整单矩阵；询价单明细行「N 家已报」→ 只看这一行。

| 项 | 口径 |
| --- | --- |
| 行 | 询价单商品行（商品、形态、规格、下单单位、合计数量） |
| 列 | 本单受邀供应商，每列表头显示应答状态与 `已报 M/N 项` |
| 单元格 | 该供应商对该商品的报价（元）；无报价显示 `-` |
| 最低价 | 每行取有效报价最小值，绿色高亮；同价并列全部高亮 |
| 缺报 | 不补、不推算、不填 0 |
| 总价 | **不计算、不排序、不给推荐** |
| 单位 | 同一行用同一个 SKU 的下单单位，不做任何单位换算 |

明确不做：不按总价或均价排序；不出“推荐供应商”结论、不自动勾选定标；不展示预报价／历史价（价格只看本轮实际回价）。

文案：

- 抽屉标题 `报价比较`，副标题 `起始 ~ 结束　本轮报价矩阵`；
- 表头下方说明：`绿色高亮＝该商品本轮最低价（同价并列高亮）。比价只摊开价格，不做推荐；定标请在「定标」里逐个商品选择。`
- 整单 0 报价：`本轮所有供应商都没有提交报价（超时未报价）。需要重来时请另建一份同期采购计划重新发起。`
- 单行 0 报价：`这一行目前没有任何报价。超时未报价的供应商不会补报；需要重来时请另建一份同期采购计划重新发起。`

#### 6.5.4 定标

**入口条件**

| 条件 | 处理 |
| --- | --- |
| 无询价单 | 无入口 |
| 询价中／已截止 | 可点「定标」，**不要求有报价** |
| 0 家报价 | 按钮可用；进入后所有商品都落在「无供应商报价」分组，提交即流标 |
| 已定标／已流标 | 无入口（终态） |

**抽屉内容**

| 区块 | 内容 |
| --- | --- |
| 顶部条 | `一键选择价格最低的供应商`、`清空供应商`、右侧 `已选 X/Y 个商品 · 预估总价 ¥Z` |
| 表格列 | 商品（+形态）、规格、下单单位、采购量、参考单价（元）、预估总价（元）、操作（供应商下拉） |
| 行分组 | 有报价的商品在上（可选供应商）；`无供应商报价` 分组在下（整行不可选，说明 `N 个商品本轮没有任何供应商报价，不参与定标`） |

**规则**【规则】

| 项 | 口径 |
| --- | --- |
| 定标粒度 | **按商品逐个定标**，一个商品定一家供应商 |
| 可选项 | 下拉里只出现**对该商品报过价**的供应商（带价格），并含首项 `请选择供应商` |
| 无报价商品 | 不出现在可选项里，显示 `无可选供应商` |
| 参考单价 | 所选供应商对该商品的报价 |
| 预估总价 | 参考单价 × 采购量；未选供应商显示 `-` |
| 一键最低价 | 每个有报价的商品自动选最低价供应商（并列时取列表第一家），之后可再逐个调整 |
| 清空 | 全部回到“请选择供应商”，价格两列回到 `-` |
| 未选=不采购 | 没有选供应商的商品视为不采购；一个都不选也能提交（结果=0 个商品成交） |
| 提交校验 | 只在点「确认定标」时求值，不要前置到按钮状态里（否则勾选后不会重新求值） |

**二次确认**【规则】提交前按“无报价”“有报价但未选供应商”两种情况提示；都没有则直接提交。

| 情况 | 标题 | 正文 |
| --- | --- | --- |
| 两者都有，且至少选了 1 个 | `定标结果需要你确认` | `当前定标有 N 个商品无供应商报价，有 M 个未选择供应商，这些商品均不采购，其他商品将锁定定标结果（本期不生成订单），是否确认？` |
| 只有无报价 | 同上 | `当前定标有 N 个商品无供应商报价，无法采购，其他商品将锁定定标结果（本期不生成订单），是否确认？` |
| 只有未选 | 同上 | `当前定标有 M 个商品未选择供应商，将视为不采购，其他商品将锁定定标结果（本期不生成订单），是否确认？` |
| 一个都没选 | `本次定标没有可采购的商品` | `当前定标有 N 个商品无供应商报价，有 M 个未选择供应商，本轮没有任何商品可以定标，提交后将会按流标处理，是否确认？`（只存在一种情况时，前半句只写那一种） |

按钮：`我再看看` / `确认`。

> 【改造】早期原型文案写的是“生成正式订单”，本期不生成订单，统一改为“锁定定标结果（本期不生成订单）”；0 成交时按“提交后将会按流标处理”写（原型已同步）。

**定标结果**【规则】

| 项 | 口径 |
| --- | --- |
| 已定标 | 至少 1 个商品选了供应商：询价单记录每个商品的定标供应商，状态→已定标；计划派生状态→已定标 |
| 已流标【本期新增】 | 一个供应商都没选（0 个商品成交）：状态→已流标，本轮询价作废；**不生成订单、不推送供应商** |
| 终态 | 两种结果都是终态：不可修改、不可取消、不可再发起询价、不能删除计划 |
| 页面 | 计划两个页签只读；已定标时询价单明细行显示 `已定标 · 供应商名`，已流标时不显示；比价仍可看 |
| 提示 | 已定标：`已定标：N 个商品　预估总价 ¥X`；已流标：`本轮无成交商品，询价单 INQ… 已流标（本期不生成订单）` |
| 订单 | **本期都不生成采购订单**（已流标更不会生成） |

| 场景 | 期望行为 |
| --- | --- |
| 区间内一天排餐都没有 | 计划可建，但 0 条材料行；详情提示无用料；不能发起询价 |
| 某食材没有任何关联商品 | 不可映射；阻断发起；可用「整段忽略」放行 |
| 同一食材既有直挂又有未直挂 | 两条材料行，可能映射到不同商品；发起询价时按 SKU 合并 |
| 跨周 / 跨月 | 逐日按“该日所在周的已保存排餐”聚合，不受周切分影响 |
| 同一天同 SKU 来自多行 | 询价行数量相加，按天需求也相加 |
| 某天单独换了 SKU | 拆成两条询价行，各带自己的按天需求 |
| 数量填 0 或留空 | 视为未填，阻断发起 |
| 数量精度 | 与克数一致保留 2 位小数，四舍五入 |
| 截止时间刚好到点 | 以服务端时间为准；到点即不可再报价 |
| 并发/重复提交发起 | 只成功一次，另一次返回“已有在途询价单” |
| 档口被删除 | 有在途询价单、或已定标／已流标计划时禁止删除档口；仅有草稿计划时提示并一并删除 |
| 定标 0 成交 | 允许提交，提交后置「已流标」（终态），不生成订单、不推送供应商；要重来只能另建同期计划 |
| 组织层进入本页 | 只展示总览，不展示计划列表与新建按钮 |
| 商品下架/停用 | 已发出的询价单不受影响（快照）；未发起的计划里该商品需重新选择 |

## 9. 本期不做

1. 克 → 箱／袋／桶 的单位换算（只展示克数，数量由采购员按下单单位填）。
2. 自动推荐供应商、自动定标、按总价自动排序。
3. 询价单撤回、截止时间延长、超时补报、取消定标（含撤销已定标／已流标）。
4. 采购订单生成与推送（定标只锁定结果）。
5. 供应商端报价界面（本期只定数据口径）。
6. 截止前催报价（下期）。
7. 多档口合并采购、跨档口比价。
8. 餐次维度（采购计划恒取该档口全部餐次）。
9. 采购计划审批流。
10. 流标后自动重发询价或自动另建同期计划（本期由采购员手工另建）。
