# 商户端生产计划 PRD

## 0. 文档信息

| 项 | 内容 |
| --- | --- |
| 模块 | 计划管理 / 生产计划（执行侧） |
| 端 | **PC（商户端桌面端）** |
| 原型 | `merchant-production-plan-v1.js`、`merchant-plan-v2.css`、`merchant-meal-plan-v1.js`（派生与口径来源）、`merchant-org-scope-switcher.js` |
| 上游 | 排餐计划（**任务与用量的唯一来源**）、菜谱管理（加工步骤及其设备 = **设备清单**来源）、设备型号主数据（额定容量） |
| 下游 | 采购计划；本模块不产出下游计划 |

**事实来源标注**

| 标注 | 含义 |
| --- | --- |
| 【原型现状】 | 原型已实现，本 PRD 直接固化 |
| 【已确认】 | 原型未表达、已评审确认 |
| 【待确认】 | 需业务 / 研发拍板 |
| 【原型差异】 | 原型与本 PRD 不一致，**以本 PRD 为准** |

> 本模块只做**当日执行确认**：排餐保存后自动派生当日设备菜清单，现场按**设备**逐台记录开工与完成时间。

## 1. 背景与目标

### 1.1 业务问题

| 问题 | 现状 |
| --- | --- |
| 计划执行无记录 | 车间按纸面/口头执行，几点开的火无人记录 |
| 一道菜跨多台设备，进度说不清 | 菜谱里每个加工步骤各自挂设备（焯水一台、烧制另一台）；按整道菜记一个状态，看不出哪台已开工、哪台还没跟上 |
| 锅数说不清 | 现场凭经验分锅，与排餐侧的用量口径对不上 |

### 1.2 本期目标

| 目标 | 衡量口径 |
| --- | --- |
| 当日执行清单可见 | 排餐保存后自动派生，无需二次录入 |
| 多设备进度可见 | 一道菜跨多台设备时**按设备分行**，各自显示设备、加工时间、状态与操作 |
| 现场两下完成确认 | **每台设备**各自只有「开始生产」「完成」两个动作 |
| 用量口径与排餐一致 | 锅数 / 出品量 / 入锅投料总量**全部只读**排餐口径 |

### 1.3 本期范围

| 范围 | 内容 |
| --- | --- |
| 页面范围 | 组织 / 档口两级范围，与排餐计划共用同一个范围切换器 |
| 清单派生 | 按天派生当日设备加工任务，并按菜谱加工步骤展开出这道菜涉及的**设备**（内容只读排餐与菜谱，不新增计划数据） |
| 现场执行 | 任务表（多设备分行）、按设备的三态状态机、开始生产（定该台设备的开工时间）、完成、撤销开工（均逐台独立） |
| 组织方式 | 按餐次分段，支持餐次 / 状态筛选与当日统计 |

## 2. 角色与场景

| 角色 | 使用环境 | 主要动作 |
| --- | --- | --- |
| 生产人员 / 厨师 | PC（后厨办公位） | 看当天任务 → 逐台开始生产（定这台设备的开工时间）→ 该台完成后确认 |
| 车间班长 / 食堂管理员 | PC | 组织层看各档口当天待生产量；核对未开始 / 生产中 / 已完成 |

**主流程**

```
组织层总览（各档口当天待生产道数）
  → 选择档口
  → 选日期（默认今天）
  → 看按餐次分段的执行清单（一道菜跨多台设备时按设备分行）
  → 对某一台设备「开始生产」：定这台设备的开工时间 → 这台进入生产中
  → 这台做完点「完成」 → 这台进入生产完成（不可回退）
  → 误操作且仍在当天：「撤销开工」把这台退回未开始，开工时间一并清空
```

**场景约束**

- 本模块**只读排餐内容**，不新增任何计划数据；现场只产生一份执行记录。
- 任务按**档口**归属：设备与锅数都是档口的现场事实。
- 一道菜可能跨多台设备，**每台设备独立开工、独立完成、独立撤销**，互不影响。
- 设备由**菜谱加工步骤**决定，现场不选设备，只确定时间。
- 清单以「天」为粒度；默认打开今天。

## 3. 术语与核心口径

### 3.1 术语

| 术语 | 定义 |
| --- | --- |
| 生产任务 | 某档口某天某餐次中**含设备加工**的一道菜（列表里一组设备行） |
| 含设备加工 | 菜谱的加工步骤非空；纯人工菜（步骤为空）**不进**生产计划 |
| 菜谱设备 | 该菜谱加工步骤里挂的**全部设备**（按步骤顺序去重）；即这道菜要开工的设备清单，**现场不可改** |
| 设备任务 | 一道菜 × 一台设备 = 任务表里的**一行**；状态、开工时间、完成时间都挂在这一行上 |
| 生产设备 | 列表设备列显示的机型，来自菜谱加工步骤（多设备时附「第 N 台」与该台负责的步骤） |
| 锅数 | 生产批次数量，作用于该菜全部设备加工步骤；**在排餐计划里录入，本页只读** |
| 入锅投料总量 W | 一锅基准投料 Q × 锅数 |
| 开工时间 / 完成时间 | **逐台**记录的实际时间（`HH:MM`） |
| 预计总时长 | Σ（各加工步骤时长 × 锅数）= 整道菜合计；按设备分行时，每台只算自己负责的步骤 |
| 撤销开工 | 某台设备 生产中 → 未开始，并**清空该台**的开工与完成时间 |

### 3.2 派生口径（只读排餐 + 菜谱）

```
任务集合   = 该档口该日排餐中「菜谱步骤非空」的菜
锅数       = 排餐计划里该菜的锅数（≥1）
入锅投料总量 W = 一锅基准投料 Q × 锅数
出品量     = W × 出餐成品系数（排餐派生）
设备清单   = 菜谱加工步骤涉及的设备（按步骤顺序去重）
菜级状态   = 各台设备状态的聚合（供统计与筛选用，见 5.2）
```

### 3.3 精度与时间格式

| 项 | 口径 |
| --- | --- |
| 出品量、入锅投料总量 | 2 位小数，kg |
| 加工时长 | 整道菜 = Σ（各步骤时长 × 锅数）；按设备分行时只算**这台设备自己的步骤** × 锅数 |
| 时长 | ≥1h 显示 `Xh Ym`，≥1m 显示 `Xm`，否则 `Xs` |
| 时间显示 | `HH:MM`；**分钟先取整再格式化**，避免出现 `16:60` 这类非法时间 |

## 4. 前置依赖

| 依赖 | 来源 | 不满足时的表现 |
| --- | --- | --- |
| 排餐计划已保存 | 排餐计划 | 本页看不到该档口任务（未保存的改动不可见） |
| 菜谱加工步骤 | 菜谱管理 | 步骤为空 → 该菜不进本页（空态文案说明仍会进后续采购计划） |
| 步骤挂的设备 | 菜谱管理 | 某步骤没挂设备 → 该步骤不计入任何设备行；步骤全空 → 该菜不进本页 |
| 设备型号额定容量 | 设备主数据 | 产能提示显示 `—` |
| 档口主数据 | 档口管理 | 组织层"暂无档口，请先创建档口" |

## 5. 功能需求

### 5.1 页面结构（两级范围）

| 层级 | 内容 |
| --- | --- |
| 组织层（未选档口） | 日期工具条 + 「{组织}的档口」卡片墙；每张卡片：档口名、负责人（姓名 · 手机号，未指定显示"未指定负责人"）、各经营餐次与营业时间、"{日期} 待生产 N 道 / {日期} 无设备菜任务"、"进入生产计划 ›" |
| 档口层（已选档口） | 日期工具条 → 统计条 → 筛选条 → 任务表 |
| 面包屑 | 计划管理 / 生产计划 |

| 规则 | 说明 |
| --- | --- |
| 默认范围 | 与排餐计划共用同一个组织 / 档口切换器，默认停在「全部档口（总览）」【原型现状】 |
| 范围联动 | 在本页切档口后，切回排餐计划也是同一个档口 |
| 筛选重置 | **切换范围时**清空餐次与状态筛选，避免用旧档口的餐次筛新档口的任务 |
| 组织层数据 | 卡片统计读**各档口已保存的排餐**，不依赖用户是否进入过该档口 |

### 5.2 日期与统计

| 区块 | 规则 |
| --- | --- |
| 日期工具条 | 前一天 / 日期选择器 / 后一天；非今天时显示「回到今天」；默认今天 |
| 统计条 | 当日任务 N 道 · 未开始 N · 生产中 N · 生产完成 N（按**道**计数、不受筛选影响）；一道菜跨多台设备时取**菜级聚合状态**：全未开始 = 未开始，全完成 = 生产完成，其余（部分开工 / 部分完成）= 生产中 |
| 筛选条 | 餐次下拉（该档口经营餐次）、状态下拉（未开始 / 生产中 / 生产完成）；右侧"已筛选 X / Y 道"与"开餐时间：午餐 11:30 …" |
| 筛选口径 | 状态筛选同样按**道**（菜级聚合）：命中则该菜的**全部设备行**一起展示 |
| 空态 | 当日无设备菜 → "当日暂无设备加工任务"，并说明"生产计划只包含菜谱中含设备加工步骤的菜。纯人工菜不进生产计划，但仍会进入后续的采购计划" |
| 筛选无结果 | 单独空态"没有符合筛选条件的任务"（不与当日无任务共用一个空态） |

### 5.3 任务表（8 列，多设备分行）

| 列 | 口径 |
| --- | --- |
| 菜品 / 出品量 / 入锅投料总量 / 锅数 | **整道菜共用**：一道菜跨多台设备时这 4 列纵向合并（rowspan），只出现一次 |
| 生产设备 | 该行设备任务的机型（多设备时附「第 N 台」），并给出这台设备负责的步骤与时长（如"焯水 · 6m"）；设备来自菜谱，**未开工也照常显示** |
| 加工时间 | 未开始 `—`；生产中"{HH:MM} 开始"；完成"{HH:MM} — {HH:MM} · 时长"（**该台自己的时间**） |
| 状态 | **该台设备**：未开始 / 生产中 / 生产完成 |
| 操作 | **该台设备**：未开始 →「开始生产」；生产中 →「完成」（当天另有「撤销开工」）；完成 → 置灰「已完成」 |

**列表顺序**

| 层级 | 规则 |
| --- | --- |
| 分段 | 按**餐次**分段；段头显示餐次、开餐时间、本段 N 道、已完成 N 道（按道计数） |
| 段内排序 | 按**菜级聚合状态**：生产中 → 未开始 → 生产完成 |
| 同状态内 | 保持**排餐顺序** |
| 多设备分行 | 同一道菜的设备行**连续排列**，共用 4 列合并；设备行内按加工步骤先后顺序 |
| 无餐次 | 不出现该分段 |

### 5.4 状态机

**每台设备各自一条状态链**（一台设备的状态变化不影响同菜其它设备）：

```
未开始 ──开始生产（定这台设备的开工时间）──▶ 生产中 ──完成──▶ 生产完成
   ▲                                            │
   └──────── 撤销开工（仅当天，清空该台时间）────┘
```

**菜级聚合状态**（只用于统计与筛选，不单独存储）：

```
全未开始 → 未开始   ｜   全完成 → 生产完成   ｜   其余（部分开工 / 部分完成）→ 生产中
```

| 规则 | 说明 |
| --- | --- |
| 未开始 → 生产中 | 必须确定**这台设备**的开工时间（设备来自菜谱，不用选） |
| 生产中 → 生产完成 | 记录**该台**的完成时间；**不可回退到生产中**；误操作只能线下处理 |
| 生产中 → 未开始 | 「撤销开工」**仅当天**开放；该台的开工时间与完成时间一并清空 |
| 逐台独立 | 开工 / 完成 / 撤销都只作用于被操作的那一台设备 |
| 生产完成 | 不可撤销、不可回退 |
| 菜级聚合 | 统计条与状态筛选按「道」算，口径见 5.2 |
| 状态归属 | 现场记录归本模块所有，**不回写排餐计划的任何字段** |

### 5.5 三个动作与抽屉

| 动作 | 抽屉内容 | 规则 |
| --- | --- | --- |
| 开始生产（仅该台未开始） | ① 该菜涉及的设备**固定回显**（机型 + 负责步骤 + 额定容量 + 该台时长），**不提供设备下拉**；被点的那台给「开工时间」输入（默认当前时刻，可改，**必填**），其余设备只读回显当前状态与时间；② 汇总：入锅投料总量、预计总时长（全设备合计） | **只开工被点的那一台**；点确认即进入生产中，**无二次确认步骤**；抽屉内注明"本次只记录 {设备} 的开工时间，其余设备请在列表里点它那一行的「开始生产」" |
| 完成（仅该台生产中） | 生产设备、开工时间、当前时刻、已进行时长 | 文案明确"**这台设备**进入生产完成，不可回退到生产中"；多设备时补一句"本次只完成 {设备}，其余设备的状态与时间不变" |
| 撤销开工（仅该台生产中且当天） | 生产设备、开工时间 | 明确"**这台设备**的开工时间会一并清空，可重新定时间"；已完成的不可回退 |

> 布局与文案要点：开工抽屉顶部固定说明"在**这一步**确定这台设备的**开工时间**"；抽屉里**先列设备（只回显、不可选）**，再给本次开工的那台填时间。
> 抽屉里的汇总**不重复列表已有的数据**：出品量、锅数在任务表里已经有了，抽屉只留开工时需要看的两项（入锅投料总量、预计总时长）；撤销抽屉只回显"哪台设备、几点开的"。

### 5.6 现场记录

| 字段 | 说明 |
| --- | --- |
| 存储结构 | 一条任务记录 = 这道菜各**设备**的现场记录：`{ devices: { 设备机型: { 状态, 开工时间, 完成时间 } } }` |
| 状态 | **每台设备**：未开始 / 生产中 / 生产完成 |
| 开工时间 | 该台开工时确定（默认当前时刻，可改）；撤销开工时清空 |
| 完成时间 | 该台点完成时的当前时刻；未完成或撤销后为空 |
| 存储分片 | 按档口分片；键格式以「日期 + 餐次 + 菜谱」定位**一道菜**，设备在记录内再分一层 |
| 逐台独立 | 写一台设备的记录不影响同菜其它设备的状态与时间 |
| 版本隔离 | 记录结构升级后旧数据不得被读成新结构（避免造出"同菜每台设备都继承了那道菜整体状态"的假状态） |

## 6. 规则汇总表

| 编号 | 规则 | 类型 |
| --- | --- | --- |
| P01 | 只有含设备加工的菜进生产计划；纯人工菜不进（仍进后续采购计划） | 派生 |
| P02 | 任务按「档口 + 日期」派生，读**已保存**的排餐 | 派生 |

| P05 | 锅数缺失时按 1 锅兜底 | 派生 |

| P07 | 列表按餐次分段，段内按**菜级聚合状态** 生产中 → 未开始 → 生产完成，同状态保持排餐顺序 | 展示 |
| P08 | 未开始时加工时间显示 `—`；设备列照常显示机型（来自菜谱） | 展示 |
| P09 | 每台设备独立开工、独立完成、独立撤销，互不影响 | 状态 |
| P10 | 开工必须确定**该台设备**的开工时间；默认当前时刻、必填 | 校验 |
| P11 | 开工抽屉固定回显该菜全部设备，只给被点的那台填时间，**无设备下拉** | 交互 |
| P12 | 开工无二次确认步骤；完成后不可回退 | 状态 |
| P13 | 撤销开工仅当天可用，且清空**该台**的开工时间与完成时间 | 状态 |
| P14 | 生产完成不可撤销 | 状态 |
| P15 | 统计条与状态筛选按「道」算：菜级状态 = 各台设备的聚合（全未开始=未开始，全完成=生产完成，其余=生产中） | 展示 |
| P16 | 统计条按全部任务计数，筛选只影响表格行 | 展示 |
| P17 | 切换范围时清空筛选条件 | 交互 |
| P18 | 时间显示前先对分钟取整，禁止出现 `16:60` | 展示 |
| P19 | 现场记录不回写排餐任何字段 | 边界 |
| P20 | 排餐保存后，本页若正在显示则同步刷新 | 交互 |
| P21 | 已开工设备跟随排餐刷新：排餐改人数 / 锅数后，各台用量与时长同步变化 | 边界 |
| P22 | 记录结构升级需做版本隔离，旧数据不得被解析成新状态 | 数据 |

## 7. 计划间边界

| 方向 | 内容 |
| --- | --- |
| 本计划**写入** | 现场记录：**每台设备**的状态、开工时间、完成时间（按档口分片） |
| 本计划**只读** | 排餐计划（菜谱、餐次、锅数）、菜谱主数据（加工步骤及其设备、出餐成品系数）、设备额定容量 |
| 本计划**不回写** | **排餐计划的任何字段**（含锅数、用量、状态）；菜谱；档口 |
| 与排餐的关系 | 单向派生：排餐 → 生产。排餐有未保存修改时，本页仍是上一版已保存的内容 |
| 与采购的关系 | 互不依赖：本页只覆盖设备菜，采购计划覆盖全量菜（含纯人工菜），两条派生路径同源不同集 |

## 8. 异常与边界

| 场景 | 表现 |
| --- | --- |
| 排餐未保存 | 本页看不到新增/删减的菜；排餐保存后本页同步刷新 |
| 排餐改人数 / 锅数 | 该任务的入锅投料总量、出品量、各台加工时长跟随变化；**已开工设备同样跟随**（无定格） |
| 排餐删掉某道菜 | 该任务从清单消失（含它的全部设备行）；对应现场记录成为无引用数据，界面上不再呈现【待确认：是否需要清理策略或保留追溯】 |
| 菜谱改为纯人工 / 被下架 | 不再派生该任务 |
| 菜谱加工步骤变更 | **设备清单跟随变化**：新增设备 → 该菜多出一行未开始；删除设备 → 该行消失（现场记录不再呈现）；未变的设备保留自己的状态与时间 |
| 菜谱某步骤没挂设备 | 该步骤不计入任何设备行（时长也不计）；步骤全空 → 该菜不进本页 |
| 设备被停用 | 本页不实时校验设备主数据状态：已派生出来的设备行照常显示与操作【待确认：停用设备的存量记录如何处理】 |
| 同一机型挂多道菜 | 各道菜各自成行，互不影响；同一时段被多道菜占用**不做冲突检测**（本期不做排程） |
| 开工时间晚于当前时刻 | 不拦截（现场补录场景）；时间列按记录原样展示 |
| 跨天操作 | 前一天 / 后一天可查看与开工；「撤销开工」只对**当天**开放 |
| 切换档口 / 日期 | 筛选条件在切换范围时重置；日期切换保留筛选条件【待确认：日期切换是否也应重置】 |
