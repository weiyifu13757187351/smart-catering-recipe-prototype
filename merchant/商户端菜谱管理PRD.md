## 1. 文档目的与范围

本文档补充商户端菜谱中心的实现级细节，覆盖：页面结构、列表字段、筛选项、按钮、交互流程、校验规则、数据来源与状态流转。

本文档的定位：

- 与《租户端菜谱管理与授权 PRD》配套，租户端负责「提供菜谱并授权」，商户端负责「选择、落地并独立经营使用」。
- 商户端不再出现「标准菜谱」「设备菜谱」两个独立栏目，统一收敛到「菜谱管理 → 菜谱库」。
- 商户端不维护菜谱分类、标签与加工字典，这些内容由租户统一维护，商户端只读。

### 1.1 本期不包含

- 菜谱审批流程；
- 商户维护租户分类、标签或加工字典；
- 租户版本自动覆盖组织菜谱；
- 上级组织自动向下级组织继承菜谱；
- 组织之间自动同步菜谱；
- 真实后厨设备下发与状态回传；
- 跨租户共享菜谱；
- 菜谱成本核算及定价。

## 2. 角色与数据范围

### 2.1 组织数据隔离

商户下每个组织拥有**独立的菜谱库**。

| 规则 | 说明 |
| --- | --- |
| 数据范围 | 页面数据范围以左上角当前组织为准 |
| 组织切换 | 切换组织后，列表、筛选结果、待同步数量和同步记录全部随之切换 |
| 上下级独立 | 上级组织同步菜谱，不代表下级组织自动拥有 |
| 修改隔离 | 不同组织对同一菜谱的修改互不影响 |

### 2.2 组织切换交互

用户在编辑菜谱或同步选择过程中切换组织时：

1. 提示「当前未保存内容或已勾选内容将丢失」；
2. 用户确认后切换；
3. 切换后重新加载目标组织的菜谱库、分类视图和待同步数量。

## 3. 数据来源

### 3.1 菜谱来源只有两种

商户端列表来源**只有**以下两种，不展示「只读」「可编辑」「商户版本」「自主维护」等附加权限标签。

| 来源 | 定义 | 生成方式 |
| --- | --- | --- |
| 租户授权 | 由租户授权，并经当前组织**主动同步**形成的组织菜谱 | 在「同步菜谱」抽屉中勾选同步 |
| 自建 | 当前组织自行创建的菜谱 | 「＋ 新建菜谱」 |

关键约束：

- 租户授权成功后，菜谱只进入**目标商户的可同步范围**，不会直接写入所有组织菜谱库；
- 必须由各组织**分别主动同步**才会形成该组织自己的菜谱；
- 因此「授权」决定**能否同步**，「同步」决定**是否进入组织**，「组织状态」决定**是否投入使用**。

### 3.2 原型演示数据来源

配套原型为纯前端演示，数据来源如下，供研发对照接口设计时参考：

| 数据 | 原型存放位置 | 上线后应替换为 |
| --- | --- | --- |
| 组织菜谱列表 | `merchant-unified-recipe-v1.js` 内 `rows` 演示数组 | 组织菜谱库接口（按组织 + 筛选条件分页） |
| 可同步菜谱 | 同文件 `available` 演示数组 | 租户授权可同步范围接口（按组织计算） |
| 待同步数量 | `available` 数组按当前组织过滤后的长度 | 服务端按组织返回的待同步计数 |
| 分类树 | 同文件内固定分类结构 | 租户统一分类接口（只读） |
| 标签与字典 | `merchant-tenant-device-dictionary.js` | 租户字典接口（只读） |

原型中所有数据均在内存中，刷新页面即恢复初始演示数据，不产生真实持久化。

### 3.3 数据独立性

| 操作位置 | 影响租户菜谱 | 影响当前组织 | 影响其他组织 |
| --- | --- | --- | --- |
| 租户编辑并发布新版本 | 是 | 仅产生更新提醒 | 仅产生各自更新提醒 |
| 当前组织编辑同步菜谱 | 否 | 是 | 否 |
| 当前组织上下架菜谱 | 否 | 是 | 否 |
| 当前组织删除菜谱 | 否 | 是 | 否 |
| 当前组织确认版本更新 | 否 | 是 | 否 |
| 租户撤销授权 | 是 | 已同步菜谱保留 | 各组织按是否已同步分别处理 |

| 卡片 | 说明文案 | 进入 |

| 菜谱分类 | 查看租户统一维护的一级、二级分类 | 菜谱分类（只读） |

### 4.3 页面清单

| 页面 | 视图标识 | 说明 |

## 5. 菜谱库列表

### 5.1 页面结构

从上到下依次为：

1. 返回工作台按钮、页面标题「菜谱库」；
2. 组织提示条；
3. 操作按钮：同步菜谱（含数量气泡）、＋ 新建菜谱；
4. 筛选区：默认筛选项 + 更多筛选；
5. 数据表格。

### 5.2 组织提示条

固定展示：

> 当前组织：{组织名称}　菜谱数据仅属于当前组织；切换组织后将展示对应组织的菜谱库。

### 5.3 列表字段

| 列序 | 字段 | 展示类型 | 业务说明 | 约束与备注 |
| --- | --- | --- | --- | --- |
| 1 | 菜谱信息 | 图文 | 图片 + 菜谱名称；副标题展示菜谱编号 · 别名；有新版本时在名称旁展示「有新版本」标识 | 编号全局唯一，用于区分同名菜谱 |
| 2 | 菜谱分类 | 文本 | 二级分类全路径，如「热菜 / 小荤」 | 分类失效时展示「已停用」或「已删除」 |
| 3 | 来源 | 文本 | 租户授权 / 自建 | 仅此两种，无附加权限标签 |
| 4 | 加工方式 | 文本 | 纯人工 / 含设备加工 | 判定规则见 7.4 |
| 5 | 适配设备 | 文本 | 设备厂家 · 型号，多个时折叠为「等 N 种」 | 纯人工菜谱展示「—」 |
| 6 | 用料 | 数量 | 「N 项」 | 用料明细条数 |
| 7 | 菜谱标签 | 数量 + 悬浮 | 列表显示标签数量，悬浮查看分组后的完整标签内容 | 支持按标签筛选；与租户端展示规则一致 |
| 8 | 版本 / 状态 | 组合 | 版本号 + 组织私域状态 | 如「V2 已上架」；有新版本时另有标识 |
| 9 | 更新信息 | 文本 | 操作人 + 更新时间 | 如「食堂菜谱管理员 2026-09-14 10:30」 |
| 10 | 操作 | 按钮组 | 见 5.6 | 按状态动态渲染 |

### 5.4 筛选项（默认可见）

| 控件 | 类型 | 选项 / 占位 | 说明 |
| --- | --- | --- | --- |
| 关键词 | 输入框 | 搜索菜谱名称、别名或编号 | 模糊匹配，三字段任一命中即展示 |
| 来源 | 下拉 | 全部来源 / 租户授权 / 自建 | 默认「全部来源」 |
| 状态 | 下拉 | 全部状态 / 草稿 / 已上架 / 已下架 | 默认「全部状态」 |
| 菜谱分类 | 下拉 | 全部菜谱分类 / 一级 / 二级 全路径 | 选项来自租户统一分类，只可选不可维护 |
| 加工方式 | 下拉 | 全部加工方式 / 纯人工 / 含设备加工 | 默认「全部加工方式」 |

### 5.5 更多筛选

点击「更多筛选 ⌄」展开，按钮文案变为「收起筛选 ⌃」，追加以下筛选项：

| 控件 | 类型 | 选项 |
| --- | --- | --- |
| 烹饪分类 | 下拉 | 全部烹饪分类 / 炒 / 炖 / 蒸 / 煮 / 烤 |
| 菜系 | 下拉 | 全部菜系 / 川菜 / 鲁菜 / 粤菜 / 浙菜 等 |
| 标签 | 下拉 | 全部标签 / 各租户标签 |
| 设备厂家 | 下拉 | 全部厂家 / 各有效厂家 |

「重置」按钮清空全部筛选条件并恢复默认列表。

### 5.6 行操作

行操作按钮按菜谱状态动态渲染：

| 动作 | 租户授权 | 自建 | 条件与结果 |
| --- | --- | --- | --- |
| 查看 | 支持 | 支持 | 打开菜谱详情抽屉；有新版本时在此处理版本更新 |
| 编辑 | 支持 | 支持 | 打开编辑抽屉；须使用租户当前有效的分类、标签与字典 |
| 上架 | 支持 | 支持 | 仅「已下架」状态展示；上架后进入「已上架」 |
| 下架 | 支持 | 支持 | 仅「已上架」状态展示；下架后进入「已下架」 |
| 删除 | 支持 | 支持 | 仅删除当前组织私域菜谱，不影响租户端与其他组织 |

补充规则：

- 租户授权来源菜谱在**删除后且授权仍有效**时，可以重新同步；
- 操作区**不单独显示「处理更新」**，版本处理统一从「查看」进入；
- **不提供「复制」操作**：菜谱统一通过「＋ 新建菜谱」创建，避免产生来源与归属不清的副本。

### 5.7 空态与异常

- 无数据时展示空态提示；
- 筛选无结果时提示调整筛选条件；
- 组织菜谱数量、待同步数量均按当前组织实时计算。

## 6. 同步租户授权菜谱

### 6.1 入口与数量气泡

「同步菜谱」按钮位于菜谱库操作区，有新的可同步菜谱时显示数量气泡。

**数量定义**：租户已经授权给当前商户、当前组织尚未同步、且当前允许同步的菜谱数量。

- 数量**按组织分别计算**，不是整个商户的统一数量；
- 切换组织后数量随之变化。

### 6.2 可同步条件

菜谱必须**同时**满足：

1. 租户对当前商户的授权关系有效；
2. 租户菜谱当前已上架；
3. 菜谱分类有效；
4. 菜谱使用的必要标签和加工字典有效；
5. 当前组织尚未同步该菜谱。

### 6.3 同步抽屉

右侧全高抽屉，标题「同步租户授权菜谱」，副标题展示当前组织。

抽屉内的说明文案：

> 选择租户已授权给当前商户、但尚未同步到当前组织的菜谱。同步后形成当前组织自己的菜谱。

抽屉结构：

| 区域 | 内容 |
| --- | --- |
| 左侧分类树 | 全部菜谱 / 各一级分类 / 各二级分类 |
| 工具区 | 关键词搜索、加工方式筛选、设备厂家筛选 |
| 已选摘要 | 当前已勾选数量 |
| 菜谱列表 | 可同步菜谱，逐项可勾选 |
| 底部操作 | 取消 / 同步所选菜谱（N） |

组织可勾选**一个或多个**菜谱后批量同步。

分类或字典失效的菜谱：

- 暂不计入可同步数量气泡；
- 在同步抽屉中**展示但置灰**；
- 不允许勾选；
- 明确显示「所属分类已停用」或「所属分类已删除」。

### 6.4 同步结果

确认同步后：

- 在当前组织菜谱库形成**独立菜谱**；
- 来源显示「租户授权」；
- 同步租户**当前最新已发布版本**；
- 同步基础信息、用料、加工步骤、设备适配方案及相关内容；
- **初始状态为「已下架」**，由组织确认后自行上架；
- 当前组织获得编辑、上下架和删除权限；
- 待同步数量相应减少；
- 不影响商户下其他组织的待同步状态。

### 6.5 同步失败与部分成功

批量同步时**允许部分成功**：

- 用户在抽屉勾选菜谱后，若租户菜谱被下架、删除、撤销授权或分类失效，则该菜谱同步失败；
- 其他仍有效的菜谱可以继续同步；
- 结果中明确列出失败菜谱及原因；
- **不回滚**已经成功同步的菜谱；
- 结果展示成功数量、失败数量及逐项失败原因。

### 6.6 重复同步

同一组织已存在对应租户授权菜谱时：

- 不允许重复同步；
- 该菜谱不出现在正常可同步列表中；
- 如果存在租户新版本，通过查看详情处理更新，**不重新同步**。

### 6.7 删除后重新同步

组织删除租户授权来源菜谱时，只删除当前组织私域菜谱。如果租户授权仍然有效且源菜谱仍满足同步条件：

- 该菜谱重新进入当前组织可同步范围；
- 「同步菜谱」气泡数量增加；
- 组织可以再次同步租户当前最新版本；
- 原组织版本和修改内容**不自动恢复**。

## 7. 新建与编辑菜谱

### 7.1 交互形式

新建和编辑与租户端保持一致的内容结构与主要交互：

- 使用全高右侧抽屉；
- 包含「1 基础信息」「2 用料明细」「3 加工步骤」三个页签；
- 加工步骤支持人工处理和设备加工切换；
- 设备加工支持按设备型号查看独立操作时间轴。

商户端差异仅体现在：

- 所属数据范围不同；
- **商户端分类、标签和字典只可选择，不可维护**；
- 租户授权来源菜谱可能出现「当前版本／最新授权版本」切换。

### 7.2 可使用内容

组织自建与编辑菜谱**只能**使用：

- 租户当前有效的菜谱分类；
- 租户当前有效的菜谱标签；
- 租户当前有效的烹饪、菜系、工艺及设备参数字典；
- 当前可用的设备厂家和设备型号。

### 7.3 创建范围

组织可以自行创建：

- 纯人工菜谱；
- 含设备加工菜谱。

### 7.4 加工方式判定

| 加工方式 | 判定条件 |
| --- | --- |
| 纯人工 | 加工步骤全部为人工处理步骤 |
| 含设备加工 | 加工步骤中包含至少一个设备加工步骤 |

### 7.5 基础信息字段

| 字段 | 类型 | 必填 | 业务说明 | 约束与备注 |
| --- | --- | --- | --- | --- |
| 图片 | 上传 | 是 | 菜谱成品图 | 限 1 张 |
| 菜谱名称 | 输入 | 是 | 菜谱主名称 | 允许同名，见 11.4 |
| 别名 | 输入 | 是 | 菜谱别名 | 列表副标题展示 |
| 外语菜谱名 | 弹窗 | 否 | 多语种名称，展示「已配语种 N/10」 | 最多 10 个语种 |
| 烹饪分类 | 下拉 | 是 | 炒 / 炖 / 蒸 / 煮 / 烤 | 来自租户字典 |
| 菜谱省份 | 下拉 | 是 | 全国 / 四川 / 浙江 / 山东 等 | 来自租户字典 |
| 出餐成品系数 | 输入 | 是 | 百分比 | 影响用量换算 |
| 菜谱分类 | 级联下拉 | 是 | 一级分类 + 二级分类 | **分类由租户统一维护**，仅可选有效分类 |
| 菜系分类 | 下拉 | 是 | 川菜 / 鲁菜 / 粤菜 / 浙菜 等 | 来自租户字典 |
| 菜品简介 | 多行文本 | 否 | 菜谱说明 | — |
| 菜品标签 | 多选 | 否 | 按分组多选标签 | **来自租户字典，可多选二级标签** |

分类或字典失效时的限制：编辑并提交或重新上架时，**必须更换为有效**分类／标签／字典内容。

### 7.6 用料明细

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 用料角色 | 输入 / 下拉 | 主料、辅料、调料等 |
| 标准食材 | 输入 | 标准食材名称 |
| 投料量 | 输入 | 数值 |
| 单位 | 输入 / 下拉 | 克、千克、毫升等 |
| 投料状态 | 输入 / 下拉 | 投料时的状态描述 |
| 切配方式 | 输入 / 下拉 | 切、丝、片、丁等 |
| 切配规格 | 输入 | 具体规格 |
| 说明 | 输入 | 补充说明 |

支持增删多行用料。

### 7.7 加工步骤

支持两种模式切换：

| 模式 | 内容 |
| --- | --- |
| 人工处理 | 人工步骤及说明 |
| 设备加工 | 按设备型号分别维护独立操作时间轴 |

### 7.8 提交

| 按钮 | 结果 |
| --- | --- |
| 取消 | 关闭抽屉，放弃未保存内容 |
| 保存草稿 | 保存为「草稿」状态，尚未正式提交使用 |
| 提交 | 提交校验通过后进入「已上架」或按业务规则流转 |

提交校验：必填项校验、分类／标签／字典有效性校验。

## 8. 菜谱详情与版本更新

### 8.1 详情结构

点击列表「查看」打开菜谱详情抽屉，展示菜谱编号 · 名称。

详情包含四个内容页签：

| 页签 | 当前版本 | 最新授权版本 |
| --- | --- | --- |
| 基础信息 | 可查看 | 可查看 |
| 用料明细 | 可查看 | 可查看 |
| 加工步骤 | 可查看 | 可查看 |
| 营养预览 | 可查看 | **不提供** |

### 8.2 版本切换

有新版本时，详情顶部显示：

- **当前版本**；
- **最新授权版本**，并显示 `NEW` 标识。

规则：

- 组织已经同步该菜谱后，当前组织菜谱**不自动变化**；
- 列表显示「有新版本」；
- 操作区**不单独显示「处理更新」**；
- 用户点击「查看」进入菜谱详情处理更新。

### 8.3 更新到此版本

- **只有切换到「最新授权版本」后**，才显示「更新到此版本」操作；
- 组织确认更新后：
  - 当前组织菜谱内容更新为租户最新授权版本；
  - 「有新版本」提示消失；
  - 当前版本号更新；
  - 当前组织此前对该菜谱的修改内容**被最新授权版本替换**；
  - 不影响租户菜谱；
  - 不影响其他组织的当前版本和更新选择。

如果菜谱当前**已上架**，更新前必须提示：

> 该菜谱当前已上架，更新后新内容将立即生效。确认更新到最新授权版本吗？

### 8.4 暂不更新

组织可以不更新：

- 当前版本继续使用；
- 「有新版本」提示保留；
- 后续仍可通过查看详情处理更新。

### 8.5 未同步组织

组织尚未同步该菜谱时：

- 可同步范围直接展示租户最新已发布版本；
- 组织首次同步时直接形成最新版本；
- 不需要处理历史版本。

## 9. 菜谱分类（只读）

### 9.1 只读约束

> 菜谱分类由租户统一维护，商户及组织仅可查看，不支持新增、编辑、删除或排序。

验收要点：**商户端菜谱分类只读，不存在新增、编辑、删除和排序入口。**

### 9.2 页面结构

| 区域 | 内容 |
| --- | --- |
| 左侧 | 分类结构树：一级分类 / 二级分类 |
| 右侧 | 分类明细表 |

### 9.3 分类明细表字段

| 字段 | 说明 |
| --- | --- |
| 分类名称 | 一级 / 二级分类名称 |
| 层级 | 一级分类 / 二级分类 |
| 上级分类 | 二级分类展示所属一级分类，一级分类展示「—」 |
| 状态 | 启用 / 已停用 / 已删除 |
| 最近更新 | 租户侧最近更新时间 |

### 9.4 分类失效对商户端的影响

**租户停用分类**：

- 已同步的组织菜谱继续保留，不自动下架；
- 菜谱原分类显示「已停用」；
- 已上架菜谱可以继续使用；
- 新建菜谱不能选择已停用分类；
- 编辑并提交或重新上架时，必须更换为有效分类；
- 租户恢复分类后，「已停用」标识自动消失。

**租户删除分类**：

- 已同步菜谱保留原分类历史信息；
- 原分类显示「已删除」；
- 菜谱不自动删除或下架；
- 编辑并提交或重新上架时，必须重新选择有效分类；
- 商户分类页面不再将其作为正常分类展示，但历史菜谱仍可识别原分类。

**核心原则**：分类失效限制后续新建、编辑提交、重新上架和首次同步，但**不打断已经上架使用**的组织菜谱。

## 10. 状态与权限

### 10.1 自建菜谱状态

| 状态 | 含义 | 主要操作 |
| --- | --- | --- |
| 草稿 | 尚未正式提交使用 | 查看、编辑、提交、删除 |
| 已上架 | 当前组织正式使用 | 查看、编辑、下架、删除 |
| 已下架 | 当前组织暂停使用 | 查看、编辑、重新上架、删除 |

### 10.2 组织菜谱操作权限

菜谱同步后已成为当前组织自己的菜谱，因此租户授权和自建菜谱均可独立维护。

| 操作 | 租户授权 | 自建 |
| --- | --- | --- |
| 查看 | 支持 | 支持 |
| 编辑 | 支持 | 支持 |
| 上架 | 支持 | 支持 |
| 下架 | 支持 | 支持 |
| 删除 | 支持 | 支持 |
| 接收租户新版本提醒 | 支持 | 不适用 |
| 重新同步 | 删除后且授权仍有效时支持 | 不适用 |

### 10.3 租户菜谱与商户可同步状态对应关系

| 租户菜谱状态 | 授权状态 | 组织同步情况 | 商户端结果 |
| --- | --- | --- | --- |
| 已上架 | 生效中 | 未同步 | 可同步 |
| 已上架 | 生效中 | 已同步 | 组织私域菜谱正常维护 |
| 已上架 | 已撤销 | 未同步 | 不可同步 |
| 已上架 | 已撤销 | 已同步 | 已同步菜谱继续保留，不再接收授权更新 |
| 已下架 | 生效中 | 未同步 | 暂不可同步 |
| 已下架 | 生效中 | 已同步 | 组织私域菜谱不自动下架，可继续独立维护 |
| 已删除 | 任意 | 未同步 | 不可同步 |
| 已删除 | 任意 | 已同步 | 组织私域菜谱继续保留，不自动删除 |

### 10.4 租户侧变化对商户端的影响

**租户下架菜谱**：

- 未同步组织暂时不能同步；
- 已同步形成的组织菜谱不自动下架；
- 组织仍可以继续维护当前私域菜谱；
- 租户重新上架后，未同步组织恢复同步资格；
- 如果形成新版本，已同步组织按版本更新规则处理。

**租户删除菜谱**：

- 未同步组织不再允许同步；
- 已同步组织菜谱继续保留；
- 已同步组织不会被自动删除或下架；
- 因租户源菜谱已不存在，不再产生后续授权版本；
- 商户删除本地菜谱后不能再次同步该租户源菜谱。

**租户撤销授权**：

- 授权批次变为「已撤销」；
- 尚未同步的组织不再允许同步相关菜谱；
- 相关菜谱从可同步数量中移除；
- 已同步形成的组织私域菜谱继续保留；
- 组织仍可编辑、上下架和删除；
- 已同步菜谱不再接收该授权关系下的后续版本提醒；
- 商户删除后不能通过已撤销授权重新同步。

**标签及加工字典停用**：

- 新建菜谱不可再选择；
- 尚未同步且依赖必要无效内容的菜谱暂不可同步；
- 已同步菜谱保留原内容，用于历史查看和当前使用；
- 已上架菜谱不自动下架；
- 再次编辑提交时，应提示更换为有效内容；
- 租户恢复后，可恢复选择和同步。

## 12. 验收标准

- 商户端不再出现标准菜谱、设备菜谱两个独立栏目。
- 菜谱列表可以通过「纯人工」和「含设备加工」识别加工方式。
- 不同组织分别展示自己的待同步数量。
- 组织可以通过关键词、分类、加工方式和设备条件筛选可同步菜谱。
- 组织可以批量勾选并同步菜谱。
- 同步完成后，菜谱来源显示「租户授权」，**初始状态为已下架**。
- 同步菜谱可以编辑、上架、下架和删除。
- 当前组织对菜谱的修改不影响租户端及其他组织。
- 删除租户授权来源菜谱后，在授权仍有效时可以重新同步。
- 商户自建菜谱来源显示「自建」，不显示「商户自建」或「自主维护」。
- 商户端菜谱分类只读，不存在新增、编辑、删除和排序入口。
- 商户端新建和编辑菜谱只能选择租户有效分类、标签和字典内容。
- 租户分类停用或删除后，已上架组织菜谱不自动下架。
- 分类失效后，新建、编辑提交、重新上架和首次同步受到限制。
- 租户发布新版本后，已同步组织菜谱显示「有新版本」，但内容不自动覆盖。
- 操作区不显示「处理更新」，用户通过「查看」进入版本处理。
- 查看详情支持「当前版本／最新授权版本」切换。
- 确认更新只影响当前组织，不影响租户及其他组织。
- 租户撤销授权后，未同步组织不可再同步，已同步组织菜谱继续保留。
- 租户删除源菜谱后，已同步组织菜谱继续保留，但不再获得后续版本。
- 批量同步部分失败时，成功项不回滚，并展示失败原因。
- 切换组织后，菜谱列表、分类视图和待同步数量同步切换。

## 13. 原型实现说明与待确认

### 13.1 原型实现说明

| 项 | 说明 |
| --- | --- |
| 技术形态 | 纯静态前端，数据全部内置于 JavaScript，无后端接口 |
| 入口 | 左侧导航「菜谱中心 → 菜谱管理」，进入工作台后选择「菜谱库」或「菜谱分类」 |
| 组织切换 | 顶栏组织切换按钮，切换后按组织重新计算列表与待同步数量 |
| 分类维护 | 商户端分类页只读，无新增 / 编辑 / 删除 / 排序入口 |
| 历史遗留层 | 原型由多代脚本叠加而成，旧版可编辑分类页仍在代码中，但入口已被隐藏，正常操作不可达 |
| 标注形态 | 只读角标 + 抽屉，不改变原型既有功能 |

#### 历史遗留层明细

旧内联脚本共引用 27 个元素 id，其中 **18 个已不存在**（均属被统一层替换掉的「引用授权菜谱 / 新建菜谱下拉」流程）：

| 范围 | 影响 |
| --- | --- |
| 全局 click 监听中的 `#recipeCreateMenu` | 每次点击都抛 `TypeError`，已加空值保护修复 |
| 其余 17 个引用（`#authorizedBody`、`#selectAllAuthorized` 等） | 位于不可达函数内，正常操作不会触发 |

### 13.2 原型修改记录

| # | 修改 | 原因 | 类型 |
| --- | --- | --- | --- |
| 1 | 为全局 click 监听中的 `#recipeCreateMenu` 增加空值保护 | 该元素已被统一层移除，导致每次点击抛出 `TypeError: Cannot set properties of null` | 错误修复（无行为变化） |
| 2 | 移除列表「操作」列的「复制」入口及其处理逻辑 | 业务决策：菜谱统一通过「新建菜谱」创建，不提供复制 | 功能调整 |
| 3 | 注入 `annotation-kit`（只读标注资源）与 `host-view-adapter.js` | 支撑业务标注展示 | 标注接入 |

除上述三项外，原型的功能、数据与交互与原始版本一致。

#### 业务决策：移除「复制」

| 项 | 说明 |
| --- | --- |
| 决策 | 商户端菜谱**不提供「复制」操作** |
| 理由 | 菜谱统一通过「＋ 新建菜谱」创建，避免产生来源与归属不清的副本 |
| 影响范围 | 列表操作列不再出现「复制」；自建菜谱状态、组织菜谱操作权限、分类与字典失效限制等规则中的「复制」表述一并移除 |
| 与来源 PRD 的差异 | 来源《租户端与商户端统一菜谱管理 PRD》第 12.4、13.3、14、20 章均列出「复制」权限，本次按业务决策移除，本文档已按移除后的口径表述 |
