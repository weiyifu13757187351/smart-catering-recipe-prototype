## 1. 背景与目标

### 1.1 业务问题

| 问题 | 现状 |
| --- | --- |
| 排餐靠经验、无留痕 | 每周排餐以纸面/表格为主，改了哪一格、为什么改无法追溯 |
| 用量说不清 | 做多少锅、出多少成品、这一餐够多少人吃，只能口头估算 |
| 下游靠人工传导 | 生产、采购各自重新抄一遍菜单，口径容易分叉 |

### 1.2 本期目标

| 目标 | 衡量口径 |
| --- | --- |
| 周排餐一次录入、下游自动派生 | 排餐计划是**全链路唯一人工录入口** |
| 用量可算、可追溯 | 每格给出出餐合计与「预计满足 N 人就餐」；当日调整留原因与操作人 |
| 减少重复录入 | 人均用餐量默认引用档口配置；排餐支持整周复制 |

### 1.3 范围与不做

- **做**：组织 / 档口两级范围、周排餐表、三输入与派生、菜品详情、加菜换菜、复制排餐、日期管理、保存生效、当日调整记录。
- **不做**：排程与设备、营养与成本、菜单发布、车间端（手机）、排餐与生产状态联动（V3 已解耦）。

## 2. 角色与场景

| 角色 | 使用环境 | 主要动作 |
| --- | --- | --- |
| 排餐员 / 档口管理员 | PC，周维度批量排 | 选档口 → 排一周 → 保存 → 临时调整并记原因 |
| 食堂管理员 | PC，看整体 | 组织层总览看各档口排餐情况 |

**主流程**

```
组织层总览（各档口排餐情况）
  → 选择档口（卡片「进入排餐」或切换器）
  → 切换周（上一周 / 下周 / 周选择器）
  → 点「编辑」
  → 逐格录入：加菜 / 换菜 → 填锅数 → 填人均用餐量 → 看派生结果
  → 保存（校验通过后立即生效）
  → 当天临时变动：加/删/换菜 → 必填原因 → 进当日调整记录
```

**场景约束**

- 排餐以档口为单位：**先选档口，再排该档口的经营餐次**。
- 计划只挂在档口上；组织层不是一份计划，而是各档口的入口。
- 历史周只读；过去日期（早于今天）只读；只有**今天及未来**可编辑。

## 3. 术语与核心口径

### 3.1 术语

| 术语 | 定义 |
| --- | --- |
| 组织 / 档口 | 计划的数据范围两级；档口是排餐的作业单元，属于某个次级组织 |
| 餐次 | 早餐 / 早点 / 午餐 / 午点 / 晚餐 / 夜宵；某档口的可排餐次 = 该档口在档口管理里配的经营餐次 |
| 一锅基准投料 Q | 菜谱 BOM 中**可折成质量**的用料合计（g）；纯人工菜与含设备菜同口径，均按「一锅」配置 |
| 锅数 | 本次做几锅；**排餐侧唯一必填的用量驱动项**（1–99） |
| 人均用餐量 | 该格计划每人吃多少（g/人，1–9999）；排餐侧输入项 |
| 出餐成品系数 | 菜谱标准出餐率（%），**只读跟随菜谱**，V3 起不再逐格手改 |
| 出品量 / 出餐成品总量 | 投料用量总量 × 出餐成品系数 |
| 预计就餐人数 | 该餐次「计入统计」分类的出餐成品合计 ÷ 人均用餐量（派生结果，不是输入） |
| 沿用 | 首次建立某格取值时，回查**上周同星期几 + 同餐次**的历史值 |
| 计入就餐人数 | 菜谱分类页的二级分类开关；只影响「预计满足 N 人就餐」 |

### 3.2 计算口径

```
投料用量总量 = 一锅基准投料 Q × 锅数
出餐成品总量 = 投料用量总量 × 出餐成品系数
出餐合计（餐次）= 该餐次各菜出餐成品总量之和（物理口径，含全部菜）
预计就餐人数 = 该餐次「计入统计」分类的出餐成品合计 ÷ 人均用餐量，向下取整
每行用量 = 该行投料量 × 锅数（单位保持菜谱原单位）
```

| 精度与单位 | 口径 |
| --- | --- |
| 质量折算 | g / kg、ml / L 折算为克（1 g = 1 ml）；个 / 只 / 条 / 份 / 适量**不折算**，不进合计，但仍按锅数放大 |
| 出品量、投料用量总量 | 2 位小数 |
| 用料明细「本次用量」 | **全表统一双单位**：`{克数}g（{千克数}kg）`，如 `9000g（9kg）`、`3600g（3.6kg）`、`300g（0.3kg）`；克数最多 2 位小数，千克最多 2 位小数并去尾零；**计数单位行（个 / 只 / 条 / 份 / 适量）无质量口径，保持原单位显示 `{数值}{单位}`** |
| 用料明细「一锅投料」 | 保持**菜谱原单位**原样展示（如 `9000 g`、`300 ml`），不做单位进位，也不与「本次用量」混用一套格式 |
| 出餐合计（格子内展示） | 1 位小数 |
| 人均用餐量 | 整数（g/人） |
| 出餐成品系数 | 只读，取菜谱标准值 |

> 排餐侧**不存在**「先定人数再反推用量」的路径：锅数与人均用餐量是输入，人数是派生结果。

## 4. 前置依赖

| 依赖 | 来源 | 不满足时的表现 |
| --- | --- | --- |
| 档口主数据（名称、负责、经营餐次、营业时间、预计人均用餐量） | 档口管理 | 组织层"暂无档口，请先创建档口"；无档口则无法排餐 |
| 菜谱库（BOM、加工步骤、出餐成品系数、二级分类） | 菜谱管理 | 选择器列表为空，无法加菜 |
| 菜谱分类「计入就餐人数」开关 | 菜谱管理 → 菜谱分类 | 未设置时**缺省全部分类都计入** |
| 设备型号额定容量 | 设备主数据 | 仅用于「一锅装不下」提示，不影响计算 |
| 下游消费 | 生产计划读「已保存的排餐」 | 未保存的改动下游不可见 |

## 5. 功能需求

### 5.1 页面结构（两级范围）

| 层级 | 内容 |
| --- | --- |
| 组织层（未选档口） | 顶部周工具条 + 「{组织}的档口」卡片墙；每张卡片：档口名、负责人（姓名 · 手机号，未指定显示"未指定负责人"）、各经营餐次与营业时间、"已排 N 道菜 / 未排餐"、"进入排餐 ›" |
| 档口层（已选档口） | 周工具条（含复制排餐）→ 周元信息 → 计算口径行 → 统计口径行（有排除分类时）→ 周排餐表 |
| 面包屑 | 计划管理 / 排餐计划 |

| 规则 | 说明 |
| --- | --- |
| 默认范围 | 进入时停在「全部档口（总览）」；点卡片或切换器才进入具体档口【原型现状】 |
| 选择保持 | 用户选过档口后，不被默认值拉回总览 |
| 编辑中锁定 | 编辑模式下切换器 disabled，附文案"编辑中，保存或取消后可切换" |
| 未保存拦截 | 切范围前弹抽屉「切换范围 / 当前排餐还有未保存的修改」，按钮「取消切换」「保存后切换」；校验不通过则不提交、也不切换 |

### 5.2 周与时间控制

| 项 | 规则 |
| --- | --- |
| 周工具条 | 上一周 / 周选择器（按自然周）/ 下一周；非本周时额外显示「回到本周」 |
| 周定义 | 自然周，周一为起始 |
| 周元信息 | 「历史周 · 仅支持查看」/「有未保存修改」/「已保存 · 最近更新：时间」/「暂未排餐」 |
| 历史周 | 周起始 < 本周 → 整周只读，「编辑」按钮置灰 |
| 过去日期 | 日期 < 今天 → 该列只读（已排内容可见，不可增删改） |
| 跨周保存 | 按周分别存储；跨周（周日排下周、周一回看本周）不得丢改动 |
| 计划分片 | 计划按「档口 + 周」分片；组织层只做统计展示 |

### 5.3 周排餐表

| 元素 | 规则 |
| --- | --- |
| 行 | 餐次；取该档口的经营餐次（未选档口的总览不涉及） |
| 行头 | 餐次名 + 开餐时间（早餐 06:30 / 早点 09:30 / 午餐 11:30 / 午点 15:00 / 晚餐 17:30 / 夜宵 21:00） |
| 列 | 排餐日期（默认周一至周五可排，其余日期未排） |
| 列头 | 调整记录图标 ◷（有记录高亮，悬浮气泡显示当日调整；点击打开记录抽屉）、周几（MM/DD）、「今日」标签 |
| 删除当天 | 仅编辑模式、非历史周、且日期 > 今天时显示 × |
| 未排日期 | 编辑态在表上方展示"＋ 恢复周X" chips，点击恢复该列 |
| 冻结表头 | 页面下滚且表头滚出视野时，表头浮在窗口顶部；横向位移跟随表格滚动 |

**格子内容（自上而下）**

| 区块 | 规则 |
| --- | --- |
| 人均用餐量 | 编辑态：输入框（1–9999 整数，g/人）；有沿用值时显示"沿用上周四 午餐"角标，手工改写后角标**立即消失**；只读态：显示值或"未填人均用餐量" |
| 预计满足 N 人就餐 | 紧贴人均用餐量；三态：「待填人均用餐量」/「本餐次菜品不计入就餐人数统计」/「预计满足 N 人就餐」；编辑时**边输边算**（不重画表格，保留光标） |
| 菜品 chip | 菜名、二级分类标签、"{锅数} 锅 · 出餐 {X}kg"；编辑态带 × 删除 |
| 出餐合计 | "出餐合计：X kg"（1 位小数） |
| 分类统计 | "荤 N · 素 N · 汤类 N …"，荤素排最前；无菜显示"未排餐" |
| 添加菜谱 | 编辑态显示"＋ 添加菜谱" |

### 5.4 菜品详情抽屉

| 项 | 规则 |
| --- | --- |
| 只读态条件 | 非编辑模式 / 历史周 / 过去日期 → 无输入框、无「确定 / 删除 / 替换」 |
| 字段 | 菜谱分类（只读）、出餐成品系数（只读，标注"跟随菜谱"）、**烹饪锅数（唯一输入，1–99）** |
| 头部标签 | 「含设备加工」/「纯人工」；"用料明细按「一锅」配置：一锅基准投料 Q；适用设备 …" |
| 派生行 | 投料用量总量 = 一锅基准投料 × 锅数；出餐成品总量 = 投料用量总量 × 出餐成品系数 |
| 用料明细 | 列：用料 / 一锅投料 / 占比 / 本次用量；表头提示"本次用量 = 一锅投料 × N 锅"；计数单位行标注不计入合计但仍放大 |
| 本次用量显示 | **整列统一双单位 `{克数}g（{千克数}kg）`**：不再按 1000 g 分档（不允许"9 kg"与"300 g"两种写法在同一列里混排）；无论锅数为几，都同时给出 g 与 kg |
| 锅数联动 | 改锅数 → 投料用量总量、出餐成品总量、公式行、用料明细、提示全部实时重算；失焦收敛为整数 |
| 提示 | ① 一锅 Q 超过最小设备额定容量 → "一锅装不下，现场需拆成多锅处理"（只提示不拦）；② 该菜属被排除分类 → "改锅数只影响出餐量与生产，不改变「预计满足 N 人就餐」" |
| 底部动作 | 删除此菜 / 替换菜谱 / 确定（确定后 toast"已更新，保存后生效"） |

**字段数据源（三项均为菜谱主数据，排餐侧只读消费）**

| 抽屉字段 | 数据源 | 维护方 | 排餐侧关系 |
| --- | --- | --- | --- |
| 菜谱分类（一级 / 二级全路径，如"热菜 / 小荤"） | 菜谱管理 → 菜谱库 → 菜谱「基础信息 · 菜谱分类」 | **分类字典由租户统一维护、商户端只读**；分类挂到菜谱由商户新建 / 编辑菜谱时选择 | 只读消费：① 展示；② **二级分类**是分类聚合排序与「是否计入就餐人数」的判定键 |
| 出餐成品系数（%） | 菜谱管理 → 菜谱库 → 菜谱「基础信息 · 出餐成品系数」 | 商户维护，随菜谱版本走 | **只读跟随菜谱**；V3 起排餐侧不逐格手改，改菜谱即改所有引用该菜谱的格子 |
| 用料用量明细（用料 / 一锅投料 / 占比 / 本次用量） | 菜谱管理 → 菜谱库 → 菜谱「用料明细」页签（用料角色、标准食材、投料量、单位、投料状态、切配方式） | 商户维护，随菜谱版本走 | 只读消费：**一锅基准投料 Q = 该菜谱用料明细中可折算为质量的投料量合计**；占比 = 该行投料量 ÷ Q；本次用量 = 该行投料量 × 锅数，并统一显示为 `{克数}g（{千克数}kg）` |
| 适用设备、菜谱编码 · 版本 | 菜谱「加工步骤」页签、菜谱主数据 | 商户 / 租户授权版本 | 只读展示；设备另用于「一锅装不下」提示 |

**取数与落库口径**

| 规则 | 说明 |
| --- | --- |
| 排餐只落库三项 | 排餐侧仅存储**菜谱 ID、锅数、人均用餐量**；菜谱分类、出餐成品系数、用料明细**实时读菜谱主数据，不落快照** |
| 源改动即全量生效 | 菜谱的分类 / 出餐成品系数 / 用料明细被改动后，所有引用该菜谱的排餐格子派生值随之变化（无须重新排餐）【待确认：是否需要"菜谱已变更"提示或影响面提示】 |
| 菜谱版本 | 排餐引用菜谱的具体版本（选择器展示"编码 · 版本"）；租户更新授权版本后，存量排餐是否自动切换引用【待确认】 |
| 分类失效 | 菜谱分类被停用 / 删除后，该菜仍按原二级分类参与聚合与计算，不静默剔除【原型差异：原型未处理分类失效，正式实现需给兜底展示】 |

### 5.5 加菜 / 换菜（两段式抽屉）

| 步骤 | 规则 |
| --- | --- |
| 第 1 步 选菜谱 | 筛选：菜名搜索、分类、设备厂家（含"纯人工（无设备）"）；列表列：图片、菜谱名称（编码 · 版本）、分类、适用设备、加工方式；**已在本餐次的菜置灰"已添加"不可选**；新增为多选、替换为单选 |
| 第 2 步 填锅数 | 逐菜卡片（一锅基准投料、出餐成品系数、投料用量总量、出餐成品总量）+ ± 步进；支持"统一锅数 → 应用到全部"；底部合计"本次 N 道 · 投料合计 · 出餐合计"；被排除分类的菜带「不计入就餐人数」标签 |
| 默认锅数 | **新增一律 1 锅**（不回查上周）；**替换沿用被替换那道菜的锅数**（换菜不换量） |
| 确认 | 落地后格子按分类聚合重排；toast"已加入 N 道菜并确认锅数，保存后生效"；**仍需点页面「保存」才生效** |
| 校验 | 至少选 1 道；替换时不能选原菜；锅数 1–99 |

### 5.6 分类聚合排序（口径唯一）

固定顺序排序，组内保持原有先后：

```
大荤 → 小荤 → 半荤半素 → 素菜 → 汤类 → 粥类 → 面食 → 点心 → 水果
→ 其它二级分类（按首次出现顺序）→ 未分类
```

加菜 / 换菜、打开页面（切周 / 切范围）、复制排餐**都走同一处聚合**，避免口径分叉。

### 5.7 默认值取数链（人均用餐量）

| 优先级 | 来源 | 表现 |
| --- | --- | --- |
| 1 | 档口管理里该档口该餐次的「预计人均用餐量」 | 直接引用 |
| 2 | 沿用上周同星期几 + 同餐次的值 | 显示"沿用上周四 午餐"角标 |
| 3 | 内置演示默认值（早餐 300 / 早点 200 / 午餐 500 / 午点 250 / 晚餐 450 / 夜宵 300） | 不打角标 |

| 规则 | 说明 |
| --- | --- |
| 手工优先 | 用户在格子里改过 → 来源标记清除、角标消失，以手工值为准 |
| 不回写 | 排餐侧改动**不回写**档口配置 |
| 一格只带一次 | 「沿用」是首次建立该格时的一次性提示；保存后即为确定值，再进编辑不再提示 |
| 锅数兜底 | 仅在补历史数据 / 来源端未给锅数时回查上周同格，查不到落 1 锅 |

### 5.8 就餐人数统计口径（分类开关）

| 规则 | 说明 |
| --- | --- |
| 开关位置 | 菜谱管理 → 菜谱分类页，按二级分类逐项设置，**商户级一份** |
| 缺省 | 未设置过 = 全部分类都计入 |
| 影响范围 | **只作用于「预计满足 N 人就餐」**；出餐合计、荤素统计、锅数、生产计划均不受影响 |
| 全被排除 | 显示"本餐次菜品不计入就餐人数统计"，而不是 0 人 |
| 历史定格 | 开关只影响**今日及未来**；保存时把当时的开关状态记到各日期上；日期进入历史后按当时口径计算，之后改开关不回溯 |
| 无记录日期 | 种子数据、开启本功能之前保存的计划 → 按"全部分类都计入"处理 |
| 提示与跳转 | 表格上方「统计口径」行 + 「去设置」跳到菜谱分类页 |
| 跨页同步 | 菜谱分类页改开关后，排餐页立即按新口径重画 |

### 5.9 日期管理

| 动作 | 规则 |
| --- | --- |
| 删除当天 | 仅编辑模式、非历史周、日期 > 今天；当天已排菜时二次确认"周X已安排 N 道菜，移除当天后这些内容将被清空" |
| 至少保留一天 | 每周至少保留 1 个排餐日期；移除最后一个时拦截并提示"如当天不排餐，可将各餐次菜谱留空" |
| 恢复当天 | 未排日期区点击 chip 恢复该列，重新排序 |

### 5.10 复制排餐

| 项 | 规则 |
| --- | --- |
| 入口 | 编辑模式、非历史周的周工具条 |
| 来源 | 复制上周 / 复制上上周 / 自选周（下拉列出本档口已保存的其他周） |
| 覆盖口径 | **覆盖**目标日期原有排餐；带入各餐次人均用餐量与每道菜的锅数 |
| 不带入 | **不复制**当日调整记录，也不带来源周的人数为手工痕迹标记 |
| 起始位置 | 目标周为本周时，从**今天**起复制；过去的日期不动 |
| 排餐日期 | 来源周的排餐日期（activeDays）同步带入 |
| 异常 | 来源周无已保存排餐 → toast"所选来源周暂无已保存的排餐" |
| 生效 | 复制后仍需点「保存」；toast"排餐已复制，请保存后生效" |
| 聚合 | 复制进来的菜按分类聚合规则重排 |

### 5.11 保存与生效

| 动作 | 规则 |
| --- | --- |
| 进入编辑 | 点「编辑」（历史周置灰） |
| 取消 | 有未保存修改时 confirm"取消后将放弃本次所有修改，是否继续？" |
| 保存 | 仅在有改动时执行校验；校验不通过 → toast 首个错误，不提交、不退出编辑 |
| 保存成功 | toast"排餐计划已保存并立即生效"；写入更新时间；定格当日及未来的分类口径；清空「沿用」标记 |
| 空保存 | 无改动时 toast"当前没有需要保存的修改" |

### 5.12 当日排餐调整与变更记录

| 项 | 规则 |
| --- | --- |
| 适用范围 | **仅当天**；只有加菜 / 替换 / 删除需要记原因 |
| 原因必填 | 抽屉「今日排餐调整」，未填 → toast"请填写调整原因" |
| 记录字段 | 时间、餐次、类型（新增 / 替换 / 删除）、明细（菜名）、原因、操作人 |
| 查看入口 | 日期旁 ◷ 图标（有记录高亮）→ 悬浮气泡摘要 + 抽屉「当日调整记录」完整列表；无记录显示"当日暂无排餐调整记录" |
| 非当天删除 | 仅二次确认，不记原因、不产生记录 |
| 保存后可见 | 提示"今日排餐调整需要记录原因，保存后可通过日期旁的记录图标查看" |

## 7. 计划间边界

| 方向 | 内容 |
| --- | --- |
| 本计划**写入** | 排餐内容（菜谱、锅数、人均用餐量、排餐日期）、当日调整记录、分类口径定格 |
| 本计划**只读** | 档口主数据、菜谱主数据（BOM / 步骤 / 出餐成品系数）、菜谱分类开关、设备额定容量 |
| 本计划**不回写** | ① 档口配置（排餐侧改人均用餐量不反写档口）；② **生产状态与现场记录**（V3 起两边不联动，排餐侧不存在生产状态字段）；③ 菜谱 |
| 对下游 | 生产计划、采购计划**只按已保存的排餐**派生；未保存的改动下游不可见 |

## 8. 异常与边界

| 场景 | 表现 |
| --- | --- |
| 组织下无档口 | 总览显示"暂无档口，请先创建档口"，不可排餐 |
| 切档口 / 切组织 | 丢弃未保存缓冲，但**保持当前正在看的周**；有未保存修改时先走切换拦截 |
| 档口经营餐次被改 | 表格行按**当前**档口餐次收敛；已排但不在经营餐次内的菜不再展示（存量数据保留，不做自动清理）【待确认：是否需要提示或清理】 |
| 档口被删除 | 总览与切换器不再出现该档口；已保存的历史计划保留【待确认：历史计划中的档口名称是否落快照】 |
| 档口「预计人均用餐量」被改 | 只影响**之后新建立**的格子；已保存格子的值不变，也不回溯 |
| 分类开关被改 | 今日及未来的格子立即重算；历史日期按定格口径不变 |
| 菜品分类为空 | 不进分类统计，也不受分类开关影响（永远计入） |
| 一锅超设备容量 | 详情抽屉与加菜第 2 步给警示文案，不拦截保存 |
| 计数单位用料（个/只等） | 不进一锅基准投料合计与投料合计，但仍按锅数放大展示 |
| 跨周保存 | 按周分片，互不覆盖 |
| 本地存储不可用 | 原型以 localStorage 模拟服务端；正式环境以服务端为准，写入失败不得影响页面可用性 |
| 车间端（手机） | **本期不评审**；相关接口在原型中存在，但不纳入本期规则 |
