## 1. 概述与范围

### 1.1 两层背景（V4.0 重构）【本期新增】

V3.0 是「采购单 → 订单 → 商品明细抽屉」三层。评审与试用后确认：**采购单这一层没有独立业务价值**，反而让列表多一次下钻、让「同一供应商同一天到货」被拆到不同采购单里；商品明细放在抽屉里也撑不住行级验收的操作量。因此 V4.0 收敛为**两层**：

| 层 | 对象 | 定义 | 数量关系 |
| --- | --- | --- | --- |
| 第 1 层 | 订单列表 | 本档口全部订单（一张订单 = 一个送达日期 + 一家供应商），带筛选与统计 | N |
| 第 2 层 | 订单详情 / 商品明细 | 订单页头 + 更多信息 + **商品明细整页** + 发货记录 / 售后记录 / 时间轴 | M 行 |

```
订单 PO20261028001（送达日 10-28，供应商：上海鲜配，来源：采购计划 CGJH20261024001）
├── 商品行 1 → 验收记录（第1次 12→12）
├── 商品行 2 → 验收记录（第1次 6→5，原因：生鲜状态异常）
└── 商品行 3 →（未验收）
```

本轮一并确认的三个结论：

| # | 结论 | 影响 |
| --- | --- | --- |
| 1 | **删除采购单层** | 数据里只有订单；不再有 `CG…` 单号、不再有「含 N 张订单」、不再有采购单详情页（§8.2.5） |
| 2 | **商品明细从抽屉改为整页** | 行级验收、验收详情、退货、售后都在订单详情同一屏内完成 |

## 2. 名词与口径

### 2.1 两层与区间口径

| 术语 | 口径 |
| --- | --- |
| 订单 | **唯一单据**：一个送达日期 + 一家供应商；编号 `PO + 送达日 yyyyMMdd + 3 位流水`（流水按送达日重置）；状态见 §5.1 |
| 商品行 | 订单内一个 SKU 一行，是**验收单元**；带下单量 / 实际发货量 / 实际验收量 / 备注 |
| 需求区间 | 只在**新建向导**里存在（送达日期区间，最长 31 天）；提交后**按天拆成 N 张订单**，每张订单只带一个 `delivery_date`，订单上不再有区间 |
| 送达日期筛选 | 列表筛选区间，默认 **`[今天-15, 今天+15]`** |
| 验收单元 | 商品行；订单级只有一个「验收完成（签名）」收口动作 |
| 进度 | 订单详情页头 `已验收：x/y 行`；x = 已验收行数，y = 行总数 |
| 幂等键 | `档口 + 供应商 + 来源单号 + 送达日期`；重复提交不重复生单 |
### 2.2 验收相关口径【改造】

| 术语 | 定义 |
| --- | --- |
| 行级验收 | 验收的最小单元是**商品行**：点该行「验收」只填这一行的验收量，与其它行互不影响（D24） |
| 部分验收 | 同一订单内**部分行已验收、部分行未验收**；或某行验收量 < 实际发货量（短收，须填差异原因） |
| 验收完成 | 订单级动作：点「验收完成」+ 电子签名后订单 = 已完成、全部行验收量锁定。**前置：所有行都已验收**（Q23） |
| 验收记录 | 行级留痕：该商品行第 N 次验收的 `改前 → 改后`、差异原因、验收方式、验收人、时间、照片；**只追加不覆盖** |
| 实际发货量 | 供应商「确认发货」时**按行一次性**填写的数量（可小于订单量），之后不可改；补送在线下处理，系统不记录补送 |
| 实际验收量 | 该行**累计验收量** = 最后一次验收的改后值；**> 0**（**允许大于实际发货量**，V2.0.11）；已验收行可上调（补送后回填）不限次数 |
| 商品资质照片 | **供应商侧上传**的检测报告 / 快检报告照片（D28）：报告名称、类型、有效期、上传时间；**商户端只读回显**，过期标红 `已过期` 但**不阻断验收** |
| 检测报告 / 快检报告 | 商品维度的食品安全资料。`检测报告`= 第三方检测机构出具；`快检报告`= 供应商自检 / 快检；`其它`= 其它资质材料（如检疫、产地证明） |
| 验收方式 | `手动验收` / `电子秤验收`，**由验收终端自动判定、用户不可选**（PC / 移动端 = 手动验收，电子秤端 = 电子秤验收）；**每条行级验收记录都固化当时的方式** |
| 短收差异 | **V2.0.10 起不再使用 `未发 / 未收` 概念**：只判断「本次验收量 < 实际发货量」= 短收，此时**差异原因必填**；否则不需要差异原因 |
| 预报价 / 定标价 | 预报价 = 供应商端维护的「商户 × 商品」报价，商户端**只读**，用于直采带价；定标价 = 采购计划定标时该供应商对该商品的成交报价，转单时成为行单价 |

### 2.3 编号与数字口径【规则】

| 项 | 口径 |
| --- | --- |
| 订单号 | `PO` + **送达日** `yyyyMMdd` + 3 位流水，示例 `PO20261101001`；流水按送达日重置，同一送达日可因不同供应商产生多张订单 |
| 退货单号 | `RT` + 提交日 `yyyyMMdd` + 3 位流水，示例 `RT20261101001`（沿用 V1.0） |
| 互指 | 订单是**唯一单据**；来源为采购计划时带计划单号单向可追溯，供应商沟通一律用订单号 |
| 送达日期区间 | **≤ 31 天**；层1 默认 **近 15 天**（按送达日期） |
| 退货轮次 | 退货被退回重发**不设上限、只记录轮次**（沿用讨论稿 V1.5 口径）；变更打回轮次本期不做（§9） |
| 验收量 | **> 0**；**允许大于实际发货量**（超发 / 补送），不再做上限校验（V2.0.11） |
| 精度 | 数量、单价、金额均 **2 位小数**（四舍五入） |

| 系统 | 定标即生单、按天切订单、逐单落状态、行级验收留痕、到点通知 |

| 项 | 口径 |
| --- | --- |

| 权限体系 | 沿用商户端既有「角色 + 按钮权限」体系，下表只作后端配置参考，本模块不另建权限模型 |

### 3.2 权限点【规则】

| 权限点 | 覆盖动作 | 默认角色 |
| --- | --- | --- |
| `purchase.order.view` | 订单列表（第 1 层）/ 订单详情与商品明细（第 2 层）/ 验收与退货记录查看 | 采购员、验收员 |
| `purchase.order.create` | 直采下单、定标转单、生单失败后「重新生成」 | 采购员 |

| ~~`purchase.order.cancel`~~ | **V2.0.38 起不提供**：订单发起后**不可撤回**，系统内无撤回权限点 | — |
| `purchase.accept` | **行级验收**：填 / 改某商品行的验收量（L3 行内入口） | 验收员、采购员 |

- 【本期新增】`purchase.accept` 的作用域从「整单」收窄为「**单个商品行**」；`purchase.accept.confirm` 仍为订单级。

## 5. 状态模型

### 5.1 订单 5 态（主状态，唯一）【规则】

> 主状态收敛为 **5 态**（V2.0.39）：删除「退货中」——退货是**商品行的售后**，不参与订单状态机，申请售后后订单**始终停在「已完成」**；V2.0.39 起**再删除「已取消」**——订单发起后不可撤回、也没有商户侧取消动作，订单只会沿「待确认 → 已确认 → 待验收 → 验收中 → 已完成」推进；采购单**没有状态机**（§5.2）。

| 状态 | 判定 | 终态 |
| --- | --- | --- |
| 待确认 | 订单已生成并推送供应商，供应商尚未确认；**此状态下商户可改单**——仅限来源为「直采下单」的订单可点 `修改订单`（见 §8.2.1） | 否 |
| 已确认 | 供应商已确认该订单（含分拣备货中） | 否 |
| 待验收 | 供应商已确认发货（已写该订单各行的实际发货量） | 否 |
| 验收中 | 该订单**至少 1 行**已验收过一批、尚未点「验收完成」；**可继续分批累加验收，也可修改任一批次数量、从最新一批逐条往上删除（每次留痕）** | 否 |
| 已完成 | 已点「验收完成」并完成**电子签名**（前置：所有行已验收）；**全部行验收量锁定不可再改** | **是** |

### 5.2 只有订单是实体【规则】

| 项 | 口径 |
| --- | --- |
| 实体 | V4.0 起**数据里只有订单**（`purchase_order`），采购单容器已删除（§8.2.5） |
| 状态机 | 只有订单有状态机（§5.1）；一次下单生成的多张订单各自独立流转、互不影响 |
| 追溯 | 同一次提交生成的订单通过 `batch_no` 关联展示（仅用于「同批」提示），不产生新的单据与编号 |
| 不做 | 不做采购单状态、不做采购单审批、不做采购单级操作 |
### 5.3 派生标签（不改主状态，列表与详情页头并列展示）

| 标签 | 判定 | 展示位置 |
| --- | --- | --- |

| `部分发货` | 该订单任一 `实际发货量 < 订单量` | L2 订单状态列 |
| ~~`部分验收`~~ | **L2 不再展示**（V2.0.7）：主状态已是「验收中」，不重复标注；行级未验收情况看 L3 商品行的行状态 `未验收` / `已验收` | L3 行状态 |
| `有退货` | 该行售后被供应商**认可**、回写的退货数量 > 0 | **L3 明细行**（V2.0.21：只保留这一个标记，不再区分部分/全部；L2 由独立「售后状态」列表达售后进度） |
| `手动验收` / `电子秤验收` | 该条**行级验收记录**的验收方式（本期只可能出现 `手动验收`） | L3 行状态、验收详情记录表 |
| `已签名` | 该订单已完成验收并留存电子签名 | L3 验收详情签字照片区 |
| `改价` / `定标价` / `预报价` | 直采手工改价 / 单价来源 | L3 明细行、L2 明细 |
| `来源：计划` / `来源：直采` | 订单来源（字段 `source`：`plan` / `direct`） | 列表来源列、详情页头 |

### 5.4 状态 × 动作矩阵【规则】

> 动作落位：**验收完成在订单层，验收（填量）在商品行层，退货在行层**（变更本期不做）；订单**发起后不可撤回**，故矩阵不再有「撤回」列（V2.0.38）。

| 订单状态 | 发货（供应商，逐单） | 行内验收（L3） | 验收完成 + 签名（**仅 L3 头部**） | 退货（L3 行内） |
| --- | --- | --- | --- | --- |
| 待确认 | — | — | — | — |
| 已确认 | ✅ | — | — | — |
| 待验收 | — | ✅ | —（先验收） | — |
| 验收中 | — | ✅（可改） | ✅（所有行已验收时） | —（验收完成后才可发起） |
| 已完成 | — | 只读 | 只读 | ✅（唯一可发起售后的状态） |

- **列表层（第 1 层）只有 `查看` / `修改`（仅待确认 + 直采）/ `删除`（仅待确认）**（V4.10），其余动作都在订单详情内完成。
- **删除订单**：仅「待确认」状态可删（供应商确认后不可删）；点 `删除` 先二次确认（标题 `删除订单`、正文 `是否确认删除订单 PO…？删除后不可恢复`、按钮 `我再看看` / `删除`），确认后从列表与数据中移除，统计卡与页签张数同步变化。
- 「验收完成」的可用条件 = 订单状态 ∈ {验收中} **且** 该订单**所有行都已验收**（Q23）；不满足时按钮置灰并提示 `还有 N 个商品未验收，请先完成验收`。
- 本期**没有改单入口、也没有撤回入口**：订单发起后不可撤回、不可改单；需要调整只能重新下单（§9.2）。
- 验收完成后（已完成）才可发起退货；验收中只能验收 / 改验收量。**退货不改变订单状态**（§11）。
- 无权限时按钮**不显示**；无状态时按钮**置灰并给原因**（两者取交集，§3.2）。

### 5.5 状态流转（文字表达，供画图用）

| 段 | 流转 | 触发者 |
| --- | --- | --- |
| 生单 | A 采购计划定标 / B 直采下单 → **按送达日期每天 1 张订单** → 全部 `待确认` | 系统（计划自动）／采购员（直采） |
| 确认 | 待确认 → 供应商确认（可批量确认，**系统逐单落** `已确认`）→ 已确认 | 供应商 |
| 调整（本期不做） | 供应商不能改单；订单发起后**不可撤回**，需要调整只能重新下单（§9.2） | 采购员 |
| 发货 | 已确认 → 供应商确认发货（**一次填该订单各行实际发货量** + 约配送） → 待验收 | 供应商 |
| 验收 | 待验收 → 逐行验收（首次保存任意行） → **验收中**（仍有行未验收时打 `部分验收`）；可继续逐行改、不限次数，每次一条留痕 | 验收员 |
| 收口 | 验收中 → 所有行已验收 → 「验收完成」+ 电子签名 → **已完成**（终态，全部行验收量锁定） | 验收员 |
| 退货（售后） | **已完成**（验收完成 + 签名后才可退货）→ 从商品行发起售后单 → 售后状态 `待供应商确认` → 供应商**认可**：回写该行实际验收量、行标 `有退货`，订单**仍是已完成** ／ 供应商**不认可**：售后状态 `供应商不认可`、理由回显、可重新发起（不设上限，记录轮次） | 采购员 + 供应商 |

### 5.6 验收单与退货单状态

| 单据 | 状态流转 |
| --- | --- |
| 行级验收记录（`purchase_item_acceptance`） | 提交即生效、只追加；同一行可有多条（第 1…N 次）；订单完成后整体转只读 |
| 订单验收完成记录（`purchase_order_acceptance`） | 验收中（各行业务留痕生效）→ 已完成（验收完成 + 签名后锁定，`is_final=true`） |
| 售后单（`purchase_return`） | 待供应商确认 → 供应商已认可（终态，回写行验收量）／供应商不认可（可重新发起，不设上限，记录轮次）→（重新发起）待供应商确认 |

| 已添加项 | 在面板中**灰态展示 + 右侧标 `已添加`**（不过滤掉，便于理解为什么不能重复加） |
| 鼠标 | 点面板任一行 = 直接添加（与回车等价）；点面板外**只收起面板**（不添加、不清空输入） |
| 输入法 | 中文输入法上屏过程中的回车**不触发添加** |
| 上限 | 面板最多 8 条；无命中显示 `没有匹配的商品，可直接点「查询」在列表里筛选` |

### 7.1c 添加商品抽屉 · 填量即添加（V4.13）

| 项 | 口径 |
| --- | --- |
| 触发 | 在表格某行**填了采购量（>0）后，光标离开该行**即自动添加，等价于点该行「添加」（少一次点击） |
| 不触发 | 采购量为空 / 0 / 非法字符 → 离开后**不添加**，行保持可编辑（符合「没输入内容就不添加」） |
| 同行情景 | 采购量 → 备注之间移动**不算离开**（可先把备注填完再走）；离开整行（去别的行 / 点查询·重置 / 点完成 / 关闭抽屉）时才添加，且**备注随该行一起带上** |
| 提示 | 自动添加成功同样提示 `商品添加成功`（弱提示，抽屉之上） |
| 键盘 | 在采购量或备注输入框里按 `Enter` → 立即添加该行（不需要移开焦点） |
| 幂等 | 已添加的行输入框被禁用，不会重复触发；若用户先点了「添加」按钮，随后的离开动作**不会再添加一次**（同 `SKU + 送达日期` 只落一条） |

| 与模糊浮框的关系 | 两条快捷路径互不影响：搜索框回车 = 按关键词添加；表格填量离开 = 按行添加，采购量与备注都取该行已填值 |

#### 8.2.5 状态时间轴：谁会写记录、文案模板是什么

**通用口径**：一条 = `MM-DD HH:mm` + 一句中文；**倒序**展示（最新在最上）；只追加、不改不删；时间取操作发生时刻。下表是全部会写记录的动作（原型内 12 类）。

| # | 触发动作 | 触发时机 / 条件 | 文案模板 |
| --- | --- | --- | --- |
| 1 | 订单生成 | 向导「提交下单」确认后，按（送达日期 × 供应商）拆单落库 | `订单生成（来源：直采下单）` / `订单生成（来源：采购计划）` |
| 2 | 供应商确认订单 | 供应商端确认（原型用「供应商模拟 › 确认订单」；已确认态不可再点） | `供应商确认订单` |
| 3 | 供应商确认发货 | 供应商填实际发货量并提交（状态 → 待验收） | `供应商确认发货` |
| 4 | 行级验收（新增一批） | 验收弹层填本次验收量后点 `保存` | `验收「商品名」第 N 批 8箱，累计验收 20箱` |
| 5 | 修改批次数量 | 验收详情 › 验收批次记录 › `修改` 保存成功 | `修改「商品名」第 N 批验收量为 5箱，累计验收 12箱` |
| 6 | 删除批次（软删除） | 验收详情 › 验收批次记录 › `删除`，或验收弹层 › 历史验收 › `删除`（任意批次），二次确认后 | `删除「商品名」第 N 批验收记录（5箱），累计验收 7箱` |
| 7 | 验收完成 + 电子签名 | 全部商品已验收 → `验收完成（签名）` → 选验收人 + 签名 → 确认 | `验收完成并电子签名，订单已完成（无差异）` / `验收完成并电子签名，订单已完成（2 个商品有差异）` |
| 8 | 采购员修改订单 | 待确认订单 → `修改订单` 抽屉保存（金额变化才落记录，记第几次） | `采购员修改订单（第 2 次）：¥1,200.00 → ¥1,504.00` |
| 9 | 采购员发起退货 | 已完成订单 → 行内 `退货` → 填退货量 / 原因（含凭证）提交 | `采购员发起退货申请 TH20261026001：「鲜黄瓜」2箱，原因：品质不达标，等待供应商确认` |
| 10 | 供应商认可售后 | 「供应商模拟 › 认可售后」（回写该行验收量） | `供应商认可售后 TH20261026001：「鲜黄瓜」实际验收量 5 → 3，行标「有退货」` |
| 11 | 供应商不认可售后 | 「供应商模拟 › 不认可售后」并填不认可理由 | `供应商不认可售后 TH20261026001：退货量为 0，与实收不符` |
| 12 | 【演示】写入售后单 | 原型专用按钮，快速造一条待确认售后单（仅演示用） | `【演示】写入售后单：鲜黄瓜 1箱（待供应商确认）` |

**不写时间轴的动作**（只改数据或只动其它模块）：选 / 改档口、筛选与查询、删除订单（订单整条移除）、一键最低价 / 按形态批量绑定 / 一键清除（供货关系维度）、绑定或改绑单个 SKU。

**格式细节**：`商品名` 用下单快照名称；数量与单位直接拼接（`8箱`），累计量同理；金额统一 `¥1,234.00`；批次号 `第 N 批` 从 1 起，删除最新一批后编号自然回退、不跳号。

| 项 | V3.0（三层） | V4.0（两层） |

### 8.3 供货关系管理（V4.1 新增栏目）

> **定位**：按**档口**维护「商品 SKU ↔ 供应商」的供货关系，是后续下单流程（商品池按供应商过滤）的数据基础。**本轮只做关系维护，不改下单流程**（§18）。

#### 8.3.1 关系口径【规则】

| 项 | 口径 |
| --- | --- |
| 关系维度 | **档口 × 商品 SKU × 1 家供应商**（一对一）：同一 SKU 在同一档口只绑 1 家，再次绑定即**覆盖** |
| 可绑定范围 | 只有 SKU 状态 = **状态正常** 时可新增 / 修改；已下架 SKU **保留绑定关系**（不做级联删除） |
| 形态校验 | 供应商必须能供应 SKU 的形态（毛菜 / 净菜 / 半成品），按**供应商档案 `supplyTypes`** 判定；如净菜 SKU 不能绑只供毛菜的供应商 |
| 报价关系 | 绑定不要求该供应商有报价；报价用于展示与「一键最低价」选择，报价格度 = **商品（productCode）** 单价，同商品的多个 SKU 共享报价 |
| 下架展示 | 默认**隐藏**已下架 SKU；勾选「包含已下架」后灰态只读展示（无操作按钮、操作列显示 `只读`），证明绑定未被清除 |
| 关系状态 | `已绑定`（有供应商）/ `未绑定`（无任何关系记录）/ `暂无报价`（已保存但无供应商） |

#### 8.3.2 列表页

| 区块 | 口径 |
| --- | --- |
| 页头 | 标题「供货关系管理」+ 右侧说明 `按档口把商品 SKU 绑定到 1 家供应商；下架商品不清除绑定` |
| 组织 / 档口 | 与采购订单同一套共用切换器（V4.15）：组织 + 档口两级，**无「全部档口（总览）」**，进入栏目默认选中第一个组织下的第一个档口；切换后表格与统计同步刷新 |

#### 8.3.4 批量操作一：一键选择报价最低供应商

| 项 | 口径 |
| --- | --- |
| 作用范围 | **全部在售商品**（该档口 `可绑定 SKU 数`，不受筛选影响；已下架 SKU 不参与） |
| 候选 | 形态匹配 + **有报价** 的供应商 |
| 选定 | 取最低价；报价相同时按顺序判定：①该档口该 SKU **最近一次采购过**的供应商（最近一张订单的供应商，按创建时间倒序，所有状态都算）→ ②否则取**供应商 ID 较小**者（字符串升序，如 `sup1` < `sup6`） |
| 无报价 SKU | 不改不绑，**记为 `暂无报价`**（等价于在抽屉里选中「该商品暂无供应商报价」），并在结果里计数 |
| 二次确认 | 点击按钮先弹确认框：标题 `一键选择报价最低供应商`、正文 `是否一键选择最低报价供应商，如有商品已绑定供应商，将会做覆盖处理`、`取消` / `确认`；**取消不产生任何改动** |
| 覆盖 | 允许覆盖已有绑定（可重复点击，结果幂等） |
| 结果提示 | `已绑定 N 个商品的最低报价供应商`；有跳过则追加 `跳过 M 个（该商品暂无供应商报价，已记为暂无报价）`；有同价则追加 `其中 K 个存在同价，已按「最近采购 → 供应商 ID 较小」选定` |

#### 8.3.5 批量操作二：按形态批量绑定

| 项 | 口径 |
| --- | --- |
| 交互 | 抽屉内选 **1 个形态** + **1 家供应商**（候选 = 能供应该形态的供应商，选项后带供应类型） |
| 作用范围 | **该形态的全部在售 SKU**（与其它批量操作同口径，不受筛选影响；已下架不参与） |
| 预览 | `将影响 N 个「形态」商品，其中 M 个已绑定其它供应商会被覆盖；绑定到 供应商` |
| 覆盖 | **覆盖**已有绑定（来源字段记 `form`，仅数据留痕、界面不展示） |
| 结果提示 | `已把 N 个「形态」商品绑定到 供应商`；无目标时提示 `当前没有「形态」形态的在售商品` |
| 前置校验 | 未选供应商 → `请选择供应商` |

#### 8.3.6 批量操作三：一键清除供应商【规则】

| 项 | 口径 |
| --- | --- |
| 按钮文案 | **`一键清除供应商`**（原「批量解绑」） |
| 作用范围 | **全部在售商品**，**只清除已绑定（有供应商）的记录**，不受筛选影响 |
| 二次确认 | 点击后弹确认框：标题 `一键清除供应商`、正文 `是否一键清除所有已绑定的供应商`、`取消` / `确认`；**取消不产生任何改动** |

## 9. 变更（本期不纳入设计）

> **结论**：本期**不做**供应商改单 / 变更单 / 变更确认，相关需求与原型入口**全部移除**；订单确认后供应商不能改单；订单**发起后不可撤回**，需要调整只能重新下单。

### 9.1 本期移除的范围【规则】

| 项 | 处理 |
| --- | --- |
| 变更单（变更单号 / 变更明细 / 新增商品 / 删除商品） | **移除**，不做设计与原型 |
| 变更记录卡片（L3 底部） | **移除**，L3 抽屉现在只有「发货记录 / 退货记录 / 状态时间轴」 |
| 变更确认（同意 / 打回 / 轮次 / 在途唯一 / 作废） | **移除**，L2 行内不再有 `处理变更`，也没有 `变更待确认` 标签 |
| 供应商改单（改数量 / 改单价 / 换商品） | **移除**，供应商模拟区不再有 `修改订单` |
| 改单确认模式（后端配置 `manual_confirm` + 下单快照） | **移除**，第 1 层不再展示「供应商修改订单后…」的只读说明 |
| 订单版本号（V1 → V2） | **移除**，订单没有版本概念 |

### 9.2 订单需要调整怎么办【规则】

| 场景 | 处理方式 |
| --- | --- |
| 订单仍为 `待确认` | **不可撤回**（V2.0.38）：原订单保持待确认等供应商确认；确需调整只能重新下单，原订单由供应商侧处理 |
| 订单已 `已确认` 及之后 | 本期**不支持调整**：供应商按原订单送货，差异在验收环节用「实际验收量 + 差异原因」体现，或用退货处理 |
| 到货后少量差异 | 走 §10 行级验收（实际验收量 < 实际发货量需填差异原因）；已验收完成的差异走 §11 退货 |

### 9.3 后续版本再议的点

- 变更是否只支持「新增 / 删除商品」，还是也允许改数量、改单价；
- 变更确认模式（自动审核通过 / 需下单方手动确认）是平台配置还是采购单级配置；
- 变更与在途唯一、打回轮次（原设计 3 轮）、变更留痕粒度的关系。

## 10. 验收

> **本节是 V2.0 改动最大的一节**：V1.0 是「整单一次填完所有行验收量」，V2.0 改为**商品行级验收**（D24）：一行一个入口、一行一条留痕链；「验收完成」仍是**订单级**收口（Q22/Q23）。

### 10.1 验收单元与入口【改造 D24】

| 项 | 口径 |
| --- | --- |
| 验收单元 | **商品行**：L3 抽屉内每行一个「验收」入口，点开只填**该行**的验收量 |
| 入口 | L3 商品行内 `验收`；行状态 = 未验收，订单 ∈ {待验收, 验收中}，且有 `purchase.accept` |
| 已验收行 | 仍可点 `验收` **继续改**（不限次数），每次新增一条记录；订单已完成则入口变 `验收详情`（只读） |
| 不做 | **不做整单一次填完**（V1.0 口径作废）；L2 不放验收填量入口；不做按供应商 / 按天聚合签收（D11 沿用） |
| 双数量口径 | 实际发货量由供应商一次性填（订单层）；实际验收量由验收员**逐行**填，**> 0 即可、允许大于实际发货量**（V2.0.11：补送 / 超发场景不阻断） |
| 权限 | `purchase.accept` 管行内填量；`purchase.accept.confirm` 管验收完成收口（可分离授权） |

### 10.2 行内「验收」弹层字段【规则】

| 字段 | 规则 |
| --- | --- |
| 商品信息 | **列表（表格）形式只读回显**：`商品名称 / 规格 / 单位 / 单价 / 下单量 / 实际发货量 / 已验收量 / 待验收量` 一行展示；未发货不可验收（入口置灰，提示 `供应商尚未发货`） |
| 本次验收量 | **必填**，`> 0`；**口径 = 这一批的收货量，记入后累加**（V4.6）：先验 2 箱 → 已验收 2；再验 3 箱 → 已验收 5，**不再是覆盖式修改**；**允许累计超出实际发货量**（超发 / 补送，不拦截）；普通文本框（无步进器），默认留空并提示 `填「这一次」的收货量，会累加到已验收量` |
| 累计回显 | 输入即实时显示 `本次 X + 已验收 Y = 累计 Z`：等于发货量 → 绿色 `与实际发货量一致`；少于 → 橙色 `少于实际发货量 N，验收完成时需填差异原因`；超出 → 红色 `超出实际发货量 N（超发 / 补送）` |
| 历史验收 | 弹层内该行全部批次：`批次 / 时间 / 验收人 / 本次验收量 / 照片 / 操作`；操作列**每条都只有 `删除`**（不设修改，改量去「验收详情」）；**删除 = 软删除**：二次确认后该行**不消失**，整行置灰、操作列改为 `已删除`，累计验收量与待验收量同步回退；表头显示 `共 N 批 · 合计 X 箱`，有软删时追加 `· 已删除 M 批` |
| 差异原因 | **本弹层不再填写**（V4.6 起移到「验收完成」环节，见 §10.4b） |
| 验收方式 | **不由用户选择**（V2.0.10）：PC / 移动端验收自动记为 `手动验收`；电子秤端验收自动记为 `电子秤验收`；弹层内**只显示 `验收方式：手动验收`**，不再附加解释文案（V2.0.11） |
| 验收照片 | **非必填，最多 5 张**，可逐张删除；**自动回填上一批照片**（提示 `已回填上一批 N 张，最多 5 张，可删除`）；满 5 张置灰 `已达上限 5 张`；照片张数按批次归档 |
| 操作 | **`保存`**（写一条批次记录）/ `取消` |

### 10.3 保存后的订单状态与部分验收【规则】

| 项 | 口径 |
| --- | --- |
| 首次保存（任意行） | 订单 `待验收 → 验收中`；该行标记 `已验收`；仍有行未验收 → 订单打 `部分验收` 标签 |
| 后续保存（同一行） | 订单状态不变（仍为验收中）；只追加一条记录，行标记 `已验收（第 N 次修改）` |
| 全部行已验收 | L3 抽屉头部「验收完成」按钮**激活**（L2 不提供该入口，V2.0.13）；订单仍需人工点完成 + 签名才变 `已完成` |
| 验收金额 | 订单验收金额 = Σ(**行当前验收量** × 单价)，**实时变化**；无任何行验收时 L2 显示 `—` |
| 提示 | 保存成功提示 `该行验收量已保存（第 N 次修改）` |
| 不改状态的动作 | 行内验收**不改变订单其它行的任何状态**；不同行互不影响 |

### 10.4 分批累加、不限次数、每批留痕【规则·V4.6 重写】

| 项 | 口径 |
| --- | --- |
| 批次 | **不限**（Q8 沿用）；每次点 `保存` 新增一条**批次记录**，**不允许覆盖历史**；同一商品可分多批验收（如 5 箱先验 2 箱、验完别的商品再验 3 箱） |
| 累加口径 | **当前验收量 = 该行各批 `qty` 之和**（累加，不再覆盖）；待验收量 = 实际发货量 − 当前验收量（最小 0） |
| 记录内容 | 第 N 批 / 时间 / 验收人 / 验收方式 / **本批验收量** / 累计 / 照片张数（差异原因不在此处，见 §10.4b） |
| 改批次 | 验收详情与弹层历史表可按批次修改数量（`> 0`），改后**自动重算累计与待验收量**，改批次会写一条时间轴留痕 |
| 改 / 删批次 | `修改`（仅验收详情）就地改该批数量（`> 0`），重算累计与待验收量；`删除`（验收详情 + 验收弹层历史验收**两处都有**，**任意批次都能删**，不再限最新一批）= **软删除**：二次确认后行保留、整行置灰、操作列显示 `已删除`，累计与待验收量按未删除批次重算，写一条时间轴；批次号**不回退不重用**（新批次 = 现有最大批号 + 1）；有效批次全部删完 → 该行回到「未验收」，整单无任何有效批次时订单状态回到「待验收」；订单已完成（验收量锁定）时只读，已删除行仍显示 `已删除` |
| 补送回填 | 线下补送到货后再验一批即可，同样留痕；不需要供应商重新发货 |
| 已锁定 | 订单已完成 → 全部批次记录与验收量只读；提示 `订单已完成，验收量已锁定` |

### 10.4b 「验收完成」前的差异原因确认【规则·V4.6 新增】

> 背景：同一商品可能分批验收，单批「少收」并不等于整体差异，故**差异原因不在行验收时填**，统一放到收口环节按商品逐个确认。

| 项 | 口径 |
| --- | --- |
| 触发 | 点「验收完成（签名）」后，若本单存在**累计验收量 < 实际发货量**的商品行，先进入「验收完成 · 差异原因确认」抽屉；**无差异时跳过**这一步，直接进电子签名，并提示 `本单无差异（累计验收量均不少于实际发货量），可直接签名收口` |
| 列表内容 | 只列**有差异的行**：`商品名称 / 品牌 / 规格 / 单位 / 实际发货量 / 累计验收量 / 差异量 / 差异原因`（V4.8 补品牌）；表格**占满抽屉内容宽度**，右侧不留白 |
| 差异原因 | **逐行必填**（下拉单选，默认 `请选择差异原因`）；未选点「下一步：签名」→ 拦截 `请选择「某商品」的差异原因` |
| 原因枚举（9 项） | `生鲜状态异常` / `变质腐败` / `病虫害或存在异物` / `大小/重量不符` / `加工形态不符` / `少发漏发` / `包装破损` / `送错货` / **`其他`**；选「其他」时该行出现手填框（**必填、≤50 字**），未填拦截 `请填写「某商品」的其他原因`，切回其它选项自动隐藏并清空 |
| 保存位置 | **商品行级一个原因**（不是按批次），落在订单级收口 `acceptance.diffs[]`（`skuCode / ship / accepted / gap / reason / other`），同时回写行上 `diffReason` 供详情展示 |
| 后续可改 | 电子签名抽屉**顶部直接以表格列出差异商品**（`商品名称 / 品牌 / 规格 / 单位 / 实际发货量 / 累计验收量 / 差异量 / 差异原因`），并提供 `修改差异原因` 返回上一步；**无差异时该表不出现**；**签名完成后锁定** |
| 详情展示 | 验收详情「差异原因」区显示 `原因 + 实际发货量 / 累计验收量 / 差异量`；无原因时显示 `尚未填（验收完成时填写）` 或 `无差异（累计验收量不少于实际发货量）` |

### 10.5 验收量上限与差异判定【规则·V4.6 调整】

| 场景 | 处理 |
| --- | --- |
| 累计验收量 > 实际发货量 | **放行**（V2.0.11）：可能来自补送 / 超发，弹层内提示 `超出实际发货量 N（超发 / 补送）`，不拦截、不要求差异原因 |
| 本次验收量 = 0 / 未填 | 阻断（每批必须 `> 0`）；整行未到货则**不验收该行**，由差异与退货处理 |
| 累计验收量 < 实际发货量 | **不在行验收时拦截**（V4.6），只在「验收完成」环节要求该行填差异原因（§10.4b） |
| 实际发货量 < 下单量 | 行标 `部分发货`；少发的量按行记录（不再单独展示「未发」），**不自动生成退货单**（Q6 沿用） |
| 未发货 | 行内「验收」置灰 + `供应商尚未发货` |

## 11. 退货（商品行售后）【V2.0.21 重写】

> **核心口径**：退货 = **单个商品行的售后单**，**不影响订单状态**（订单始终「已完成」，因为只有已完成订单才能退货）；售后有自己的三个状态，供应商认可后**回写该行实际验收量**。

### 11.1 行级发起

| 项 | 口径 |
| --- | --- |
| 入口 | **L3 商品行内「退货」**（行是操作单元）；未发起过售后的行 = `退货`，发起过（在途 / 已认可 / 不认可）= **`售后详情`** |
| 可退条件 | 订单状态 = **已完成** 且 该行 **实际验收量 > 0** 且 该行**没有在途售后单**；有 `purchase.return.create`。未验收完成的行**不出现**退货入口 |
| 弹层字段 | ① **实际验收量**：只读回显（如 `6 箱`）② **退货量**：手动输入、必填、`> 0` 且 **≤ 实际验收量** ③ **退货原因**：下拉单选、必填，默认 `请选择退货原因`；**选「其他」时下方出现「其他原因」单行输入框（必填、最多 50 字，切回其它选项则隐藏并清空）**（V4.5） ④ **退货凭证（V4.4）**：图片上传，**非必填，最多 5 张**，可逐张删除；满 5 张后按钮置灰 `已达上限 5 张` |
| 退货原因枚举（9 项） | `生鲜状态异常` / `变质腐败` / `存在病虫或异物` / `大小/重量不符` / `加工形态不符` / `少发/漏发` / `包装破损` / `以次充好` / **`其他`**（与「验收差异原因」是**两套枚举**，互不混用）；**选「其他」时额外出现「其他原因」手填框，必填、≤50 字**（V4.5） |
| 单据 | 一张售后单对应一个商品行（带 `source_item_id`）；**同一行同一时刻只能有一张在途售后单**（Q11）；一个订单可有多张售后单 |
| 提交结果 | 生成售后单 `RT + 提交日 + 3 位流水`，售后状态 = **待供应商确认**；**订单状态不变**（仍为已完成）；写时间轴 + 通知供应商 |
| 提示 | `退货申请已提交，等待供应商确认` |

### 11.2 售后状态（三态）【规则】

| 售后状态 | 判定 | 展示 |
| --- | --- | --- |
| 待供应商确认 | 下单方已提交、供应商未答复 | L2「是否有售后」列 + L3 行「售后详情」+ L3「售后记录」卡片 |
| 供应商已认可 | 供应商点了认可 | 同上（绿），该行实际验收量已回写 |
| 供应商不认可 | 供应商点了不认可（**不认可理由必填**） | 同上（红），理由在「售后详情」回显 |

**L2「是否有售后」列取值**：只有 `无` / `有` 两种（该订单内任一商品有过售后即 `有`）；售后三态（`待供应商确认` / `供应商已认可` / `供应商不认可`）**只出现在 L3「售后记录」卡片与「售后详情」抽屉**里。

### 11.3 供应商认可 / 不认可（本期为口径 + 原型模拟）

| 供应商动作 | 结果 |
| --- | --- |
| **认可** | 售后单 = `供应商已认可`；该行 **实际验收量 = 原实际验收量 − 退货量**（回写，最小 0）；该行标 **`有退货`**（累计已退货量留存）；**订单状态不变**（仍已完成）；订单「验收金额」按新验收量重算；原始验收量保留在「验收详情」的验收记录里，另加一条 `售后回写` 说明 |
| **不认可** | 必须填**不认可理由**（≤200 字）；售后单 = `供应商不认可`；该行验收量**不变**；下单方在「售后详情」看到理由后可 **`重新发起`**（生成新售后单，轮次 +1，不设上限） |
| 超时未处理 | 本期**不自动处理**（Q13 沿用），售后停在 `待供应商确认` |

### 11.4 售后详情（L3 行内 `售后详情`）

| 区块 | 内容 |
| --- | --- |
| 商品信息 | 列表形式：商品名称 / 规格 / 单位 / 单价 / **原验收量（退货之前的量 = 当前实际验收量 + 已退货量）** / 已退货量 / 当前验收量 |
| 售后信息 | 售后单号、退货量、退货原因（选「其他」时展示 `其他：具体原因`）、申请时间、申请人、**售后状态**；下方独立「退货凭证」区展示凭证照片块（`非必填 · 本次共 N 张`），未上传显示 `本次售后未上传退货凭证` |
| 状态提示 | `待供应商确认`：`已提交，等待供应商确认；确认前订单状态仍为「已完成」`；`供应商已认可`：`实际验收量已更新为 N`；`供应商不认可`：回显**不认可理由** |
| 历史售后单 | 同一行发起过多次时，列出每张售后单（单号 / 时间 / 退货量 / 原因 / 状态 / 不认可理由） |
| 底部按钮 | `关闭`；`供应商不认可` 时额外出现 **`重新发起`**（重新走 11.1 的表单） |

### 11.5 边界

| 场景 | 处理 |
| --- | --- |
| 有在途售后单时再发起 | 拦截 `该商品已有待供应商确认的售后单`，入口只显示 `售后详情` |
| 部分退货 | 认可后剩余验收量仍 > 0，可再次发起（上限 = 当时的实际验收量） |
| 全额退货 | 认可后该行实际验收量 = 0，行上不再出现 `退货`（只剩 `售后详情`） |
| 不认可 | 可无限次重新发起，售后单逐条留痕（轮次 +1，不设上限） |
| 撤销售后 | 本期**不提供**（待确认期间只能等供应商答复） |
| 售后不改订单状态 | 订单始终 `已完成`；L2 状态筛选里也没有「退货中」 |

## 12. 价格与金额口径【规则】

| 项 | 口径 |
| --- | --- |
| 精度 | 数量、单价、金额均 2 位小数（四舍五入） |
| 行数量 | = **该送达日当天的数量**（V1.0 的「区间内每日数量之和」口径**作废**）；合计由系统汇总，**不能手改** |
| 行金额 | 行金额 = 行数量 × 单价 |
| 订单金额 | = Σ(当日行数量 × 单价)；本期订单生成后金额不再变化（无改单能力） |
| 验收金额 | = Σ(**行当前验收量** × 单价)；随每次行级验收实时变化；无任何行验收时为 0（L2 展示 `—`） |
| 退货 | **订单金额不冲减**（下单金额不变）；供应商**认可**后回写该行实际验收量，**验收金额随之按新验收量重算**（V2.0.21 由 Q12 调整）；已退数量单列展示 |
| 报价口径 | 供应商报价 = 元 / 下单单位；比价与定标都按这一个单价，**不按天分别报价**、不做单位换算 |
| 价格快照 | 下单时冻结，之后供应商预报价变化不影响已生成订单；定标时该商品无任何报价 → 不下单（不生成 0 元行） |
| 改价留痕 | 直采手工改价：行标 `改价`；订单生成后不支持改价 |
| 订单金额 vs 验收金额 | 订单金额按**下单量**算；验收金额按**当前验收量**算；少发 / 少收**不冲减**订单金额 |
| 统计口径 | 列表统计卡与页签计数**均按订单实时计算**；订单金额 = Σ 行 `qty × unit_price`，验收金额 = Σ 行 `accepted_qty × unit_price`；**不允许前端聚合计算金额**（§16.9） |

### 16.9 幂等与统计一致性说明【规则】

| 项 | 口径 |
| --- | --- |
| 生单幂等 | 幂等键 = `stall_id + supplier_id + source_no + delivery_date`；重复提交返回已生成订单 |
| 验收写入幂等 | 行级验收按 `item_id + 值未变化` 判定：无变化不新增记录；重复请求用 `requestId` 去重 |
| 验收完成幂等 | `purchase_order_acceptance.order_id` 唯一；`is_final=true` 后重复调用返回已完成结果，不重复写签名 |
| 供应商一键确认幂等 | 按**订单**幂等：已确认订单跳过；返回 `成功 N / 跳过 M` 明细 |
| 退货幂等 | 同一 `item_id` 存在 `pending` 退货单时拒绝新增；`requestId` 防重复提交 |
| 统计一致性 | 列表统计卡与页签计数**实时按订单聚合**，不落物化快照（V4.0 已无采购单层） |
| 计算来源 | 前端**禁止**自行聚合金额与进度，一律用后端下发字段；列表与详情统计口径完全一致 |
| 重算兜底 | 提供离线重算任务（按 `group_no` 全量重算），用于事件丢失或数据修复；执行结果留审计 |

## 17. 边界与异常【规则】

### 17.1 两层框架新增边界

| 场景 | 期望行为 |
| --- | --- |
| 某天所有商品数量为 0 / 空 | **不生成该天订单**；提交前算好并提示 `共 N 天有需求，已生成 N 张订单` |
| 送达日期区间 > 31 天 | 拦截 `需求区间最长 31 天，请缩小范围` |
| 定标后某供应商无任何中标商品 | 该供应商不生成订单 |
| 重复提交 / 重复定标 | 幂等键命中 → 返回已有订单，不重复生单 |
| 同日同供应商两张不同来源的订单 | 列表 **各自成行，不合并** |
| 未发货就想验收 | 行内「验收」置灰 + `供应商尚未发货` |
| 验收量 > 实际发货量 | **不拦截**（V2.0.11）：只有验收量 < 实际发货量时才要求差异原因 |
| 短收但没填差异原因 | 拦截 `「商品名」少收需选择差异原因` |
| 还有行未验收就想完成 | 拦截 `还有 N 个商品未验收，请先完成验收` |
| 订单已完成后再点验收 | 只读，提示 `订单已完成，验收量已锁定` |
| 商品资质已过期 | 只标 `已过期`，**不阻断验收**（纯展示信息） |
| 商品无资质照片 | 显示 `供应商尚未上传该商品的检测报告` |
| 档口切换 | 无「全部档口」选项；切换只改数据过滤，不改权限、不聚合 |

### 17.2 V1.0 继承的边界与异常（继续有效）

| 场景 | 期望行为 |
| --- | --- |
| 定标转单时某商品无成交价 / 定标 0 成交 | 该商品不生成明细行，生单后提示 `N 个商品因无成交价未生成订单`；0 成交则完全不生单 |
| 生单过程中部分失败 / 重复提交 | 同事务回滚，不留半张；可「重新生成」（幂等，按来源单号 + 供应商 + 区间去重） |
| 部分发货 / 部分验收 | 允许，分别标 `部分发货` / `部分验收`；剩余与补送均线下处理 |
| 选择电子秤验收 | 入口置灰：`电子秤验收需对接设备，本期暂未开放`；记录里不会出现该方式 |
| 验收中长期未完成 / 验收时商品已被下架 | 不自动完结，停在验收中（Q4）；商品已下架时明细照常展示（快照），可正常验收 |
| 供应商解除合作 / 商品下架（下单后） / 档口被删除 | 在途单据不受影响（全部为快照）；新建下单时该供应商 / 商品不再出现；存在未完结订单时**禁止删除档口** |
| 全部行验收量为 0 | 不允许「验收完成」；须改用售后单（视为全单退货）或补送后改量 |
| 供应商多次不认可售后 / 订单金额 vs 退货 | 可无限次重新发起、只记录轮次；**订单金额不冲减**，认可后回写行验收量并重算验收金额（§12） |
| 组织层查看 / 某天没有任何商品 | 组织层只有档口卡片总览，点进才看 L1；某天无行则该天不生成订单，全部天为空不能提交 |
| 单档口账号 / 授权档口被回收 | 下拉退化为只读显示；授权被回收后当前档口回退到第一个可用档口 |
