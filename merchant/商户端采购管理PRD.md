## 1. 共用底座（两模块合写一章，避免重复）

### 1.1 菜单与入口
- `采购管理` → `采购订单`（两层：订单列表 → 订单详情）、`供货关系管理`（单层）。
- 面包屑固定 `采购管理 / ×××`；详情返回只回列表。

### 1.2 数据范围：组织 × 档口切换器【规则】
- 切器只做**数据过滤**，不改单据归属；与全局切器**双向同步**。
- **不提供「全部档口」**：列表与统计卡永远只看单个档口；默认选中授权范围内第一个档口。
- 切组织 → 落到该组织第一个档口并刷新；授权外档口不出现在下拉里。

### 1.3 上下游依赖

| 依赖 | 取用内容 | 本文需交付 |
| --- | --- | --- |
| 计划管理 › 采购计划 | **按计划需求明细（SKU + 需求量 + 送达日期）转单**（来源 B，§2.7）【已确认：本期交付】；**供应商 = 该计划定标时选定的供应商** | 转单入口、字段映射、拆单、幂等 |

| 结算/成本（后续） | 验收金额可用于成本归集 | 只留字段，本期不实现 |

### 1.4 全局口径（只在这里定义）
- **订单编号**：`CG + 送达日期 yyyyMMdd + 3 位随机数`，例 `CG20261101483`；**随机数不随流水重置**，只需保证同送达日期内不重复（撞号重取）。与长文档 `PO…` 冲突处**以本节为准**。
- **退货单号**：`RT + 提交日期 yyyyMMdd + 3 位随机数`，同规则，不随流水重置。【已确认】
- 数量一律 = **SKU 下单单位**的数量，系统不做克→箱折算。
- **精度口径（全文唯一）**：
  - 数量、单价：2 位小数，四舍五入。
  - **金额：2 位小数，小数第 3 位起直接截断，不做四舍五入**（订单金额、验收金额、行总价、小计、合计、统计卡金额一律如此，金额只向下取、不允许因进位虚增）。
  - 计算过程用原始精度（数量 × 单价原值），**只对最终金额做截断**，不允许先把单价四舍五入再相乘。
- 幂等键：`档口 + 供应商 + 来源单号 + 送达日期`；重复提交不重复生单。
- 一张订单 = 一个送达日期 + 一家供应商；送达日期区间 ≤ 31 天。
- 订单在 `待确认` 状态**可删除**（即撤回）；进入 `已确认` 及之后**不可撤回、不可删除**，系统无其它撤回动作。

### 1.5 本期不做（全局）
供应商端界面、结算对账与审批流、整单验收、跨档口合并视图、**跨订单复制**（复制商品/复制整单到另一张单）、导出、打印模板、订单额度校验。

## 2. 模块 A · 采购订单

### 2.1 定位与结构
- 一句话：**订单是本模块唯一实体**，商品明细是订单详情的一整页（不是抽屉）；验收与售后都落在商品行上。
- 两层：`订单列表（N 张）` → `订单详情 / 商品明细整页（M 行）`；另有 `新建订单向导（3 步，直采）` 与 `采购计划转单（来源 B，无向导）`。
- **只有一个手工来源 + 一个转单来源**，订单环节本身不选供应商：
  - 直采下单 → 供应商由**供货关系管理**决定（§2.6）
  - 采购计划转单 → 供应商由**采购计划定标结果**决定（§2.7）

### 2.2 状态模型【规则】（全文只此一处）
- 主状态 5 态：`待确认 → 已确认 → 待验收 → 验收中 → 已完成`；无「已取消」「退货中」。
- 派生标签（不改主状态）：`部分发货`、`有退货`、`手动验收`、`已签名`、`来源：直采 / 计划`、价格来源标签。
- 一期只可能出 `手动验收`（电子秤对接不做）。

### 2.3 状态 × 下单方可操作【规则】

> 下单方 = 商户端采购方。**两个条件取交集**：状态允许 + 有该项权限，缺一不显示按钮（不置灰）。
> **来源决定"能不能改"**：直采下单是商户自己选品选量，未确认前可整单改；采购计划转单的下单内容来自计划定标结果（供应商、商品、数量、送达日期），**任何状态都不允许修改**。

**状态链两条来源一致**：`待确认 → 已确认 → 待验收 → 验收中 → 已完成`；差异只在各状态可做的操作。

#### 2.3.1 来源 = 直采下单

| 状态 | 可做的操作 | 明确不可做 / 说明 |
| --- | --- | --- |
| 待确认 | 查看详情、**修改订单**（收货联系人/电话、收货地址、商品清单：增删行 + 改采购量）、**删除**（二次确认后物理删除） | 不能验收、不能退货；供应商尚未确认 |
| 已确认 | 查看详情 | 修改入口消失、删除消失；等供应商发货 |
| 待验收 | 查看详情、**行级验收填量**（第 1 批） | 不能「验收完成」；不能退货；发起后不可撤回 |
| 验收中 | 查看详情、继续**分批累加**验收、改任一批次数量、**删除任意批次**（删除后置灰保留）、**验收完成 + 电子签名**（前置：全部行已验收） | 完成后所有行验收量锁定；不能退货（须先完成） |
| 已完成 | 查看详情、验收详情只读、**从商品行发起退货**、售后详情 | 验收量不可改、订单不可改不可删；退货**供应商认可后冲减验收金额**，**订单金额不变**（在途 / 不认可不冲减） |

#### 2.3.2 来源 = 采购计划转单

| 状态 | 可做的操作 | 明确不可做 / 说明 |
| --- | --- | --- |
| 待确认 | 查看详情、**删除**（二次确认后物理删除） | **不提供「修改订单」**（含收货联系人/电话、收货地址）；商品清单、供应商、数量、送达日期全部锁定；不能验收、不能退货 |
| 已确认 | 查看详情 | 无修改、无删除；等供应商发货 |
| 待验收 | 查看详情、**行级验收填量**（第 1 批） | 与直采一致：不能「验收完成」、不能退货 |
| 验收中 | 查看详情、分批累加验收、改任一批次数量、**删除任意批次**（删除后置灰保留）、**验收完成 + 电子签名** | 与直采一致；完成后锁定 |
| 已完成 | 查看详情、验收详情只读、**从商品行发起退货**、售后详情 | 与直采一致：验收量不可改、订单不可改不可删；退货仅冲减验收金额 |

- 【规则】除「修改 / 删除」随来源不同外，验收、验收完成、退货、售后四段操作两种来源完全一致，不因来源做差异化限制。


### 2.4 第 1 层 · 订单列表

**页面结构**：页头（标题 `采购订单` + 右上 `+ 新建订单`）→ 统计卡区 → 筛选条 → 两组平铺页签 → 订单表。

#### 2.4.1 统计卡 ×5

| 卡片 | 取数口径 |
| --- | --- |
| 订单总数 | 当前档口**历史 + 今天**的订单数（不区分状态） |
| 订单验收总金额 | 当前档口**历史 + 今天**「已完成」订单的**验收总金额**累计 |
| 本月订单数 | 当前档口**本月**的订单数（不区分状态） |
| 本月订单验收总金额 | 当前档口**本月**「已完成」订单的**验收总金额**累计 |
| 待我验收完成订单数 | 当前档口**历史 + 今天**「验收中」的订单数 |

- 【规则】5 张卡只跟**档口**走：切档口刷新；**不受筛选条件和页签影响**（改日期 / 来源 / 供应商 / 状态，卡片数字不变）。
- 金额统一 2 位小数带 `¥`，**小数第 3 位起截断、不四舍五入**（§1.4）；卡片数值与列表数据必须同源，不允许前端二次累加。

#### 2.4.2 筛选条（顺序固定，从左到右）

| 筛选项 | 控件 | 数据源 | 生效方式与默认值 |
| --- | --- | --- | --- |
| 送达日期 | 起 ~ 止 两个日期框 | 用户选择，无候选 | 默认 `[今天-15, 今天+15]`；改动**即时生效** |
| 来源 | 下拉 | 固定枚举：全部来源 / 直采下单 / 采购计划 | 默认「全部来源」；改动即时生效 |
| 供应商 | 下拉 | 该档口**已出现过**的供应商去重（直采取供货关系绑定、转单取计划定标供应商）【已确认】；为空时只保留「全部供应商」 | 默认「全部供应商」；改动即时生效 |
| 订单编号 | 输入框 | 无 | 空；**回车**或点 `查询` 生效，包含匹配、忽略大小写 |
| `查询` / `重置` | 按钮 | — | `重置` 恢复：日期回今天±15 天、来源与供应商回「全部」、编号清空、两组页签回「全部」 |

- 日期非法（起 > 止）不报错，按交集为空处理，列表给无结果态。

#### 2.4.3 两组平铺页签（带张数）

| 页签组 | 选项 | 计数口径 |
| --- | --- | --- |
| 订单状态 | 全部状态 / 待确认 / 已确认 / 待验收 / 验收中 / 已完成 | 计数基数 = **当前日期 / 来源 / 供应商 / 编号筛选后的订单集**，不含自身页签条件，也不含另一组页签条件 |
| 售后 | 全部售后 / 有售后 / 无售后 | 同上 |

- 计数为 0 的页签**灰态不可点**，仍保留展示（让人看到「该状态没有单」）。
- 两组页签**交叉生效**（状态 + 售后同时过滤）；点页签只重算列表，**不重算统计卡**。

#### 2.4.4 表格（11 列，顺序固定）

| # | 列名 | 字段口径 |
| --- | --- | --- |
| 1 | 订单编号 | `CG…`（§1.4）；可点击进详情 |
| 2 | 供应商 | 订单所属供应商名称 |
| 3 | 来源 | 标签 `直采下单` / `采购计划`；转单额外显示**来源单号**（计划单号），直采无单号 |
| 4 | 送达日期 | `MM-DD 周X` |
| 5 | 品项 | 该订单**不同 SKU 数** + 「项」（不是商品行数） |
| 6 | 订单总金额 | Σ（采购量 × 单价），结果**截断到 2 位小数**（§1.4） |
| 7 | 验收总金额 | Σ（累计验收量 × 单价），结果**截断到 2 位小数**；该订单**没有任何行验收过**时显示 `—` |
| 8 | 订单状态 | 状态标签 + 派生标签：`部分发货`（有行已发货且未全部发货）、`已签名`（已完成且已签名） |
| 9 | 是否有售后 | `有` / `无`；有 = 该订单任一商品提交过售后（售后三态不在列表展开，进详情看） |
| 10 | 创建时间 | `MM-DD HH:mm` |
| 11 | 操作 | 见 2.4.5 |

#### 2.4.5 行操作（与 §2.3 取交集，不满足即不显示）

#### 2.5.5 行操作（三种，按状态显隐）

| 按钮 | 出现条件 | 动作 |
| --- | --- | --- |

| 有待确认订单（状态 = 待确认） | 空态 `订单待供应商确认，确认发货后回显预计发货时间与配送员` |

#### 2.5.7 售后记录（7 列）

| 列 | 口径 |
| --- | --- |
| 售后单号 | `RT` 号（§1.4） |

#### 2.5.8 状态时间轴

按钮随状态出现：`确认订单`（待确认）、`确认发货`（已确认）、`认可售后` / `不认可售后`（存在待确认售后时）。正式版由供应商端接口驱动。

### 2.6 新建订单向导（3 步，来源 A 直采）

#### 2.6.1 入口与商品池

- 入口：订单列表右上 `+ 新建订单`，直达第 1 步（不存在「选供应商」步）。

**商品池口径（核心结论，开发必读）**
> **可添加的商品列表 = 该档口「已绑定过供应商」的商品**；未绑定供货关系的商品**不会出现**在可添加列表里。
> 三个条件同时满足才进入候选：① 该档口**在售**（商品中心上下架） ② 该档口该 SKU **已在供货关系管理绑定供应商** ③ 该绑定供应商对该 SKU **有预报价**。
> 三者缺一即不出现。

| 场景 | 展示 |
| --- | --- |
| 该档口一个候选商品都没有 | `该档口还没有「已绑定供应商且有报价」的商品，无法下单。请先到 采购管理 › 供货关系管理 把商品绑定到供应商（单价与供应商都取自这里）。` + 按钮 `去供货关系管理` |
| 区间内日期被全部删除 | `区间内 N 天已全部删除，点右上角「恢复已删除的日期」或重新选择日期区间` |
| 当前日期还没有商品 | `MM-DD 还没有商品，点右上角「+ 添加该日商品」` |

#### 2.6.2 第 1 步 · 送达日期与数量

| 区块 | 内容与口径 |
| --- | --- |
| 日期区间 | `起始日` ~ `结束日` 两个日期框；**区间最长 31 天**，每个日期单独下单，某天不填则不生成该天订单 |

**可选项与数据源**

| 可选项 | 数据源 | 过滤 / 口径 |
| --- | --- | --- |
| 商品（添加抽屉候选） | 供货关系管理 + 商品中心 + 供应商预报价 | 按 §2.6.1 三条；下架 / 未绑定 / 无报价一律不出现 |

| 单价 | 该供应商对该 SKU 的预报价 | **只读**，下单时快照进订单行 |

| 采购量 | 手输 | > 0，2 位小数 |
| 备注 | 手输 | 选填，随行带入订单行备注 |

#### 2.6.3 添加商品抽屉

| 区块 | 口径 |

#### 2.6.5 第 3 步 · 收货与提交

| 字段 | 控件 | 数据源 | 校验 |
| --- | --- | --- | --- |
| 收货联系人 | 只读输入框 + `选择` / `重选` / `清除`，点开抽屉单选 | **门店后厨人员**（组织人员下拉发）；抽屉内可搜姓名 / 手机号，表格 3 列：姓名 / 手机号 / 选择 | 必填；**不支持手工输入**（提示 `请选择收货联系人（门店后厨人员）`） |

### 2.7 来源 B · 采购计划转单【已确认：本期交付】

#### 2.7.1 定位与前置

- 转单 = 把**已定标**的采购计划按需求明细一次性批量生成订单，不走新建向导、不选商品、不选供应商。
- 入口显示前置（全部满足）：① 计划属于当前档口 ② 计划**已完成定标** ③ 计划**未转单**。

#### 2.7.2 入口与交互

- 入口：采购计划（档口级）详情页主按钮 `生成采购订单`；**订单列表不提供转单入口**。
- 点击弹二次确认：`将为该计划生成 N 张订单（按送达日期 × 供应商拆单），生成后不可撤回，是否继续？`（N 由提交前预计算回显）。
- `取消` 不产生任何单据；`确认` 后按钮进入 loading，防重复点击。

#### 2.7.3 字段映射（计划 → 订单）

| 订单字段 | 取值来源 |
| --- | --- |
| 档口 | 计划所属档口 |
| 供应商 | 计划该商品**定标时选定的供应商**；转单不重选、不改派【已确认】 |
| 单价 | 该供应商对该商品的**定标报价**，直接带入；不重取预报价、不允许改价【已确认】 |
| 采购量 | 计划该商品在**该送达日期**的需求量（SKU 下单单位，不折算） |
| 送达日期 | 需求明细的日期；一张订单只带 1 个日期 |
| 来源 | 固定 `采购计划` |
| 来源单号 | 计划的计划单号 |
| 收货联系人 / 电话 | 默认该档口负责人（姓名 + 手机）；负责人为空时留空，提交前必须补填【已确认】 |
| 收货地址 | 默认门店地址【已确认】 |
| 订单状态 | `待确认`（推送供应商后待其确认） |
| 订单编号 | 按 §1.4 生成 |

#### 2.7.4 拆单规则

- 分组键 = **（送达日期 × 供应商）**，每组生成 1 张订单。
- 同一计划：同一天不同供应商 → 多张；同一供应商不同天 → 多张。
- **无需求量的日期不生成订单**（如 3 天里只有 2 天有需求，只生成那 2 张）。
- 同一计划生成的子订单带同一个「同批」标记，仅用于列表聚拢与详情提示，**不产生新单据、不产生新编号**。

#### 2.7.5 明确不判断的三件事（避免开发自行补校验）

| 不判断 | 原因 |
| --- | --- |
| 供货关系是否已绑定 | 转单供应商来自计划定标结果，与供货关系无关；未绑定商品同样能转 |
| 商品当前是否在售 | 按计划快照行转，不回查上下架（下架商品也可能有一笔待送采购）【待确认】 |
| 预报价 | 单价只用定标报价，不取预报价 |

- 因此**不产生「跳过商品」清单**：能否转只看该计划里有没有需求量。

#### 2.7.6 幂等与失败

- 幂等键 `档口 + 供应商 + 计划单号 + 送达日期`：同键重复提交不重复生单，返回 `该计划已生成订单`。
- 生单失败**整体回滚**、不允许部分成功（避免计划半转单）；报错需指出失败原因并允许重试，重试仍走同一幂等键。

#### 2.7.7 结果与回写

- 生成后返回订单列表；若新单送达日期不在当前筛选区间，提示 `已生成 N 张订单，部分不在当前筛选范围` 并给「放宽筛选」入口，确保新单可见。
- 计划侧：标记 `已转单` + 回显生成的订单号；计划转单后**只读**，不可再编辑、不可重复转单。

#### 2.7.8 与直采的差异

| 维度 | 直采下单（来源 A） | 计划转单（来源 B） |
| --- | --- | --- |
| 入口 | 列表 `+ 新建订单` 向导 | 计划详情 `生成采购订单` |
| 商品 | 手工添加（已绑定 + 有报价） | 计划需求明细，不可增删 |
| 供应商 | 供货关系绑定 | 计划定标结果 |
| 单价 | 预报价快照 | 定标报价 |
| 备注 | 可填 | 不带 |
| 待确认态可改 | 收货信息 + 商品清单 | **仅收货信息** |

#### 2.7.9 本节待确认（2 项）

1. 已下架商品是否仍允许转单（当前口径：允许，按计划快照转）。
2. 是否支持同一计划**分次转单**（当前口径：不支持，一次全转）。

### 2.8 行级验收

#### 2.8.1 验收单元与入口

- 验收单元 = **商品行**（一个 SKU 一行），不是整单。
- 入口：订单详情商品行的 `验收` 按钮。前置：① 订单状态 ∈ {待验收, 验收中} ② 该行**已发货**（`实际发货量 ≠ 空`）；未发货点不了（提示 `供应商尚未发货`）。
- 可分多次、多批验收；**每批只填「这一次」的量，累加进累计验收量**。

#### 2.8.2 验收弹层（一级抽屉）字段

标题 `验收 · {商品名}`，副标题 `{订单号} · 送达 MM-DD 周X · 第 N 批`（N = 已存批次数 + 1）。

| 区块 | 内容 |
| --- | --- |
| 商品信息（8 列） | 商品名称（+形态）/ 规格 / 单位 / 单价 / 下单量 / **实际发货量** / 已验收量（无则显示 `未验收`）/ **待验收量**（无验收时 = 实际发货量） |
| 本次验收量 | 数字输入，`*` 必填；提示文案 `填「这一次」的收货量，会累加到已验收量；可分多次验收，差异原因在「验收完成」环节填写` |
| 实时汇总条 | 随输入实时变化，见 2.8.3 |
| 验收方式 | 只读展示 `手动验收`（本期唯一方式） |
| 验收照片 | **选填，0～5 张**；`+ 添加照片`，可逐张删除；有历史批次时**回填上一批照片**（提示 `已回填上一批 N 张，最多 5 张，可删除`）；达上限按钮变 `已达上限 5 张` |
| 历史验收（5 列） | 批次 / 时间 / 验收人 / 本次验收量 / 照片；**仅展示，不可改不可删**（改删在验收详情里做）；提示 `共 N 批 · 合计 X 单位，仅展示；修改 / 删除请在「验收详情」里操作` |
| 底部 | `取消`（回到商品明细）/ `保存` |

#### 2.8.3 实时汇总与差异判定

汇总条公式：`本次 X + 已验收 Y = 累计 Z 单位`，并按 Z 与实际发货量的关系变色 + 追加文案：

| 关系 | 文案 | 处理 |
| --- | --- | --- |
| 累计 > 实际发货量 | `超出实际发货量 D 单位（超发 / 补送）` | **不拦截**，可保存 |
| 累计 < 实际发货量 | `少于实际发货量 D 单位，验收完成时需填差异原因` | 可保存，收口时补原因（§2.8.7） |
| 累计 = 实际发货量 | `与实际发货量一致` | 可保存 |

- 未填量时汇总条只显示 `已验收 Y 单位 · 待验收 P 单位`。

#### 2.8.4 保存后的连带影响【规则】

1. 新增 1 条批次记录：批次号、时间、验收人、验收方式、本批量、改前累计、改后累计、照片张数、差异原因（此处为空）。
2. 该行累计验收量 = 改后累计；行状态变 `已验收`。
3. 订单状态 `待验收` → `验收中`（不动 `已完成`）。
4. 写 1 条状态时间轴（§2.5.8）。
5. 关闭弹层，刷新商品明细；toast `「{商品名}」本次验收 X{单位}已记入（累计 Z{单位}）`。
6. 校验拦截：未填 → `请填写本次验收量`；填 0 或负数 → `本次验收量必须大于 0`。

#### 2.8.5 验收详情（二级抽屉）

标题 `验收详情 · {商品名}`，副标题 `{订单号} · 送达 MM-DD 周X`；底部只有 `关闭`。区块顺序固定：

| 区块 | 内容与口径 |
| --- | --- |
| ① 商品信息（10 列） | 商品名称（+形态）/ 品牌 / 规格 / 单位 / 单价 / 下单量 / 实际发货量 / 累计验收量 / 待验收量 / **当前验收金额**（累计验收量 × 单价，截断到 2 位小数）；未验收项显示 `—` |
| ② 售后回写横幅（有退货量时） | `售后回写：该商品已退货 X{单位}，当前累计验收量 Y，验收金额已冲减 ¥Z（订单金额不变）；原始批次记录保留在下方（不覆盖历史）` |
| ③ 验收批次记录（8 列） | 批次 / 时间 / 验收人 / 验收方式 / 本批验收量 / 累计 / 照片 / **操作**（`修改` 恒有；`删除` 任意批次可点，删后该行置灰、操作列显示 `已删除`）；标题带 `共 N 批 · 累计 X 单位` + 提示语（未完成：`可改单批数量；删除任意批次，删除后置灰保留`；已完成：`订单已完成，验收量已锁定`，操作列全部显示 `—`） |
| ④ 差异原因 | 三态文案见下表 |
| ⑤ 验收照片 | 只展示**最近一批**：`最近一批 · 第 N 批 · 共 X 张`；空态 `该商品尚未上传验收照片` |
| ⑥ 商品资质照片 | 供应商上传、商户端只读。每条显示：报告名 + 类型 + `有效期至 X` + 过期标 `已过期` + `上传：供应商 · 时间`；空态 `供应商尚未上传该商品的检测报告` |
| ⑦ 验收人员签字照片 | 签名图 + 验收人 + 时间；空态 `该订单尚未完成验收签名` |

**差异原因区块三态**

| 情况 | 展示 |
| --- | --- |
| 已填差异原因 | 原因文本（选其他显示 `其他：具体原因`）+ 明细行 `实际发货量 X · 累计验收量 Y · 差异 D · 验收完成时填写` |
| 未填且累计 < 发货量 | `累计验收量少于实际发货量，差异原因将在「验收完成」时填写` |
| 累计 ≥ 发货量 | `无差异（累计验收量不少于实际发货量）` |

#### 2.8.6 批次修改与删除【规则】

| 操作 | 规则 | 文案 |
| --- | --- | --- |
| 修改批次数量 | 只能改**数量**；就地变输入框 → `保存` / `取消`；保存后按批次顺序**重算所有批次的累计**（`改后累计` 全部重算）并重算该行累计验收量，写时间轴，重开验收详情 | 未填 `请填写验收量`；≤0 `验收量必须大于 0`；成功 `第 N 批验收量已改为 X{单位}，累计 Z{单位}` |
| 删除批次 | **可删除任意批次**（不限最新一批）；二次确认后删除；删除后该批次行**不消失**，整行**置灰**、操作列显示 `已删除` 且不可再操作；该行验收量按**未删除批次**重新累计（后续批次累计值同步重算），写时间轴 | 确认文案 `是否删除第 N 批验收（X 单位）？删除后累计验收量会相应减少，已删除记录置灰保留、不可恢复。`；成功 `第 N 批验收已删除，累计 Z{单位}` |
| 订单已完成 | 批次**只读**，操作列显示 `—` | — |

- 每次改 / 删都写 1 条状态时间轴留痕，**不覆盖历史**。

#### 2.8.7 验收完成（差异原因确认 → 电子签名）【规则】

1. 点 `验收完成（签名）`（验收中状态条右侧）。前置校验：**全部行已验收**，否则提示 `还有 N 个商品未验收，请先完成验收`。
2. 若存在「累计验收量 < 实际发货量」的行 → 先开**差异原因确认抽屉**：
   - 标题 `验收完成 · 差异原因确认`，副标题 `{订单号} · N 个商品累计验收量少于实际发货量`
   - 横幅：`以下商品的累计验收量少于实际发货量，请逐个填写差异原因；全部填写后进入电子签名。`
   - 表格 8 列：商品名称（+形态）/ 品牌 / 规格 / 单位 / 实际发货量 / 累计验收量 / **差异量** / **差异原因**（下拉 + 选「其他」时出现手填框，≤50 字）
   - 差异原因枚举（9 项，顺序固定）：`生鲜状态异常` / `变质腐败` / `病虫害或存在异物` / `大小/重量不符` / `加工形态不符` / `少发漏发` / `包装破损` / `送错货` / `其他`
   - 底部：`取消`（回商品明细）/ `下一步：签名`
   - 校验：某行未选原因 → `请选择「{商品名}」的差异原因`；选其他未填 → `请填写「{商品名}」的其他原因`
3. 无差异行则**跳过**差异确认，直接进签名抽屉。
4. 签名抽屉：标题 `验收完成 · 电子签名`，副标题 `{订单号} · 全部 N 行已验收`
   - 有差异时顶部列出差异商品表（8 列，8 = 上述去掉下拉，改为只读原因文本）+ `修改差异原因` 按钮（可回到第 2 步）
   - `验收人`（`*`）：从**门店后厨人员**中**多选**，抽屉内可搜姓名 / 手机号，表格 3 列（姓名 / 手机号 / 选择），不支持手工输入
   - `手写签名`（`*`）：画布手写，提示 `如多人验收，请在一张签名框内签字`，可 `清除`
   - 底部：`我再看下`（取消，回商品明细）/ `验收完成`
   - 校验：未选验收人 → `请至少选择 1 名验收人`；未签名 → `请先完成电子签名`
5. 完成后：订单状态 → `已完成`；写入验收记录（时间、验收人、签名图、差异清单）；**全部行验收量锁定**；商品明细只读；toast `验收完成，已签名，订单 {单号} 已完成并锁定`。

#### 2.8.8 锁定规则汇总

| 状态 | 验收量 | 批次增删改 | 行操作 |
| --- | --- | --- | --- |
| 待验收 | 可填 | 不可（还没批次） | `验收` 可点 |
| 验收中 | 可继续累加 | 可改任意批次、**可删任意批次**（删除后置灰保留、操作列 `已删除`） | `验收` 可点 |
| 已完成 | **锁定** | 全部 `—` | 只剩 `验收详情` + `退货/售后详情` |

#### 2.8.9 自动验收完成【规则】

1. **触发**：订单的送达日期当日结束、进入**第二天 00:00** 时，若该单还没有完成验收，系统自动把状态置为 `已完成`（不需要商户操作，无签名）。
2. **数据表现**：未验收的行验收量 = 0、验收金额 = 0；**差异原因显示 `-`**；**验收人显示 `-`**；**无电子签名**（验收详情页签名为空，不显示「未签名」错误态）。
3. **时间轴**写 `送达日期已过，系统自动验收完成（无签名）`；订单转 `已完成` 后按 §2.8.8 全部锁定，可正常发起退货。
4. 已产生的验收批次**保留**（累计验收量按已验收部分计），未验收部分不再补验收。
5. 【待确认】送达日已过但仍停在 `待确认` / `已确认`（供应商未确认、未发货）的单，是否同样自动收口为 `已完成`：现按**一并收口**处理（这类单无任何验收记录，差异原因与验收人均为 `-`）。


### 2.9 售后（退货）

#### 2.9.1 发起条件【规则】

| 条件 | 说明 |
| --- | --- |
| 订单已 `已完成` | 未完成时点不到入口；越权调用提示 `需「验收完成」后才能发起退货` |
| 该行累计验收量 > 0 | 没验收过就没有可退的量 |
| 该行无「待供应商确认」的售后单 | 有在途单时提示 `该商品已有待供应商确认的售后单` |
| 该行从未发起过售后 | 已有任意售后记录时，行操作变成 `售后详情`（可重新发起见 2.9.5） |

#### 2.9.2 退货弹层字段

标题 `退货 · {商品名}`，副标题 `{订单号} · 送达 MM-DD 周X · 实际验收 X 单位`。

| 区块 | 字段 | 规则 |
| --- | --- | --- |
| 商品信息（5 列） | 商品名称（+形态）/ 规格 / 单位 / 单价 / **实际验收量** | 只读 |
| 退货量 | 数字输入，`*` 必填 | 提示 `必填，不可超过实际验收量 X 单位`；> 0 且 ≤ 实际验收量 |
| 退货原因 | 下拉，`*` 必填 | 9 项：`生鲜状态异常` / `变质腐败` / `存在病虫或异物` / `大小/重量不符` / `加工形态不符` / `少发/漏发` / `包装破损` / `以次充好` / `其他` |
| 其他原因 | 文本，`*` 条件必填 | **仅当原因为「其他」时出现**；≤50 字；切回其它原因自动隐藏并清空 |
| 退货凭证 | 照片，选填 | 最多 5 张，可逐张删除（照片 / 检测截图 / 聊天记录均可）；达上限按钮变 `已达上限 5 张` |
| 底部 | `取消` / `提交退货申请` | — |

- 【注意】退货原因枚举与「验收差异原因」是**两套枚举，不可混用**（差异原因里是 `病虫害或存在异物`、`少发漏发`、`送错货`）。

#### 2.9.3 提交校验

| 拦截项 | 文案 |
| --- | --- |
| 退货量未填 / 非数字 / ≤0 | `请填写退货量` |
| 退货量 > 实际验收量 | `退货量不能大于实际验收量（X）` |
| 未选原因 | `请选择退货原因` |
| 原因为「其他」但未填 | `请填写「其他」的具体原因` |

#### 2.9.4 售后三态与流转

| 状态 | 判定 | 商户端表现 |
| --- | --- | --- |
| `待供应商确认` | 已提交，供应商未处理 | 行操作变 `售后详情`；列表「是否有售后」= `有`；订单状态仍是 `已完成`；**金额均不冲减** |
| `供应商已认可` | 供应商认可，回写退货量 | 该行 `实际验收量` 扣减、标 `有退货`；**仅验收金额冲减，订单金额不变**（§2.9.4a）；售后详情给绿色横幅 |
| `供应商不认可` | 供应商不认可并给理由 | 售后详情给黄色横幅 + 理由；**金额均不冲减**；允许**修改后重新发起** |

**2.9.4a 金额冲减规则【规则】**

| 项 | 口径 |
| --- | --- |
| 触发时点 | **仅「供应商已认可」时冲减**；提交后（待确认）、不认可、不认可后重新发起期间**均不冲减** |
| 冲减对象 | **只冲减验收金额**：① 该行累计验收量扣减退货量 ② 订单**验收金额**随之减少 |
| 不冲减 | **订单金额（下单金额）与行总价一律不变**，仍等于下单时的 `下单量 × 单价` 快照；退货量不影响下单口径 |
| 冲减金额 | `退货量 × 该行单价`，按 §1.4 截断到 2 位小数；冲减后验收金额 = Σ(回写后累计验收量 × 单价)，与按公式直接重算结果一致 |
| 一致性 | 订单详情摘要行：`订单金额` 保持下单值不变，`验收金额` 变小；不允许出现「验收金额已扣减但行验收量没变」的中间态 |
| 历史留存 | 原始验收批次记录**不删除不覆盖**，只在行上体现「已退货量 / 当前验收量」 |
| 多次退货 | 每次认可各冲减一次验收金额，累计冲减额 = Σ(每次认可退货量 × 单价) |
| 留痕 | 写状态时间轴 `供应商已认可退货 {售后单号}，冲减验收金额 ¥Y` |

- 【规则】售后**不产生订单状态变化**，订单始终停在 `已完成`。
- 轮次**不设上限**，按该行已存售后单数自动 +1，只记录轮次不限制次数。

#### 2.9.5 售后详情（二级抽屉）

标题 `售后详情 · {商品名}`，副标题 `{订单号} · 送达 MM-DD 周X · 售后单 {单号}`；底部 `重新发起`（仅最新单为「不认可」时出现）+ `关闭`。

| 区块 | 内容与口径 |
| --- | --- |
| ① 状态横幅 | 已认可：`供应商已认可：该商品实际验收量已更新为 X 单位，验收金额相应冲减 ¥Y（订单金额不变），行标「有退货」。` / 不认可：`供应商不认可：{理由|未填写理由}。可修改后重新发起。` / 在途：`已提交，等待供应商确认；确认前订单状态仍为「已完成」，金额不冲减。` |
| ② 商品信息（7 列） | 商品名称（+形态）/ 规格 / 单位 / 单价 / **原验收量（退货前）** / **已退货量** / **当前验收量**；原验收量 = 当前验收量 + 已退货量 |
| ③ 售后信息（5 列表格） | 售后单号 / 退货量 / 退货原因 / 申请时间（+ 申请人）/ 售后状态；标题带 `本行共 N 张售后单` |
| ④ 退货凭证 | `非必填 · 本次共 N 张`；空态 `本次售后未上传退货凭证` |
| ⑤ 历史售后单（6 列，仅当该行售后单 > 1） | 售后单号 / 申请时间 / 退货量 / 退货原因 / 售后状态 / 不认可理由；倒序 |

#### 2.9.6 边界

- 本期**不做**：补货单、换货单、退货对账与退款流水（**金额冲减本身已实现**，见 §2.9.4a）。
- 供应商侧只定接口口径，商户端不出现任何供应商操作界面（原型「模拟」按钮正式版删除）。

### 2.10 校验与文案汇总

#### 2.10.1 校验清单（跨页面）

| # | 页面 | 触发时机 | 拦截 / 处理 | 文案 |
| --- | --- | --- | --- | --- |

| 4 | 向导步 3 | 提交 | 未选收货联系人 | `请选择收货联系人（门店后厨人员）` |
| 5 | 向导步 3 | 提交 | 收货地址为空 | `请填写收货地址` |
| 6 | 向导步 3 | 提交 | 区间内无任何数量 | `所选区间内没有填写任何数量` |
| 7 | 向导 | 提交确认 | 二次确认 | `是否确认提交该次采购？`（`确认` / `我再看看`） |

## 3. 模块 B · 供货关系管理

### 3.1 定位【规则】
- 一条关系 = **档口 × 商品 SKU × 1 家供应商**，一对一，重复绑定即**覆盖**。
- 它是**直采下单**的**唯一数据底座**：商品池、供应商、单价全部取自这里；没绑定就没有直采下单入口（§2.6）。
- 与来源 B 无关：转单的供应商由采购计划定标结果决定，不查本模块（§2.7）。

### 3.2 术语
| 术语 | 口径 |
| --- | --- |
| 绑定状态 | 已绑定 / 未绑定 / 暂无报价（有绑定但该供应商无报价，**仍算已绑定**） |
| 最低报价 | 该 SKU 全部可供应同形态供应商的最低**预报价** |
| 最近采购 | **只到标记**：该档口该 SKU 是否曾有采购（不管订单状态，有下单就算）；最近一次（**近 6 个月内**）的供应商与时间。**不做采购史、不做最近采购价** |
| 可绑定 SKU | 该档口**在售**商品（下架 SKU 不入批量范围） |

### 3.3 页面结构（单层）

页头：标题 `供货关系管理` + 右侧说明 `按档口把商品 SKU 绑定到 1 家供应商；下架商品不清除绑定`。

#### 3.3.1 统计卡 ×4

| 卡片 | 口径 |
| --- | --- |
| 可绑定 SKU 数 | 当前档口商品 SKU 数（**受「包含已下架」影响**：不勾 = 只在售，勾选 = 含下架） |
| 已绑定 | 存在绑定关系且关系上有供应商的 SKU 数 |
| 未绑定 | **完全没有关系记录**的 SKU 数（注意：不含「暂无报价」） |
| 无供应商报价 SKU 数 | 该 SKU 在其可选供应商里**一个报价都没有**的数量（含已绑定但无报价） |

- 4 张卡只跟**档口**与「包含已下架」走，**不受其它筛选影响**；切换「包含已下架」会重算。

#### 3.3.2 筛选条

| 筛选项 | 控件 | 数据源 | 生效方式 |
| --- | --- | --- | --- |
| 关键词 | 输入框 | 无 | 匹配 `商品名称 / SKU 编码 / 商品名`；回车或 `查询` 生效 |
| 商品分类 | 三级弹层（任一层可选，显示所选全路径） | 商品中心分类树 | 选完即写入草稿条件，`查询` 生效 |

| 供应商 | 下拉：全部供应商 + 本商户在合作供应商 | 供应商管理 | `查询` 生效 |
| 包含已下架 | 勾选框 | 商品中心上下架状态 | 勾选即重算（含统计卡） |
| `查询` / `重置` | 按钮 | — | `重置` 清空关键词 / 分类 / 形态 / 绑定状态 / 供应商，并取消「包含已下架」 |

#### 3.3.3 批量操作条

3 个按钮右对齐：`一键选择报价最低供应商` / `按形态批量绑定` / `一键清除供应商`。

| --- | --- | --- |

### 3.4 单个绑定（抽屉）

标题 `选择供应商`，副标题 `{商品名} · 只能选择能供应「{形态}」的供应商`；底部 `取消` / `保存`。

| 区块 | 内容与口径 |
| --- | --- |

| 供应商候选表（5 列） | 单选列 / 供应商（名 + 联系人）/ 供应类型标签 / **该商品报价** / 最近采购标记（最近一次采购过该 SKU 的供应商显示 `最近采购` 标签） |
| 候选过滤 | **只列能供应本 SKU 形态的供应商**（如净菜 SKU 不出现毛菜供应商）；候选池来自供应商管理的在合作供应商 |
| 无报价供应商 | 该 SKU 有报价供应商存在时：**无报价的行单选锁定不可点**，报价列显示 `该供应商无此商品报价` |

### 3.5 批量三动作【规则】

| 动作 | 交互 | 规则 |
| --- | --- | --- |
| `一键选择报价最低供应商` | 二次确认：标题 `一键选择报价最低供应商`、文案 `是否一键选择最低报价供应商，如有商品已绑定供应商，将会做覆盖处理` | 对全部在售 SKU 取最低预报价供应商并覆盖写入；**平局规则**：① 报价相同时优先**最近一次采购过**该 SKU 的供应商 ② 仍相同则取**供应商 ID 较小**者；**幂等**，可重复点击；无任何供应商报价的 SKU 保持「暂无报价」不写入 |
| `按形态批量绑定` | 抽屉：`商品形态`（`*`，一次只处理一个形态，默认取当前筛选形态，否则 `半成品`）+ `供应商`（`*`，只列能供应所选形态的供应商，选项带供应类型）；预览行 `将影响 N 个「{形态}」商品，其中 M 个已绑定其它供应商会被覆盖；绑定到 {供应商}`；底部 `取消` / `确认绑定` | 覆盖该形态**全部在售 SKU**；切换形态时清空已选供应商并重算预览；成功 toast `已把 N 个「{形态}」商品绑定到 {供应商}` |
| `一键清除供应商` | 二次确认：标题 `一键清除供应商`、文案 `是否一键清除所有已绑定的供应商` | 只清**在售 SKU** 的绑定关系，不动下架 SKU；无已绑定时 toast `当前没有已绑定供应商的商品` |

- 二次确认弹层统一：`确认` 才执行，`取消` 不做任何改动。

### 3.6 与上下架的交互【规则】

| 场景 | 行为 |
| --- | --- |
| SKU 下架 | **不清除绑定关系**（保留原供应商），列表默认隐藏该行 |
| 勾选「包含已下架」 | 下架行灰态**只读**展示：显示原绑定 / 最低报价 / 最近采购，「绑定状态」显示 `已下架`，操作列 `只读` |
| 批量三动作 | 作用范围只含在售 SKU，**不修改下架 SKU 的绑定** |
| 下架 SKU 重新上架 | 原绑定仍然有效，直接参与直采下单商品池（前提是该供应商有报价，见 §2.6.1） |
| 统计卡 | 「包含已下架」勾选状态会改变「可绑定 SKU 数」与「已绑定 / 未绑定 / 无报价」的基数 |

## 4. 价格与金额

| 价格类型 | 口径 |
| --- | --- |
| 预报价 | 供应商维护，商户端只读；**直采**下单的单价来源 |
| **定标报价** | 采购计划定标结果；**转单**直接带入订单行，不重取预报价 |
| 下单价 | 下单时快照进订单行，订单生成后不再变化 |
| 结算价 | 后续版本，本期只留字段 |

- 下单金额 = Σ(采购量 × 单价)，**退货不影响、始终等于下单快照**；验收金额 = Σ(累计验收量 × 单价)，**退货经供应商认可后按 `退货量 × 单价` 冲减验收金额**（规则见 §2.9.4a），在途与不认可不冲减。
- **金额精度：2 位小数，小数第 3 位起截断，不四舍五入**（含行总价、小计、合计、统计卡金额）；计算用原始精度，只对最终金额截断（§1.4）。

## 5. 边界与异常【规则】

### 5.1 数据范围与权限边界

| 场景 | 处理 |
| --- | --- |
| 组织下没有档口 | 档口下拉禁用并提示 `该组织暂无档口`；列表空态，不出现新建入口 |
| 切换组织 | 落到新组织第一个档口并刷新；不保留原档口 |
| 越权档口 | 授权外档口**不出现在下拉**；通过 URL / 参数直访 → 提示无权限并回订单列表 |
| 越权单据 | 不属于当前档口的订单、计划、关系数据一律不可见（列表与详情同口径） |
| 切换档口 | 只改数据范围过滤，不改权限、不改单据归属；进行中的向导 / 抽屉需关闭 |
| 无权限动作 | **前端隐藏 + 接口层拦截**双保险；只靠按钮隐藏视为未实现 |

### 5.2 订单状态与锁定边界

| 场景 | 处理 |
| --- | --- |
| 订单发起后 | 状态 `待确认` 时**可删除**（二次确认后物理删除，见 §2.3 / §2.4.5）；`已确认` 及之后**不可撤回、不可删除**，系统无撤回动作 |
| 非「待确认」状态 | 无 `修改订单`、无 `删除` 入口；接口拒绝 |
| 转单来源订单 | **任何状态都不提供 `修改订单`**（含收货信息、商品清单）；待确认态只能删除后重新转单 |
| 订单已 `已完成` | 验收量锁定、批次只读、订单不可改不可删；仅允许发起退货 |
| 两人同时验收同一行 | 以**先提交**的为准；后提交者提示 `该商品已有更新的验收记录，请刷新后重试` |
| 验收完成与验收并发 | 先完成者生效；后提交的验收提示 `订单已完成，验收量已锁定` |
| 售后在途时验收完成 | 不允许（退货入口本就要求已完成，表现为行操作无 `退货`） |
| 页面停留过久 | 提交时以服务端状态为准，状态不符一律拦截并提示刷新 |

### 5.3 数量与金额边界

| 场景 | 处理 |
| --- | --- |
| 精度 | **数量、单价**：2 位小数，四舍五入；**金额**：2 位小数、**小数第 3 位起截断，不四舍五入**（只向下取，不允许进位虚增）；前端只展示、不做二次聚合 |
| 金额截断范围 | 行总价、订单总金额、验收总金额、小计、合计、统计卡金额、当前验收金额**全部适用**；计算用原始精度，仅对最终金额截断 |
| 单价与金额的关系 | 不允许先把单价四舍五入再相乘；单价参与计算时用原值，展示时才取 2 位 |
| 单位 | 一律 SKU 下单单位；**不做克→箱/袋折算**，超发短缺由人工判断 |
| 采购量 | 必须 > 0；空 / 0 拦截 |
| 验收量 | 必须 > 0；**累计可超实际发货量**（超发 / 补送）不拦截，只提示 |
| 累计验收量 < 发货量 | 不拦截保存，但**验收完成时必须逐行填差异原因** |
| 退货量 | > 0 且 ≤ 该行当前累计验收量 |
| 金额展示 | 一行都没验收时验收金额显示 `—`，**不显示 `¥0.00`** |
| 金额公式 | 下单金额 = Σ(下单量 × 单价)；验收金额 = Σ(累计验收量 × 单价) |
| 退货影响 | **仅冲减验收金额**：供应商认可后按 `退货量 × 该行单价` 扣减验收金额（截断口径见 §1.4）并回写该行验收量与 `有退货` 标签；**订单金额与行总价不变**；「待供应商确认」与「不认可」不冲减 |
| 空数据 | 统计卡金额为 0 时正常显示 `¥0.00`（与列表 `—` 口径不同，不要混用） |

### 5.4 编号与幂等边界

| 场景 | 处理 |
| --- | --- |
| 订单编号 | `CG + 送达日期 + 3 位随机数`；同送达日期内重复则**重取**，连续失败给 `订单号生成失败，请重试` |
| 退货单号 | `RT + 提交日期 + 3 位随机数`，同规则 |
| 重复提交下单 | 幂等键 `档口 + 供应商 + 来源单号 + 送达日期`，不重复生单 |
| 重复点 `生成采购订单` | 幂等命中，返回 `该计划已生成订单`，不新增订单 |
| 生单部分失败 | **整体回滚**，不允许部分成功；报错需指出失败原因并允许重试（重试走同一幂等键） |
| 提交按钮连点 | 确认后按钮 loading，禁止重复提交 |

### 5.5 商品与供货关系边界

| 场景 | 处理 |
| --- | --- |
| SKU 下架 | **不清除**供货关系；列表默认隐藏；批量三动作不含下架 SKU |
| 勾选「包含已下架」 | 下架行灰态只读，保留原绑定 |
| 下架后重新上架 | 原绑定仍有效，直接回到直采商品池（前提：该供应商有该 SKU 报价） |
| 未绑定 / 无报价商品 | **不进入**直采商品池；候选为空时给空态 + `去供货关系管理` |
| 「暂无报价」态 | 允许保存关系；该 SKU 在直采池里不可下单，直到供应商有报价 |
| 关系变更（改绑 / 解绑） | **不影响已生成订单**：订单行的供应商与单价是下单时快照 |
| 报价变动 | 不影响已生成订单；新订单取当时报价 |
| 供应商被停用 / 解约（上游变更） | 已绑定关系保留，但该供应商不可再作为新绑定候选，其报价不参与最低价计算【待确认】 |
| 商品在某档口被删除 | 该档口关系记录一并失效，历史订单仍保留快照 |

### 5.6 采购计划转单边界

| 场景 | 处理 |
| --- | --- |
| 计划里某天无需求量 | 不生成该天订单，**不产生「跳过商品」清单** |
| 计划全部无需求量 | 拦截并提示，不生成任何订单 |
| 计划未定标 / 未完成定标 | 不显示 `生成采购订单` 入口 |
| 计划已转单 | 计划只读，不可再编辑、不可重复转单 |
| 供货关系未绑定 / 无报价 | **不判断**（供应商来自定标结果，§2.7.5） |
| 商品已下架 | 允许转单，按计划快照转，不回查上下架【待确认】 |
| 分次转单 | 不支持，一次全转【待确认】 |
| 转单后改单 | 只能改收货信息，商品清单与单价不可改 |
| 新单不在当前筛选范围 | 生成后自动放宽筛选，并提示 `已生成 N 张订单，部分不在当前筛选范围` |

### 5.7 列表与统计一致性边界

| 场景 | 处理 |
| --- | --- |
| 统计卡与列表 | **同源同口径**；统计卡不随筛选 / 页签变化，只跟档口走 |
| 页签计数 | 基数 = 日期 / 来源 / 供应商 / 编号筛选后的集合，不含页签自身与另一组页签条件 |
| 筛选无结果 | 与「一笔单都没有」区分成两种空态文案 |
| 分页 | 原型全量渲染；正式版 20 条/页，翻页保留筛选与页签【待确认】 |
| 数据刷新 | 验收 / 退货 / 转单 / 下单成功后刷新列表与统计卡，不允许前端自行加减数字 |

### 5.8 原型专用内容（正式版必须删除）

| 内容 | 说明 |
| --- | --- |
| 订单详情的「供应商模拟」区 | 确认订单 / 确认发货 / 认可或不认可售后，正式版由供应商端接口驱动 |
| 售后记录区的「模拟售后单」按钮 | 同上 |
