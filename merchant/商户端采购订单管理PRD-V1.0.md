## 1. 概述与范围

### 1.1 背景

商户端已有「排餐计划 → 采购计划 → 询价 → 定标」链路（《商户端采购计划PRD-V3.0》），但**定标之后没有承接单据**：V3.0 的定标只锁定结果、不生成订单，采购员拿不到一张可履约、可验收、可退货的正式单据，供应商侧也没有可确认的凭证。

本期补齐这一环：采购订单成为商户与供应商之间的**正式履约单据**，并把原来只存在于流程图里的「供应商改单 → 下单方确认 → 发货 → 验收 → 退货」闭环落到数据与页面上。

### 1.2 本期目标

| # | 目标 | 判定标准 |
| --- | --- | --- |
| G1 | 三个下单来源全部可生单 | 采购计划定标 / 独立询价定标 / 直采，均能生成待确认订单，且带「需求区间 + 每日需求」 |
| G2 | 变更可协商且全程留痕 | 供应商改单生成变更记录，按开关自动或手动确认；订单可追溯每一条变更与版本 |
| G3 | 验收口径双数量、可反复修改 | 供应商一次性填实际发货量、商户填实际验收量（≤ 发货量）；每次修改留痕 |
| G4 | 验收可收口且可担责 + 退货闭环 | 「验收完成」必须电子签名，完成后订单锁定、验收量不可再改；退货单 → 供应商确认 / 退回 → 明细标记退货 → 订单完成 |
| G5 | 供应商端口径可交付 | 商户 ↔ 供应商 11 条接口（P1–P11）契约清晰，供应商端可据此独立开发 |

## 2. 名词与口径

| 术语 | 定义（与讨论稿 §1.3 一致） |
| --- | --- |
| 采购订单 | 商户对**单一供应商**的一笔采购承诺，一供应商一单；明细按 SKU 下单 |
| 直采 | 已确定供应商、**不经比价**直接下单；同样按「需求区间 + 每日需求」下单，默认单日 |
| 独立询价 | 不挂采购计划：选需求区间 → 逐日填商品与数量 → 总览 → 发起询价 → 供应商按商品报价 → 定标 → 自动生单 |
| 需求区间 / 每日需求 | 本次采购覆盖的起止日期（订单头字段，最长 **31 天**；直采默认单日，计划 / 询价继承来源区间）/ 某条明细行在每个日期上的下单单位数量（2 位小数）；**行数量 = 该行每日数量之和**，合计不可手改 |
| 总览 | 按 SKU 汇总的视图：合计数量 + 每日需求展开 + 规格 / 下单单位 + 单价 / 金额；供核对、比价与定标 |
| 实际发货量 | 供应商「确认发货」时按行填写的数量（**一次性**，可小于订单量）；之后不可改，补送在线下处理 |
| 实际验收量 / 部分验收 | 商户验收时按行填写的数量（**≤ 实际发货量**，默认等于发货量），可反复修改且每次留痕；实际验收量 < 实际发货量 即「部分验收」，线下补送到货后改验收量补上，或直接「验收完成」按差异收口 |
| 验收方式 / 验收完成 | 本次验收的录入方式：`手动验收` / `电子秤验收`，**每条验收记录都必须带方式**，本期只做手动验收 / 收口动作：必须电子签名，完成后订单=已完成、验收量锁定、验收历史只读 |
| 变更记录 | 供应商对已提交订单做出修改后留下的版本记录（含变动明细与确认结果），**不单开单据 / 列表**；订单必须能追溯到每一条变更 |
| 预报价 / 定标价 | 预报价=供应商端维护的「商户 × 商品」报价，商户端**只读**，用于直采带价与参考；定标价=本轮询价中该供应商对该商品的成交报价，定标转单时成为订单单价 |

## 3. 角色与权限

### 3.1 角色与数据范围

| 角色 | 在本模块做什么 |
| --- | --- |
| 采购员（商户端） | 建单（直采 / 发起询价）、定标转单、撤回订单、确认或打回变更、发起退货 |
| 验收员 / 库管（商户端，可与采购员同一人） | 手动验收录 / 改验收量、判断退货、签「验收完成」 |
| 档口负责人 / 商户管理员 | 配置该档口采购设置（变更确认开关）、验收完成 |
| 供应商（供应商端） | 确认订单、修改订单、确认报价、确认发货、确认退货（本期只定口径 + 原型模拟） |
| 系统 | 按开关自动确认变更、定标即生单、状态流转、到点通知 |

| 项 | 口径 |
| --- | --- |
| 数据归属 | 订单、验收单、退货单**挂在档口**；询价单也挂档口（来源为采购计划时继承计划的档口） |
| 配置归属 | 「修改订单需下单方手动确认」开关**配在档口**（下单方自己决定），默认关=自动确认（§9.1） |
| 组织层能力 | 只做**档口卡片总览**，不出现建单入口（与采购计划一致） |
| 权限体系 | 沿用商户端既有「角色 + 按钮权限」体系，下表只作后端配置参考，本模块不另建权限模型 |

### 3.2 权限点【规则】

| 权限点 | 覆盖动作 | 默认角色 |
| --- | --- | --- |
| `purchase.order.view` | 订单总览 / 列表 / 详情 / 变更记录 / 验收与退货记录查看 | 采购员、库管 |
| `purchase.order.create` | 直采下单、定标转单、生单失败后「重新生成」 | 采购员 |
| `purchase.order.cancel` | 撤回订单 | 采购员（可按角色收窄到仅创建人） |
| `purchase.change.confirm` | 同意变更 / 打回重改 | 采购员 |
| `purchase.inquiry.view` | 询价单列表 / 详情 / 比价矩阵 / 报价进度查看 | 采购员 |
| `purchase.inquiry.create` | 独立询价发起询价 | 采购员 |
| `purchase.inquiry.award` | 定标（含一键最低价、确认定标） | 采购员 |
| `purchase.accept` | 验收（手动验收方式；保存 / 修改验收量） | 库管、采购员 |
| `purchase.accept.confirm` | 验收完成 + 电子签名（收口与担责） | 库管负责人、采购员 |
| `purchase.return.create` | 发起退货、修改被退回的退货单 | 采购员、库管 |
| `purchase.setting.edit` | 档口采购设置（变更确认开关，档口级） | 商户管理员、档口负责人 |

- 按钮显隐以权限点为准，**同时**受状态约束（§5.3）；两者取交集。无权限时按钮**不显示**（不置灰）。
- `purchase.accept` 与 `purchase.accept.confirm` 必须可分离授权：能录验收量的人不一定能签「验收完成」。

## 5. 状态模型

### 5.1 采购订单 7 态（主状态，唯一）【规则】

| 状态 | 判定 | 终态 |
| --- | --- | --- |
| 待确认 | 已推送供应商，供应商尚未确认 | 否 |
| 已确认 | 供应商已确认（含分拣备货中） | 否 |
| 待验收 | 供应商已确认发货（已写实际发货量） | 否 |
| 已验收 | 已保存过验收量、尚未点「验收完成」；**验收量可继续修改（每次留痕）** | 否 |
| 退货中 | 退货单已提交、供应商未最终确认 | 否 |
| 已完成 | 已点「验收完成」并完成**电子签名**（含无退货收口，或退货已确认并标记）；**验收量锁定不可再改** | **是** |
| 已取消 | 商户撤回（仅待确认可撤） | **是** |

### 5.2 派生标签（不改主状态，列表与详情页头并列展示）

| 标签 | 判定 | 展示位置 |
| --- | --- | --- |
| `变更待确认` / `变更已自动确认` | 存在 1 条状态=待确认的变更记录 / 最近一条变更记录状态=已自动确认（开关关闭时） | 订单号后、变更记录列表 |
| `有退货` / `部分退货` / `全部退货` | 退货单在途 / 部分行有退货数量 / 全部行退货数量=实际验收量 | 状态列、明细行 |
| `部分发货` / `部分验收` / `已转 N 单` | 实际发货量 < 订单量 / 实际验收量 < 实际发货量 / 来源询价单已生成订单 | 状态列、明细行、询价单 |
| `已签名` / `手动验收` / `电子秤验收` | 验收单上存在电子签名 / 该条验收记录的验收方式（本期只可能出现 `手动验收`） | 验收记录区、变更历史 |
| `来源：计划` / `来源：询价` / `来源：直采` | 来源类型 | 订单号前的来源标签 |

### 5.3 状态 × 动作矩阵【规则】

| 状态 | 撤回 | 确认变更 | 录 / 改验收量 | 验收完成（签名） | 发起退货 | 修改退货单 | 查看变更对比 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 待确认 | 可 | 有待确认变更时 | — | — | — | — | 可 |
| 已确认 | — | 有待确认变更时 | — | — | — | — | 可 |
| 待验收 | — | 有待确认变更时 | 可 | — | — | — | 可 |
| 已验收 | — | — | 可（改） | 可 | 可 | — | 可 |
| 退货中 | — | — | 可（改） | 可 | — | 被退回时可改 | 可 |
| 已完成 | — | — | — | — | — | — | 可 |
| 已取消 | — | — | — | — | — | — | 可 |

- 「确认变更」在**待验收**状态仍允许：发货前改单有意义；发货后（待验收）改单需二次确认提示 `订单已发货，变更只影响对账口径，请确认`。
- **已验收之后不允许再改单**（变更入口消失），但允许继续追加验收 / 验收完成 / 发起退货。
- 「验收完成」只能从**已验收**态发起，前置要求至少 1 条验收记录 + 电子签名；已完成与已取消除查看外无任何动作入口。

### 5.4 状态流转（文字表达，供画图用）

| 段 | 流转 | 触发者 |
| --- | --- | --- |
| 生单 | A 采购计划定标 / B 独立询价定标 / C 直采 → 按供应商拆单 → **待确认** | 系统（A/B 自动）／采购员（C） |
| 协商 | 待确认 → 供应商确认订单 → **已确认**；待确认 / 已确认 / 待验收 → 供应商直接改单 → **生成变更记录（版本 +1）**：开关关=变更立即生效、订单仍为原状态；开关开=变更待确认 → 商户同意 → 生效，商户打回 → 保持上一版本 | 供应商 + 商户 / 系统 |
| 撤回 | 待确认 → 商户撤回 → **已取消**（在途变更作废，快照保留） | 采购员 |
| 发货 / 收口 | 已确认 → 供应商确认发货（一次性填实际发货量 + 约配送） → **待验收**；待验收 / 已验收 → 录或改实际验收量（≤ 实际发货量） → **已验收**（可反复修改，每次一条留痕）；线下补送到货 → 供应商**不重新发货** → 商户回验收抽屉往上改量；已验收 → 「验收完成」+ 电子签名 → **已完成**（终态，验收量锁定） | 供应商 + 验收员 |
| 退货 | 已验收 / 退货中 → 发起退货 → **退货中** → 供应商退回重新发起（改后重发，轮次 +1）／供应商同意 → 明细标记退货 → **已完成** | 采购员 + 供应商 |

### 5.5 验收单与退货单状态

| 单据 | 状态流转 |
| --- | --- |
| 验收单 | 已验收（提交即生效，本期无草稿态）→ 已完成（验收完成 + 签名后锁定） |
| 退货单 | 待供应商确认 → 已确认（终态）／已退回重新发起 →（修改后）待供应商确认 |

## 6. 三个下单来源

> 三个来源**同构**：都带「需求区间 + 每日需求」，行数量 = 区间内每日数量之和；生单时全部冻结为快照。

### 6.1 来源 A：采购计划定标转单

**入口**：采购计划详情 › 询价单 › 定标抽屉 › 点「确认定标」。

| 项 | 口径 |
| --- | --- |
| 触发 | 定标提交成功且**至少 1 个商品成交**；【已确认 D8】定标提交即**自动生单**，无二次「生成订单」步骤 |
| 拆单 | 按供应商分组；同一供应商多商品合成**一张**订单；0 成交不生成任何订单；只成交部分商品时只为成交商品生单，未定标商品视为不采购 |
| 单价来源 | 取**该供应商对该商品的定标报价**（成交价）；该行无人报价则**不下单**（不生成 0 元行） |
| 需求区间 / 每日需求继承 | 直接继承采购计划 / 询价单快照的区间（起始 ~ 结束），无需重填；逐 SKU 继承每日需求，行数量 = 区间合计 |
| 收货信息 | 地址=次级组织地址（可改）、联系人=档口负责人（可改）、电话必填、到货时段默认 07:00–09:00 |
| 结果 | 生成 N 张订单（待确认）并推送供应商；采购计划仍为「已定标」，增加派生标签 `已转 N 单` |
| 失败兜底 | 生单失败时**定标结果保留**（不置流标），提示 `定标结果已保存，订单生成失败，可在「采购管理 › 采购订单」点「重新生成」`；重新生成**幂等**（按来源单号 + 供应商去重） |

### 6.2 来源 B：独立询价下单

**入口**：采购管理 › 采购订单 › 新建 › 「询价下单」。流程与采购计划一致，需求为**手工录入**（不派生排餐、无「同期第 X 份」概念）。七步流程见 §7.3，本节只定生单口径。

| 项 | 口径 |
| --- | --- |
| 触发 | 定标提交成功且至少 1 个商品成交 → **自动生单**，无二次「生成订单」步骤；0 成交则置已流标、不生单 |
| 需求来源 | 采购员所选的需求区间 + 逐日填量（默认明天单日，最长 31 天），生单即为快照 |
| 拆单 | 同 A：档口 + 供应商 + 来源单号；一供应商一张 |
| 单价来源 | 定标报价（成交价） |
| 发起询价 | 报价截止时间默认 `当前 +24h`、最小 `当前 +1h`；受邀供应商默认 = 本商户可下单且合作中的全部供应商，可按供应类型筛 |
| 在途约束 | 同一档口同一时刻只允许 1 条在途询价单；已定标 / 已流标为终态，重来只能新建询价单 |
| 结果 | N 张待确认订单并推送供应商，继承区间与每日需求；询价单标签 `已转 N 单`，可「查看订单」 |
| 失败兜底 | 同 A（定标结果保留 + 重新生成 + 幂等） |

### 6.3 来源 C：直采下单（不询价）

**入口**：采购订单列表 › 「新建采购订单」› 「直采下单」。

| 项 | 口径 |
| --- | --- |
| 触发 | 采购员完成直采向导「收货与提交」并二次确认 → 立即生单，**不询价、不定标** |
| 供应商 / 商品 | 单选；候选 = 本商户绑定且「合作中」的供应商，可按供应类型筛选；商品从商品中心**状态=已发布**的商品 / SKU 中选，可多选，加工形态须落在该供应商的供应类型内（越界阻断） |
| 单价来源 | 默认取该供应商对该 SKU 的**预报价**（自动带出）；无预报价则留空、必填手工输入；均支持手工覆盖 |
| 需求区间 | 【已确认 Q1】支持多日：默认**单日**（起=止=明天），可改为区间（≤31 天）并逐日填量 |
| 数量 / 每日需求 | 逐日填量，行数量=Σ每日；必填、> 0、2 位小数，单位=SKU 下单单位 |
| 拆单 | 只生成**一张**订单（单供应商），来源单号为空 |
| 结果 / 校验 | 生成 1 张订单（待确认）并推送供应商，**跳过询价与定标**；手工覆盖价与预报价不一致时行上标 `改价`，提交前汇总提示 `有 N 行价格与预报价不一致` |
| 失败兜底 / 重复下单 | 提交失败保留已填内容（前端不丢数据），提示重试，按「档口 + 供应商 + 当次提交令牌」防重；同一天对同一供应商多次直采**允许**，生成多张订单、不合并（Q15） |

### 6.4 拆单与订单号【规则】

| 项 | 口径 |
| --- | --- |
| 拆单键 | `档口 + 供应商 + 来源单号`；一个来源单号下同一供应商只生成一张 |
| 订单号 | `PO + yyyyMMdd + 3 位当日流水`（示例 `PO20261023001`），后端生成、全局唯一、前端只展示 |
| 来源单号 | 计划定标：关联采购计划号与询价单号；独立询价：关联询价单号；直采：空 |
| 快照 | 供应商名、商品名 / 形态 / 规格 / 下单单位、单价、区间与每日需求、金额、收货信息全部在下单时冻结；生成即待确认，同事务写入版本号 V1 |
| 幂等 | 重复点击定标 / 下单只成功一次；重新生成按 `来源单号 + 供应商` 去重 |

### 6.5 单价来源优先级【规则】

| 来源类型 | 单价取值 |
| --- | --- |
| 计划定标 | 定标报价（成交价）；该行无人报价 → 不下单，生单后提示 `N 个商品因无成交价未生成订单` |
| 独立询价定标 | 定标报价（成交价） |
| 直采 | 预报价（自动带出，可覆盖）> 手工输入（无预报价时必填） |

> 一句话：**询价路径用「本轮成交价」，直采用「预报价或手填价」**；两者都进订单快照，之后供应商改价不影响已生成的订单。

## 7. 新建订单向导

### 7.1 方式选择（弹窗）

| 卡片 | 文案 | 说明行 |
| --- | --- | --- |
| 直采下单 | `已有确定的供应商，直接按需求下单，不经过比价` | `适合长期合作、价格已谈妥的供应商；默认单日到货，也可改成区间按天填` |
| 询价下单 | `先按天填好需求，向多家供应商询价，收到报价再定标下单` | `适合临时采购、需要比价的情况` |

> 从采购计划 / 询价单定标进入的转单**不走这个弹窗**（§6.1、§6.2）。

### 7.2 直采四步

| 步骤 | 内容 | 关键交互 |
| --- | --- | --- |
| ① 选择供应商 | 供应商卡片列表（名称、供应类型标签、联系人、最近合作日期）；顶部供应类型筛选 + 搜索 | 单选；选中后显示 `该供应商可供应：毛菜 / 净菜` |
| ② 需求区间与逐日填量 | 先选起止日（默认明天单日），再按日期 tab 逐日加商品填量；表格列：商品（+形态）/ SKU 规格 / 下单单位 / `预报价` / `当天数量` / 金额 / 删除 | 右上「添加商品」打开选商品抽屉；单价列可编辑（默认预报价，标 `预报价`；手工改过标 `改价`）；数量为空标红 |
| ③ 总览 | 按 SKU 汇总：合计数量、单价、金额、每日需求展开、区间内 `N 天 / M 项` | 合计只读（由每日自动汇总）；可返回上一步改单天 |
| ④ 收货与提交 | 收货地址、联系人、电话、到货时段、备注、汇总 `N 项 · 合计 ¥X` | 二次确认：`将向「供应商名」下单 N 项，需求区间 MM-DD ~ MM-DD，合计 ¥X，提交后订单进入待确认` |

- 直采**只能一个供应商一张单**；要下给另一家请再建一单。同一 SKU 在同一天不允许重复添加（重复选择时提示并聚焦已有行），跨天可重复出现。

### 7.3 询价下单七步

| 步骤 | 内容 |
| --- | --- |
| ① 需求区间与逐日填量 | 与直采 ② 同一套编辑器（日期 tab + 逐日填量），但不显示可编辑单价列，改显示 `参考价（预报价）` |
| ② 总览 | 每个 SKU 合计数量 + 每日需求展开；底部 `需求区间 MM-DD ~ MM-DD · N 天 · M 个商品` |
| ③ 发起询价 | 报价截止时间（默认 `当前 +24h`，最小 `当前 +1h`）、受邀供应商多选（默认全选本商户可下单供应商）→ 提交 → 生成询价单并跳详情 |
| ④ 报价中 | 供应商看板（待报价 / 已报价 / 超时未报价，已报显示 `已报 K/N 项`）；`剩余 X 小时` |
| ⑤ 比价 | 报价矩阵（行=商品合计数量，列=供应商），最低价绿色高亮，**不排序、不推荐、不算总价**（沿用 V3.0 §6.5.3） |
| ⑥ 定标 | 逐商品选供应商（含 `一键选择价格最低的供应商`）、`已选 X/Y · 预估总价 ¥Z` → `确认定标`（**提交即自动生单**） |
| ⑦ 生单结果 | `已生成 N 张订单`：单号 / 供应商 / 品项 / 金额 / 需求区间 / 状态；`查看订单` / `继续新建` |

- 询价单页签与采购计划共用同一套组件与文案，仅 `来源` 显示 `独立询价`。**0 成交** → 询价单置「已流标」、**不生单**；`重新发起` 需新建询价单。

### 7.4 需求明细编辑（按天）与选商品规则【规则】

| 项 | 口径 |
| --- | --- |
| 日期 tab | 区间内每天一个 tab，`MM-DD 周X`；当天有未填量的行时右上角红点数 = 未填量的行数 |
| 行内容 | 商品（+形态）/ 规格 / 下单单位 / `当天数量`（必填）/ 参考预报价 / 操作（删除） |
| 添加商品 | 每天各自加行；同一 SKU 在同一天不可重复；跨天可以重复出现 |
| 汇总与空天 | 某 SKU 只要在任一日期有量就进「总览」，行数量 = 各天之和；某天未加行 = 当天不采购，区间内可存在空天；全部天为空则不能提交 |
| 与采购计划一致性 | 交互、文案、日期 tab 样式沿用采购计划「采购明细」页签；差异是**没有排餐派生、没有克数、没有按天覆盖概念** |
| 候选池 | 本组织商品中心**状态=已发布**的商品 / SKU；草稿 / 已下架不可选；两步选品：①选商品（名称 / 加工形态 / 分类筛选）→ ②点 SKU 卡片即时生效（无「确定」按钮） |
| 形态校验与单位 | 直采时加工形态必须落在所选供应商的供应类型内，否则该商品标 `不可选` 并提示 `该供应商不供半成品`；询价路径不预审（报价阶段自然过滤）；数量恒为 SKU **下单单位**，系统不换算克数、不展示克数 |
| 已选反馈 | 选中后按钮变 `已添加`，再次点击提示 `该商品已在清单中` |

### 7.5 总览页签

| 元素 | 口径 |
| --- | --- |

| 列 | 商品（+形态）/ 规格 / 下单单位 / **合计数量** / 每日需求 / 单价（直采可编辑；询价显示参考预报价）/ 金额 / 操作 |

### 7.6 提交校验清单【规则】

## 8. 采购订单列表与详情

### 8.1 采购订单总览（组织层）

| 元素 | 内容 |

| 页头 | `采购订单` + 说明 `各档口的下单与履约概况`；无组织切换器（沿用组织上下文） |

## 9. 变更确认

### 9.1 手动 / 自动确认开关（档口级 + 下单快照）【规则】

| 项 | 口径 |
| --- | --- |
| 语义 | `修改订单后需下单方手动确认`：**开 = 需手动确认；关 = 自动确认生效** |
| 默认值 | **关**（前期默认自动确认，【已确认 D6】） |
| 配置位置 | 档口级：基础信息 › 档口管理 › 编辑档口 › **采购设置** 区块里的开关；后端以档口维度配置表实现，不写死 |
| 生效范围 | **下单时快照到订单**（`manual_confirm` 字段）：开关变化只影响之后创建的订单，已生成订单沿用下单时的模式 |
| 影响（关） | 供应商提交修改 → 变更记录=`已自动确认`、订单版本 +1、明细立即更新、通知商户 |
| 影响（开） | 变更记录=`待确认`、明细保持旧版本、等下单方确认；同意后生效（版本 +1）；打回则保持上一版本 |
| 通知 / 演示 | 两种模式都发站内消息（`供应商修改了你的订单`），落在订单 / 待办；原型提供「演示开关」验证两种模式，正式版删除（§14） |

### 9.2 变更记录与版本【规则】

| 项 | 口径 |
| --- | --- |
| 单据形态 | **订单的版本记录**，不单开列表、不进菜单；订单详情以「变更记录」区块展示 |
| 版本号 | 订单创建为 V1；每**生效**一次变更 +1（被驳回不占版本号） |
| 状态 | `待确认` / `已自动确认` / `已同意` / `已打回` / `已作废` |
| 关联快照 | 记录变更前后的**整单快照**（明细行 + 每日需求 + 需求区间 + 金额 + 到货时段 + 备注），可逐行与逐天对比 |
| 留痕 | 订单明细行上标 `已变更`；详情页展示完整变更链（谁、何时、改了什么、确认方式、确认人） |
| 在途唯一 | 同一订单同一时刻只允许 **1 条**待确认变更；已有一条待确认时供应商不能再发起（提示先去处理） |
| 作废 | 订单撤回 / 已验收时若有待确认变更，自动置「已作废」 |
| 并发 | 变更提交按 `version_no` 乐观锁；后提交者提示 `订单已被修改，请刷新后重试` |
| 详情区块列 | 版本 / 时间 / 发起方（供应商标识 + 操作人）/ 变动摘要（`2 行改数量、1 行改价、删除 1 行、新增 1 行；金额 +¥120.00`）/ 确认方式（`自动确认`、`手动确认（采购员 张三）`、`已打回（原因…）`）/ 操作（`查看对比`，待确认且有权时 `同意`、`打回重改`） |

### 9.3 打回重改与轮次【规则】

| 项 | 口径 |
| --- | --- |
| 原因 | 必填，最长 200 字；4 个快捷标签（`价格不接受` / `数量不对` / `商品不对` / `到货时间不行`）+ 自由文本 |
| 结果 | 变更记录=`已打回`（含原因），订单保持上一版本，供应商收到通知 |
| 轮次 | 同一订单累计打回 **3 轮**；第 4 次提交时供应商端提示 `该订单变更已打回 3 次，请与采购员线下确认或由采购员撤回订单`，商户端不再收到第 4 次 |
| 再发起 / 商户侧提示 | 供应商可新建一条变更记录，被驳回记录保留可查；商户侧列表 / 详情提示 `该订单变更已打回 3 次，如需终止请撤回订单` |

### 9.4 变更对比展示【原型】

| 区块 | 内容 |
| --- | --- |
| 头部 | `订单变更` + 副标题 `订单号 · V1 → V2`；右侧 `变更原因`（供应商填写，只读） |
| 差异表 | 行级三态：`新增`（绿色）/ `删除`（红色删除线）/ `修改`（列内 `原值 → 新值`，标红旧值、标绿新值）；列 = 商品 / 规格 / 单位 / 数量 / 单价 / 金额；每日需求变化行内展开 |
| 金额条 | `变更前 ¥X → 变更后 ¥Y（+¥Z）`，涨价 / 降价用色 |
| 尾部 | `打回重改`（危险按钮）+ `同意变更`（主按钮）；**仅手动确认模式下出现** |

### 9.5 变更的边界

- 允许改：每日数量、在区间内增删日期、单价、SKU（换商品）、新增行、删除行、需求区间、到货时段、备注。
- 不允许改：供应商、档口、收货地址 / 联系人（如需改，走撤回重下）；变更不改订单来源、来源单号与订单号，订单号不变、版本号递增。
- 变更只能在 `待确认 / 已确认 / 待验收` 状态发起；`已验收` 之后只能走退货。

## 10. 验收

### 10.1 双数量口径与入口【规则】

| 项 | 口径 |
| --- | --- |
| 实际发货量 | 供应商「确认发货」时**一次性**按行填写（可小于订单量），之后不再改；补送为线下行为，系统**不记录**补送发货 |
| 实际验收量 | 商户按行填写，**≥ 0 且 ≤ 实际发货量**，2 位小数；默认 = 实际发货量 |
| 入口 | 列表行 `验收` / 详情页 `验收`；状态 = 待验收 或 已验收（未完结）时可用 |
| 签收聚合 | **不做**按供应商 / 按天的聚合批次；同一供应商同一天的多张订单各自逐单验收（【已确认 D11】） |
| 部分验收 | 实际验收量 < 实际发货量 即部分验收；可改验收量补上，或直接「验收完成」按差异收口 |
| 权限 | 有 `purchase.accept` 可保存验收量；有 `purchase.accept.confirm` 才能「验收完成」 |

### 10.2 验收方式（手动 / 电子秤）【规则】

| 项 | 口径 |
| --- | --- |
| 本期可用 | **手动验收**（即流程图里的「平台验收」，在平台内人工录入） |
| 预留 | **电子秤验收**：选项置灰 + 标签 `预留`，提示 `电子秤验收需对接设备，本期暂未开放`；选中不生效，记录里不会出现该方式 |
| 方式留痕 | 抽屉顶部一个「验收方式」单选（默认 `手动验收`）；**每条验收量变更记录与验收完成记录都固化保存当时的方式**，详情页与变更历史展示 |
| 后续 | 移动端 / 电子秤端接入同一套验收与签名组件（字段与接口先留好） |

### 10.3 明细录入

| 列 | 口径 |
| --- | --- |
| 订单量 / 实际发货量 | 当前生效版本数量（只读，可展开看每日需求）/ 供应商确认发货时填写的数量（只读，一次性固定，可小于订单量） |
| 实际验收量 | 可编辑、≥ 0、2 位小数；默认 = 实际发货量；**≤ 实际发货量**，超出阻断 |
| 差异 | `未发 = 订单量 − 实际发货量`、`未收 = 实际发货量 − 实际验收量`，均高亮 |
| 差异原因 / 退货意向 | 存在未收（少收）时必填；多选：`数量短缺` / `质量问题` / `规格不符` / `临期` / `其他（文本）`；有差异 / 质量问题时勾选 `该行需退`，仅作退货单预填，不改变订单状态 |

- 底部汇总：`订单 N 项 · 已录验收量 X 项 · 差异 M 行`；两个按钮：`保存验收量`（留痕）与 `验收完成`（收口）。
- 明细上方显示验收变更次数与最近一次修改：`已修改 3 次 · 最近 10-23 15:20 张三`，可点开「变更历史」。

### 10.4 保存与修改验收量【规则】

| 项 | 口径 |
| --- | --- |
| 保存 / 无变化 | 点 `保存验收量`：与上次值比较，**有变化就生成一条变更记录**（逐行 `改前 → 改后`、操作人、时间、验收方式、可选修改说明）；无变化则提示 `验收量没有变化`，不生成记录 |
| 修改次数 / 修改说明 | 验收完成前**不限制次数**（Q8），订单与明细显示 `已修改 N 次`；修改说明选填（Q7），有差异时**差异原因必填** |
| 变更历史 | 详情「验收记录」区块按时间倒序：时间、操作人、**验收方式**、行级 `改前 → 改后`、合计变化；可展开逐行查看 |
| 补送 | 线下补送到货后直接回验收抽屉把该行验收量往上改（≤ 实际发货量），同样留痕；**不需要**供应商重新发货 |
| 不可改 | 订单已完成（验收完成 + 签名）后，验收量与变更历史全部只读 |

### 10.5 验收完成 + 电子签名【规则】

| 项 | 口径 |
| --- | --- |
| 入口 | 验收抽屉内 `验收完成`；仅状态 = 已验收 时可用 |
| 前置校验 | ①至少保存过 1 次验收量；②所有存在未收差异的行都已填差异原因；③否则按钮置灰并说明原因 |
| 电子签名 | 点击弹出签名弹窗：PC 端手写板（鼠标 / 触摸绘制）；确认后生成签名图，记录签名人、签名时间、**验收方式** |
| 二次确认 | `验收完成后本订单将锁定：实际验收量不可再修改，是否继续？` → `再检查` / `继续签名` |
| 结果 | 订单 = 已完成（终态）；验收量、变更历史、签名全部只读；**不再允许改验收量** |
| 差异收口 / 全部为 0 | 未发 / 未收有差异时**允许**完成验收（按差异收口），收口后不再受理线下补送，仍须补货则另建订单（本期不做补货单）；全部行验收量为 0 时**允许保存**（记录未到货）但**不允许「验收完成」**，须补送到货后改量或按差异收口 |
| 不做 | 超时未完成验收不自动完结，停在已验收（Q4）；按供应商聚合签收、补送记录、电子秤对接、验收单打印、移动端与电子秤端签名本期不做（§18） |

## 11. 退货

### 11.1 发起

| 项 | 口径 |
| --- | --- |
| 入口 / 可退行 | 已验收订单详情 `发起退货`；验收提交后的引导；可退行 = 实际验收量 > 0 的行（含无差异行，用于质量问题） |
| 可退数量 | ≤ 该行实际验收量 − 已退货数量；2 位小数 |
| 单据 | 一张订单可有多张退货单，但**同一行同一时刻只能有一张在途退货**（Q11） |
| 原因 / 凭证 / 备注 | 原因必选：`质量问题` / `数量短缺` / `规格不符` / `临期` / `其他（文本）`；凭证为图片上传（可选，原型用占位，本期不强制）；备注选填，给供应商的说明 |
| 提交 | 生成退货单（`待供应商确认`），订单 → 退货中，通知供应商 |

### 11.2 供应商确认（本期为口径 + 原型模拟）

| 供应商动作 | 结果 |
| --- | --- |
| 同意 | 退货单 = 已确认；双方订单明细标记退货数量与 `已退货` / `部分退货`；订单 → **已完成** |
| 不同意（退回重新发起） | 必须填原因；退货单 = `已退回重新发起`；商户可修改数量 / 原因后再次提交（轮次 +1，**不设上限**）；订单保持退货中 |
| 超时未处理 | 本期**不自动处理**（Q13），订单停在退货中 |

### 11.3 金额与完结

- 本期**订单金额不因退货冲减**（Q12），退货数量单列展示；结算冲减留给结算模块。
- 全部行退货数量 = 实际验收量 → 标 `全部退货`；部分行小于验收量 → `部分退货`。
- 退货单确认后订单 = 已完成；已完成订单不可再发起退货。整单拒收（验收全部为 0）视为全单退货：必须发起退货单，订单进退货中。

## 12. 价格与金额口径【规则】

| 项 | 口径 |
| --- | --- |
| 精度 / 金额 | 数量、单价、金额均 2 位小数（四舍五入）；行金额 = 数量 × 单价，订单金额 = Σ 行金额（当前生效版本） |
| 数量口径 | 行数量 = 需求区间内每日数量之和（只填每天，合计由系统汇总，**不能手改合计**） |
| 报价口径 | 供应商报价 = 元 / 下单单位；比价与定标都按这一个单价，**不按天分别报价**、不做单位换算 |
| 价格快照 / 成交价缺省 | 下单时冻结，之后供应商预报价变化不影响已生成订单；定标时该商品无任何报价 → 不下单（不生成 0 元行） |
| 改价留痕 | 直采手工改价：行标 `改价`；变更改价：记入变更记录 |
| 变更与金额 | 变更生效后按最新每日需求重算行合计与订单金额，变更记录保存前后金额 |
| 订单金额 vs 验收金额 | 订单金额按**订单量**算；`实收金额`按**实际验收量**算；少发 / 少收**不冲减**订单金额 |
| 验收量修改 / 退货 | 每次修改独立留痕（不覆盖历史），记录改前 / 改后与操作人，「验收完成」时整单锁定；退货本期不冲减金额，退货数量单列 |

## 17. 边界与异常【规则】

| 场景 | 期望行为 |
| --- | --- |
| 定标转单时某商品无成交价 / 定标 0 成交 | 该商品不生成明细行，生单后提示 `N 个商品因无成交价未生成订单`；0 成交则完全不生单，询价单 → 已流标（沿用 V3.0） |
| 生单过程中部分失败 / 重复提交 | 已生成订单保留，失败部分可「重新生成」（幂等，按来源单号 + 供应商去重）；重复点击下单 / 定标只成功一次 |
| 供应商并发改单 / 手动确认模式下又被改 | 按 `version_no` 乐观锁，后提交者提示 `订单已被修改，请刷新后重试`；已有待确认变更时供应商无法再提交（提示先处理） |
| 变更待确认时商户点撤回 | 变更自动作废（`void`），订单 → 已取消 |
| 已发货后改单 / 已验收后改单 | 待验收态允许改单但需二次确认提示、仅影响对账口径；已验收后不允许（入口消失，但可追加验收 / 验收完成 / 退货） |
| 部分发货 / 部分验收 | 允许，分别标 `部分发货` / `部分验收`；剩余与补送均线下处理，补送到货后改验收量补上或按差异收口 |
| 验收量修改 / 超发货量 | 验收完成前可反复修改，每次保存生成一条变更记录；验收量 > 实际发货量阻断：`实际验收量不能大于实际发货量（X）` |
| 已完成后再验收 / 改量 | 只读，入口隐藏（验收量锁定） |
| 选择电子秤验收 | 入口置灰：`电子秤验收需对接设备，本期暂未开放`；记录里不会出现该方式 |
| 已验收长期未完成 / 验收时商品已被下架 | 不自动完结，停在已验收（Q4）；商品已下架时明细照常展示（快照），可正常验收 |
| 供应商解除合作 / 商品下架（下单后） / 档口被删除 | 在途订单不受影响（全部为快照），新建下单时该供应商 / 商品不再出现；存在未完结订单（非已完成 / 已取消）时**禁止删除档口**（与采购计划口径一致） |
| 全部验收量为 0 | 允许保存（记录未到货），但**不允许「验收完成」**；须改用退货单（视为全单退货）或补送后改量 |
| 退货单被退回 3 次以上 / 订单金额 vs 退货 | 不设上限但记录轮次，详情可看历史；本期不冲减订单金额，退货数量单列 |
| 组织层查看 / 需求区间超上限 / 某天没有任何商品 | 组织层只有档口卡片总览，点进才看订单列表；超 31 天阻断 `需求区间最长 31 天，请缩小范围`；某天无行则该天不出现在每日需求里，全部天为空不能提交 |

## 18. 本期不做

1. 供应商端界面（订单确认、改单、发货、退货确认只定接口口径 + 原型模拟）。
2. 电子秤硬件对接与自动称重回填（验收签名本期只做 PC 手写板，移动端 / 电子秤端预留）。
3. 订单审批流、大额审批、下单额度校验。
4. 多档口合并下单、跨档口比价、跨订单合并支付。
5. 按供应商 / 按天聚合的到货批次签收（本期严格逐单验收）；分批退货；补货单；补送的发货记录（线下处理）。
6. 换货单、发票、对账结算与金额冲减。
7. 订单批量操作、列表导出、打印模板（拣货单 / 送货单）。
8. 询价撤回、截止时间延长、超时补报、催报价、自动定标与推荐。
9. 采购计划侧「部分转单」入口（定标即全量成交商品转单）。
10. 直采同一供应商同日多单自动合并。

## 21. 验收用例

> 来自讨论稿 §20.1（AC01–AC29 全保留，仅合并同源分支）；用于原型自测与研发联调，每条都可独立复现。

| # | 场景 | 预期 |
| --- | --- | --- |
| AC01 | 采购计划定标 3 个商品，分属 2 家供应商 | 生成 2 张订单，明细归属正确，来源单号一致 |
| AC02 | 定标 0 成交 | 不生单，询价单 = 已流标，采购订单列表无新单 |
| AC03 / AC04 | 直采选 1 家供应商 2 个商品 / 直采选半成品但供应商只供净菜 | 前者：1 张订单，单价默认预报价，可改价并标 `改价`；后者：该商品不可选并有提示 |
| AC05 | 独立询价：3 天区间、每天不同商品与数量 → 2 家报价 → 定标 2 家 | 总览合计 = 各天之和；生成 2 张订单且都带 3 天每日需求；询价单显示 `已转 2 单` |
| AC06 | 供应商在开关**关闭**时改单 | 变更记录 = 已自动确认，订单 V2，明细立即更新 |
| AC07 / AC08 | 开关**打开**时改单 / 手动确认模式打回 | 改单后订单进 `变更待确认`、明细仍为 V1，同意后 V2；打回则变更 = 已打回、订单仍 V1，供应商可再提交 |
| AC09 | 待确认订单点撤回 | 状态 = 已取消，在途变更作废，可从询价单重新生成 |
| AC10 – AC12 | 待验收订单验收，2 行有差异 → 发起退货 → 供应商同意 / 退回 | 验收后订单 = 已验收；发起后退货中；同意 → 明细标记退货数量与 `部分退货`、订单 = 已完成；退回 → 退货单 = 已退回重新发起，可改后重发 |
| AC13 / AC14 | 组织层进入总览 / 列表筛选「待我处理」 | 前者只见档口卡片、无新建入口、卡片数字与档口列表一致；后者只剩 `变更待确认` + `待验收` 订单 |
| AC15 – AC17 | 直采不选区间直接提交 / 需求区间填 40 天 / 某天某行数量留空 | 默认单日区间，订单需求区间 = 该单日，可切多日按天填量；40 天阻断 `需求区间最长 31 天，请缩小范围`；数量留空阻断并指出 `MM-DD「商品名」` |
| AC18 / AC19 | 供应商只报 3 个商品中的 2 个 / 档口开关打开后新建订单 | 询价单显示 `已报 2/3 项`、比价矩阵仅这 2 个商品有可选供应商；新订单 `manual_confirm=true` 走手动确认，历史订单仍按创建时的自动确认 |
| AC20 | 变更里把某天数量从 3 改成 2 | 变更记录显示每日差异与金额变化；订单合计相应减少 |
| AC21 | 订 10 箱，供应商实发 7 箱 → 商户验收 7 箱 | 订单标 `部分发货` + `部分验收`；验收量 7 ≤ 发货量 7；线下补送 3 箱后把验收量改成 10，生成第二条变更记录，可「验收完成」 |
| AC22 | 订 10 箱实发 10 箱，验收填 12 箱 | 阻断：`实际验收量不能大于实际发货量（10）` |
| AC23 | 点「验收完成」但不签名 | 阻断并提示 `请先完成电子签名`；签名确认后可完成 |
| AC24 / AC25 | 已完成订单再看详情 / 同一供应商同一天有定标单 + 直采单各一张 | 前者验收量与变更历史只读、无改量 / 追加入口；后者两张订单各自验收、互不影响（不做合并签收） |
| AC26 | 同一天连续两次修改验收量（7 → 8 → 10） | 详情「验收记录」出现两条变更记录，各自显示改前 → 改后、操作人、时间 |
| AC27 | 保存验收量但数值未变 | 提示 `验收量没有变化`，不产生变更记录 |
| AC28 | 手动录一次验收量并保存 | 验收记录行显示 `手动验收`；订单详情的变更历史同样显示方式 |
| AC29 | 尝试选择「电子秤验收」 | 选项置灰不可选，提示 `电子秤验收需对接设备，本期暂未开放`；不会产生该方式的记录 |
