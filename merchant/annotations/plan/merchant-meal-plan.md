# 商户端 · 排餐计划业务标注

> 事实来源：《商户端排餐计划 PRD》（`商户端排餐计划PRD.md`，PC 端口径，原型为排餐计划 V3）。
> 本文只写原型看不出来、但实现或验收需要知道的规则。标「原型差异」的条目是 PRD 口径与原型现状不一致，**不要以原型为准**；标「待确认」的条目 PRD 未定，不要按惯例补齐。

<!-- anno:start id=meal-plan-overview-rules -->
## 本页规则

### 页面定位

- 入口：左侧一级「计划管理」→ 二级「排餐计划」；面包屑「计划管理 / 排餐计划」。
- 排餐计划是**全链路唯一的人工录入口**：生产计划与采购计划都只按**已保存**的排餐派生，未保存的改动下游不可见。
- 排餐以**档口**为单位：计划只挂在档口上，组织层不是一份计划，而是各档口的入口。

### 数据范围与默认状态

- 两级范围：次级组织 → 档口；数据范围以左上角切换器为准。
- 进入本页默认停在「全部档口（总览）」；点卡片或切换器才进入具体档口，用户选过之后**不被默认值拉回总览**。
- 组织下没有档口时显示「暂无档口，请先创建档口」，此时无法排餐。

### 只读与可编辑

- **历史周**（周起始早于本周）整周只读，「编辑」置灰。
- **过去日期**（早于今天）该列只读；只有**今天及未来**可编辑。
- 有未保存修改时切换范围（组织 / 档口）会被拦下，先要求「保存后切换」或「取消切换」。

## 本页规则

### 页面结构

- 周工具条 → 周状态文案 → 计算口径行 → 统计口径行（有排除分类时）→ 周排餐表。
- 表格：**行 = 餐次**（取该档口经营餐次，随档口收敛）、**列 = 排餐日期**（默认周一至周五）。
- 表头在页面下滚、表头滚出视野时浮在窗口顶部；横向滚动时「餐次」列吸左。

### 编辑与生效

- 点「编辑」进入编辑态；「取消」会二次确认「取消后将放弃本次所有修改」。
- 「保存」只在有改动时执行校验：校验不通过 → 提示首个错误、不提交、不退出编辑。
- 保存成功提示「排餐计划已保存并立即生效」，并记录「最近更新」时间。
- 「沿用」角标只在首次建立该格时出现；**保存后即为确定值**，再进编辑不再提示。

### 日期管理

- 删除当天：仅编辑态、非历史周、且日期**晚于今天**；当天已排菜时二次确认。
- **每周至少保留 1 个排餐日期**：移除最后一个时被拦下，提示「如当天不排餐，可将各餐次菜谱留空」。
- 被移除的日期在表上方以「＋ 恢复周X」呈现。

### 跨周

- 计划按**周**分别存储，跨周（周日排下周、周一再看本周）不会丢改动。
- 周状态文案四种：历史周 · 仅支持查看 / 有未保存修改 / 已保存 · 最近更新：时间 / 暂未排餐。

## 范围与编辑模式

- 范围切换器与生产计划共用同一个组织 / 档口选择。
- **编辑模式下切换器整体 disabled**，旁边给锁提示「编辑中，保存或取消后可切换」——这是原型当前的主要防丢改动手段。
- 右侧按钮随模式切换：「编辑」→「取消」+「保存」。
- PRD 另有一条「切换范围拦截」规则（有未保存修改时弹抽屉，可选「取消切换」/「保存后切换」），原型里与上面的「编辑态锁定」**重叠实现**，见下方差异说明。

## 周工具条与复制排餐

| 控件 | 规则 |
| --- | --- |
| 上一周 / 下一周 | 按自然周（周一为起始）前后翻 |

- 来源周没有已保存排餐时提示「所选来源周暂无已保存的排餐」；复制后仍需点「保存」才生效。

## 计算口径

本节固定的三个式子就是本页全部算法口径：

- 投料用量总量 = 一锅基准投料 Q × 锅数
- 出餐成品总量 = 投料用量总量 × 出餐成品系数（系数**只读跟随菜谱**，V3 起不逐格手改）
- 预计就餐人数 = 该餐次成品合计 ÷ 人均用餐量

关于输入方向：

- **锅数与人均用餐量是输入，人数是派生结果**，不存在「先定人数再反推用量」的路径。
- 一锅基准投料 Q 取菜谱「用料明细」中**可折算为质量**的投料量合计；纯人工菜与含设备菜同一口径，都按一锅配置。
- 质量折算：g / kg、ml / L 按 1 g = 1 ml 折成克；个 / 只 / 条 / 份 / 适量**不折算**，不进合计，但仍按锅数放大。
- 精度：出品量、投料用量总量 2 位小数；格子内出餐合计 1 位小数；人均用餐量为整数 g/人。

## 统计口径（分类开关）

- 开关在「菜谱管理 → 菜谱分类」页维护，按二级分类逐项设置，**商户级一份**；未设置过 = 全部分类都计入。
- 本行只在**有分类被关闭**或**历史日期定格过分类**时出现；点「去设置」跳到菜谱分类页。
- 影响面**仅限「预计满足 N 人就餐」**：出餐合计、荤素统计、锅数、生产计划都不受影响。
- 历史定格：开关只影响今天及未来；保存时把当时的开关状态记到各日期上，日期进入历史后按当时口径计算，之后改开关**不回溯**。
- 未记录过的日期（种子数据、开启本功能之前保存的计划）按「全部分类都计入」处理。

## 餐次行

- 行 = 该档口的**经营餐次**；档口只经营早餐，就不会出现午餐 / 晚餐行。
- 行头显示餐次名与开餐时间，开餐时间为固定字典：早餐 06:30、早点 09:30、午餐 11:30、午点 15:00、晚餐 17:30、夜宵 21:00。
- 档口经营餐次被改后，行按**当前**档口配置收敛；已经排过、但不在经营餐次内的菜不再展示（存量数据保留，不做自动清理）【待确认】。
<!-- anno:end id=meal-plan-week-mealhead -->

<!-- anno:start id=meal-plan-week-permeal -->
## 人均用餐量

- 输入约束：1–9999 的整数（g/人）；只读态显示值，未填时显示「未填人均用餐量」。
- 取数优先级（只为**新建该格**时取一次默认值）：

| 优先级 | 来源 | 界面表现 |
| --- | --- | --- |
| 1 | 档口管理里该档口该餐次的「预计人均用餐量」 | 直接引用 |
| 2 | 沿用上周**同星期几 + 同餐次**的值 | 显示「沿用周X 餐次」角标 |
| 3 | 内置演示默认值（早餐 300 / 早点 200 / 午餐 500 / 午点 250 / 晚餐 450 / 夜宵 300） | 不打角标 |

- **手工优先**：用户在格子里改过 → 沿用角标立即消失，以手工值为准。
- 排餐侧改动**不回写**档口配置；档口侧配置变更也只影响之后新建立的格子。
- 有菜的格子**必须**填人均用餐量，否则保存被拦下，提示「周X 餐次 请填写人均用餐量」。
- 原型说明：来源标记（`src=stall`）已记录但界面不展示，因此口径 1 与口径 3 在页面上无法区分【原型】。
<!-- anno:end id=meal-plan-week-permeal -->

<!-- anno:start id=meal-plan-week-feed -->
## 预计满足 N 人就餐

- 紧贴人均用餐量输入，编辑时**边输边算**（只改文案，不重画表格，避免丢光标）。
- 三种状态，不要混用：
  1. 未填人均用餐量 → 「待填人均用餐量」
  2. 本餐次菜品全被排除 → 「本餐次菜品不计入就餐人数统计」（**不是 0 人**）
  3. 正常 → 「预计满足 N 人就餐」
- 取值口径：该餐次**计入统计**的分类的出餐成品合计 ÷ 人均用餐量，**向下取整**。
- 分类被排除的菜改锅数，只影响出餐量与生产，不改变这里的 N。
<!-- anno:end id=meal-plan-week-feed -->

<!-- anno:start id=meal-plan-week-dish -->
## 菜品格

- 展示：菜名、二级分类标签、「N 锅 · 出餐 X kg」；编辑态右上角 × 删除。
- 点菜格（× 除外）打开菜品详情抽屉；只读模式下同样可点开看口径与用料。
- **分类聚合排序**（口径唯一）：格子里的菜按固定顺序聚在一起 —— 大荤 → 小荤 → 半荤半素 → 素菜 → 汤类 → 粥类 → 面食 → 点心 → 水果 → 其它二级分类（首次出现顺序）→ 未分类；组内保持原有先后。
  - 加菜 / 换菜、打开页面（切周 / 切范围）、复制排餐都走同一处聚合。
- 锅数是**唯一必填的用量驱动项**（1–99）；缺省时按 1 锅兜底。
- 删除行为分叉：**当天**删除要走「今日排餐调整」必填原因；非当天只做二次确认，不记原因、不产生记录。
<!-- anno:end id=meal-plan-week-dish -->

<!-- anno:start id=meal-plan-week-summary -->
## 出餐合计与分类统计

- 出餐合计 = 该餐次各菜出餐成品总量之和（**物理口径，含全部菜**，不受分类开关影响），1 位小数。
- 分类统计 = 本餐次菜谱的荤素结构：荤 = 大荤 / 小荤 / 半荤半素，素 = 素菜，其余（汤类 / 粥类 / 面食 / 点心 / 水果…）按二级分类单列；荤素排最前。
- 两项都跟着格子里的菜实时变化；无菜时分类统计位置显示「未排餐」。
<!-- anno:end id=meal-plan-week-summary -->

<!-- anno:start id=meal-plan-week-add -->
## 添加菜谱

- 打开两段式抽屉：第 1 步选菜谱 → 第 2 步填写锅数；锅数在加菜时就要定下来，避免回格子逐个改。
- 抽屉里确认后**仍需点页面上的「保存」才生效**（toast 会提示「保存后生效」）。
- 本餐次已添加的菜在选择列表里置灰「已添加」，不可重复选择。

## 本页规则

- 只读态条件（任一成立即只读）：非编辑模式 / 历史周 / 过去日期 → 没有输入框，也没有「确定 / 删除 / 替换」。
- 抽屉里唯一的输入是**烹饪锅数**（1–99）；改锅数后投料用量总量、出餐成品总量、公式行、用料明细与提示全部实时重算，失焦收敛为整数。
- 「确定」只写入编辑缓冲，提示「已更新，保存后生效」——**页面上不点保存就不落库**。
- 「替换菜谱」与「删除此菜」都会关闭本抽屉：替换进入选择器（默认沿用被替换那道菜的锅数），删除在当天需填原因。
<!-- anno:end id=meal-plan-detail-rules -->

<!-- anno:start id=meal-plan-detail-grid -->
## 字段与数据源

| 字段 | 数据源 | 维护方 |
| --- | --- | --- |
| 菜谱分类 | 菜谱库 → 菜谱「基础信息 · 菜谱分类」 | 分类字典由**租户统一维护、商户只读**；挂到菜谱由商户建 / 编辑菜谱时选择 |
| 出餐成品系数 | 菜谱库 → 菜谱「基础信息 · 出餐成品系数」 | 商户维护，随菜谱版本走 |
| 烹饪锅数 | **本页输入**（排餐计划自己的数据） | 排餐员 |

- 菜谱分类与出餐成品系数在本页**只读**，标注「跟随菜谱」；出餐成品系数自 V3 起不再逐格手改，避免同一道菜在不同格子口径不一。
- 排餐侧只落库三项：**菜谱 ID、锅数、人均用餐量**；分类、出餐成品系数、用料明细都是**实时读菜谱主数据，不落快照**。
- 因此改菜谱会**全量生效**到所有引用该菜谱的排餐格子，不需要重新排餐【待确认：是否需要「菜谱已变更」的影响面提示】。

<!-- anno:start id=meal-plan-detail-basis -->
## 一锅口径与适用设备

- 头部标签区分「含设备加工」/「纯人工」：生产计划只收含设备加工的菜，纯人工菜不进生产计划（但仍进后续采购计划）。
- 用料明细按**「一锅」**配置：一锅基准投料 Q = 菜谱用料明细中可折成质量的行之和。
- 适用设备取菜谱「加工步骤」里出现过的设备（去重）；纯人工菜没有设备。
- 一锅装不下时给警示：「一锅 {X}kg 超过最小设备额定容量 {Y}kg，现场需拆成多锅处理」——**只提示不拦截**，口径仍是「一锅 = 菜谱一锅量」。
- 整条用量链路与设备无关：设备只决定这道菜上什么机器。
<!-- anno:end id=meal-plan-detail-basis -->

<!-- anno:start id=meal-plan-detail-derive -->
## 派生行

- 投料用量总量 = 一锅基准投料 × 锅数
- 出餐成品总量 = 投料用量总量 × 出餐成品系数
- 两行都是只读派生值，随锅数实时重算；精度 2 位小数。
- 该菜若属被排除的二级分类，抽屉里会额外说明「改锅数只影响出餐量与生产，不改变这一格的『预计满足 N 人就餐』」。
<!-- anno:end id=meal-plan-detail-derive -->

<!-- anno:start id=meal-plan-detail-bom -->
## 用料用量明细

| 列 | 口径 |
| --- | --- |
| 用料 | 标准食材名（来自菜谱「用料明细」页签） |
| 一锅投料 | **保持菜谱配置的原单位**原样展示（如 9000 g、300 ml），不做单位进位 |
| 占比 | 该行投料量 ÷ 一锅基准投料 Q |
| 本次用量 | 该行投料量 × 锅数，**整列统一双单位** `{克数}g（{千克数}kg）` |

- 「本次用量」不再按 1000 g 分档：不允许「9 kg」与「300 g」两种写法在同一列混排；克数与千克都最多 2 位小数且去尾零（`9000g（9kg）`、`300g（0.3kg）`）。
- 计数单位行（个 / 只 / 条 / 份 / 适量）没有质量口径：保持原单位显示，**不加 kg 括号**，也不计入一锅投料合计，但仍按锅数放大。
- 表底合计「一锅投料合计」按菜谱原单位口径给出；有计数单位行时额外提示「有行走计数单位（个/只等），不计入合计，但仍按锅数放大」。
<!-- anno:end id=meal-plan-detail-bom -->

<!-- anno:start id=meal-plan-picker-rules -->
## 本页规则

- 两段式：**第 1 步选菜谱 → 第 2 步填锅数**；两步共用同一个抽屉，筛选与勾选留在内存里，来回改不丢。
- 两种入口共用本视图：从「＋ 添加菜谱」进入是**多选新增**，从详情抽屉「替换菜谱」进入是**单选替换**。
- 默认锅数：**新增一律 1 锅**（不回查上周）；**替换沿用被替换那道菜的锅数**（换菜不换量）。
- 原因记录：桌面端加菜 / 换菜**不记**调整记录（与手机端「必填原因」不同）。
- 确认后 toast 提示「保存后生效」——加完菜回到表格，**还要点页面上的「保存」**。

## 填写锅数（第 2 步）

- 每道选中菜一张卡片：一锅基准投料、出餐成品系数、投料用量总量、出餐成品总量，随锅数实时重算。
- 锅数校验：**至少 1 锅、最多 99 锅**，越界时提示并不提交。
- 支持「统一锅数 → 应用到全部」，用于一次给多道菜定同一个锅数。
- 卡片会标出「不计入就餐人数」（该菜二级分类被排除时），以及一锅超过设备额定容量的「一锅装不下」提示。
- 底部合计「本次 N 道 · 投料合计 · 出餐合计」用于加菜前核对总量。

## 本页规则

- 三个来源：复制上周（默认选中）、复制上上周、自选周（下拉列出**本档口已保存**的其他周）。
- 覆盖口径：**覆盖**目标日期原有排餐；带入各餐次人均用餐量、每道菜的锅数、来源周的排餐日期。
- **不复制**当日调整记录。
- 目标周为本周时从**今天**起复制，过去的日期保持不动。
- 来源周没有已保存排餐时提示「所选来源周暂无已保存的排餐」；确认后仍需点页面「保存」。
<!-- anno:end id=meal-plan-copy-rules -->

<!-- anno:start id=meal-plan-history-rules -->
## 本页规则

- 记录范围：**只有当天**的排餐调整（新增 / 替换 / 删除）会产生记录；非当天的删除只做二次确认，不记原因。
- 每条记录包含：时间、餐次、类型、明细（菜名）、原因、操作人。
- 入口有两个：日期列头的 ◷ 图标（有记录时高亮，悬浮看摘要）与点击后的本抽屉。
- 无记录时显示「当日暂无排餐调整记录」。
- 记录随计划一起保存；**复制排餐不会把来源周的记录带过来**。

## 本页规则

- 触发场景：**当天**的排餐调整（加菜 / 换菜 / 删除）需要记录原因。
- **调整原因必填**：留空点确认会提示「请填写调整原因」，不关闭抽屉。
- 保存后可通过日期旁的 ◷ 记录图标查看本条调整。
- 本抽屉只收原因，具体的加菜 / 换菜在对应抽屉里完成。

## 本页规则

> **本抽屉在原型当前流程下够不到，请先读这条差异说明。**

### 原型差异（研发需确认保留哪一种）

- PRD 同时写了两条防丢改动规则：① 编辑模式**锁定**切换器（5.1）；② 有未保存修改时切范围**弹拦截抽屉**，可选「取消切换」/「保存后切换」（5.11）。
- 原型 V4 只落地了 ①：编辑态下两个下拉都是 `disabled`，而「有未保存修改」这个状态只可能在编辑态产生（非编辑态没有任何入口能写入编辑缓冲）。
- 因此本抽屉（含「保存后切换」的先校验后放行逻辑）在正常操作路径上**触发不到**，属于重叠实现。
- 建议二选一并同步 PRD：**保留 ①**（编辑态锁定）则删除本抽屉与守卫；**保留 ②**（拦截）则编辑态不应锁死切换器，改由抽屉统一收口。

### 规则本体（若保留拦截路径）

- 触发条件：当前排餐**有未保存的修改**，用户尝试切换组织 / 档口（或清空档口回到总览）。守卫只挂在**切换器自身的交互**上，直接调 API 切范围不会触发。
- 两个出口：「取消切换」留在原范围继续编辑；「保存后切换」先跑校验，**校验不通过则既不提交也不切换**。
- 保存成功后由本模块放行这次切换，切换后**保持当前正在看的那一周**。
- 与生产计划不同：切到生产计划**不再有**「先保存排餐」的拦截（V3 起两边不联动）。
