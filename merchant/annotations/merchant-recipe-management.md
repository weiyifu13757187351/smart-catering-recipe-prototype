# 商户端菜谱中心 · 菜谱管理 业务标注

> 本文件按视图分块，供 `annotation.config.json` 引用。每块对应原型上的一个角标或页面级规则入口。
> 业务事实来源：《商户端菜谱管理PRD》。原型无法表达的业务规则在此补充。

<!-- anno:start id=hub-rules -->
## 菜谱管理工作台规则

菜谱管理是商户端菜谱的统一入口，商户端**不再出现「标准菜谱」「设备菜谱」两个独立栏目**。

### 组织数据范围

| 规则 | 说明 |
| --- | --- |
| 数据范围 | 页面数据范围以左上角**当前组织**为准 |
| 组织切换 | 切换组织后，列表、筛选结果、待同步数量和同步记录全部随之切换 |
| 上下级独立 | 上级组织同步菜谱，不代表下级组织自动拥有 |
| 修改隔离 | 不同组织对同一菜谱的修改互不影响 |

切换组织时若正在编辑菜谱或已勾选待同步菜谱，需提示「未保存内容或已勾选内容将丢失」，确认后切换。

### 与租户端的关系

租户负责维护统一菜谱并授权给商户；商户端负责**选择、落地并独立经营使用**。

- 授权决定**能否同步**；
- 同步决定**是否进入组织**；
- 组织状态决定**是否投入使用**。

### 本页两个入口

| 入口 | 进入 |
| --- | --- |
| 菜谱库 | 维护租户授权同步及自建菜谱 |
| 菜谱分类 | 查看租户统一维护的一级、二级分类（只读） |

## 菜谱库入口

进入当前组织的菜谱库列表，管理两个来源的菜谱：

| 来源 | 定义 |
| --- | --- |
| 租户授权 | 由租户授权，并经当前组织**主动同步**形成的组织菜谱 |
| 自建 | 当前组织自行创建的菜谱 |

关键点：租户授权成功后菜谱只进入**可同步范围**，不会直接写入所有组织菜谱库，必须由各组织分别主动同步。
<!-- anno:end id=hub-library-entry -->

## 菜谱分类入口

进入菜谱分类页，**只读查看**租户统一维护的一级、二级分类。

商户及组织**不支持新增、编辑、删除或排序**分类。

## 菜谱库本页规则

### 页面结构

从上到下依次为：

1. 返回工作台、页面标题「菜谱库」；
2. 组织提示条；
3. 操作按钮：同步菜谱（含数量气泡）、＋ 新建菜谱；
4. 筛选区：默认筛选项 + 更多筛选；
5. 数据表格。

### 数据来源

列表来源**只有两种**，不展示「只读」「可编辑」「商户版本」「自主维护」等附加权限标签：

| 来源 | 生成方式 |
| --- | --- |
| 租户授权 | 在「同步菜谱」抽屉中勾选同步后形成 |
| 自建 | 通过「＋ 新建菜谱」创建 |

### 数据范围

页面数据以左上角当前组织为准；切换组织后列表、筛选结果、待同步数量与同步记录全部随之切换。上级组织同步菜谱不代表下级组织自动拥有。

### 租户侧变化对已同步菜谱的影响

| 租户侧动作 | 商户端结果 |
| --- | --- |
| 下架菜谱 | 已同步组织菜谱**不自动下架**，可继续独立维护 |
| 删除菜谱 | 已同步组织菜谱**继续保留**，不自动删除，但不再产生后续授权版本 |
| 撤销授权 | 已同步组织菜谱继续保留，**不再接收后续版本提醒** |
| 分类停用 / 删除 | 已上架菜谱不自动下架，原分类显示「已停用 / 已删除」 |
| 标签、字典停用 | 已同步菜谱保留原内容，用于历史查看和当前使用 |

### 原型演示数据

原型为纯前端演示，列表、可同步范围、分类树均取自 JavaScript 内置演示数据，刷新即恢复初始值，不产生真实持久化。上线后需替换为按组织 + 筛选条件分页的组织菜谱库接口。

固定展示：

> 当前组织：{组织名称}　菜谱数据仅属于当前组织；切换组织后将展示对应组织的菜谱库。

- 切换组织后列表、筛选结果、待同步数量、同步记录全部重新加载；
- 上级组织同步的菜谱不会自动下发给下级组织。

## 同步菜谱入口与数量气泡

按钮文案为「同步菜谱」，有新的可同步菜谱时显示数量气泡。

### 数量定义

**租户已经授权给当前商户、当前组织尚未同步、且当前允许同步的菜谱数量。**

| 规则 | 说明 |
| --- | --- |
| 计算维度 | **按组织分别计算**，不是整个商户的统一数量 |
| 随组织变化 | 切换组织后数量随之变化 |
| 数量减少 | 同步完成后相应减少 |
| 数量增加 | 组织删除租户授权来源菜谱、且授权仍有效时，该菜谱重新进入可同步范围，数量增加 |

点击后打开「同步租户授权菜谱」抽屉。

**刷新时机（本期确定）**：进入页面时、切换组织时、定时轮询与手动刷新**都需要**触发数量重算。
<!-- anno:end id=list-sync-button -->

## 新建菜谱

点击后打开右侧全高抽屉，包含「1 基础信息」「2 用料明细」「3 加工步骤」三个页签，与租户端的内容结构和主要交互保持一致。

组织可以自行创建：

- **纯人工菜谱**；
- **含设备加工菜谱**。

商户端差异仅在于：数据范围属于当前组织，且**分类、标签、字典只可选择，不可维护**。

新建与编辑的字段、校验规则完全一致。

取值**只有两种**：

| 取值 | 定义 |

## 版本 / 状态

组合展示**菜谱版本号 + 组织私域状态**，如「V2 已上架」。

### 组织私域状态

| 状态 | 含义 |
| --- | --- |
| 草稿 | 尚未正式提交使用 |
| 已上架 | 当前组织正式使用 |
| 已下架 | 当前组织暂停使用 |

### 有新版本

租户对已发布菜谱修改并再次提交后形成新的租户菜谱版本。已同步组织：

- 当前组织菜谱**内容不自动变化**；
- 列表显示「**有新版本**」标识；
- 操作区**不单独显示「处理更新」**，统一从「查看」进入详情处理；
- 组织可以选择暂不更新，提示保留，后续仍可处理。

**注意**：租户菜谱版本与组织私域状态相互独立 —— 租户授权只决定能否同步及能否获得后续授权版本，**不直接控制**组织菜谱的草稿、已上架和已下架状态。
<!-- anno:end id=list-version-col -->

## 更新信息

展示**操作人 + 更新时间**，如「食堂菜谱管理员 2026-09-14 10:30」。

用于追溯最后一次改动当前组织菜谱的操作人与时间。组织对菜谱的任何修改都不影响租户端及其他组织。
<!-- anno:end id=list-update-col -->

<!-- anno:start id=list-action-col -->
## 操作列

菜谱同步后已成为当前组织自己的菜谱，因此**租户授权和自建菜谱均可独立维护**。

| 动作 | 租户授权 | 自建 | 条件与结果 |
| --- | --- | --- | --- |
| 查看 | 支持 | 支持 | 打开菜谱详情抽屉；**有新版本时在此处理版本更新** |
| 编辑 | 支持 | 支持 | 打开编辑抽屉；须使用租户当前有效的分类、标签与字典 |
| 上架 | 支持 | 支持 | 仅「已下架」展示；上架后进入「已上架」 |
| 下架 | 支持 | 支持 | 仅「已上架」展示；下架后进入「已下架」 |
| 删除 | 支持 | 支持 | **仅删除当前组织私域菜谱**，不影响租户端与其他组织 |

### 补充规则

- 操作区**不显示「处理更新」**，版本处理统一从「查看」进入；
- **不提供「复制」操作**：新菜谱统一通过「＋ 新建菜谱」创建，避免产生来源与归属不清的副本；
- 租户授权来源菜谱在**删除后且授权仍有效**时，可以重新同步；原组织版本和修改内容**不自动恢复**；
- 「接收租户新版本提醒」仅租户授权来源适用，自建菜谱不适用；
- **批量操作本期不做**（批量上架／下架／删除均不提供）。
<!-- anno:end id=list-action-col -->

## 菜谱行与同名区分

### 各行内容

| 列 | 展示 |
| --- | --- |
| 菜谱信息 | 图片 + 名称（有新版本时标注）；副标题为「菜谱编号 · 别名」 |
| 菜谱分类 | 二级分类全路径，如「热菜 / 小荤」 |
| 来源 | 租户授权 / 自建 |
| 加工方式 | 纯人工 / 含设备加工 |
| 适配设备 | 设备厂家 · 型号，多个折叠为「等 N 种」；纯人工展示「—」 |
| 用料 | 「N 项」 |
| 菜谱标签 | 标签数量 |
| 版本 / 状态 | 版本号 + 状态 |
| 更新信息 | 操作人 + 时间 |
| 操作 | 按状态动态渲染 |

### 同名菜谱

组织同步或自建菜谱时发现同名菜谱：

- **允许继续创建**，不以名称作为唯一判断依据；
- 操作前提示当前组织已存在同名菜谱；
- 列表通过**编号、来源和版本**帮助用户区分。

### 其他边界

- 重复同步：同一组织已存在对应租户授权菜谱时不允许重复同步，该菜谱不出现在正常可同步列表中；若存在租户新版本，通过查看详情处理更新，**不重新同步**；
- 同一租户菜谱在 A 组织更新到 V3、B 组织停留在 V2 时互不影响；
- 组织菜谱数量与待同步数量按当前组织实时计算。

## 同步抽屉规则

### 可同步条件

菜谱必须**同时**满足以下全部条件：

1. 租户对当前商户的授权关系有效；
2. 租户菜谱当前**已上架**；
3. 菜谱分类有效；
4. 菜谱使用的必要标签和加工字典有效；
5. 当前组织**尚未同步**该菜谱。

### 抽屉结构

| 区域 | 内容 |
| --- | --- |
| 左侧分类树 | 全部菜谱 / 各一级分类 / 各二级分类 |
| 工具区 | 关键词搜索、加工方式筛选、设备厂家筛选 |
| 已选摘要 | 当前已勾选数量 |
| 菜谱列表 | 可同步菜谱，逐项可勾选 |
| 底部 | 取消 / 同步所选菜谱（N） |

组织可勾选**一个或多个**菜谱后批量同步。

### 说明文案

> 选择租户已授权给当前商户、但尚未同步到当前组织的菜谱。同步后形成当前组织自己的菜谱。

### 撤销授权的影响

租户撤销授权后，尚未同步的组织不再允许同步相关菜谱，相关菜谱从可同步数量中移除。
<!-- anno:end id=sync-rules -->

## 分类树

- 选择某一级分类时展示其下全部二级分类的菜谱；
- 分类失效（停用 / 删除）的菜谱在列表中置灰且不可勾选。

<!-- anno:start id=sync-rows -->
## 可同步菜谱列表

每行可勾选一个菜谱，支持多选后批量同步。

### 不可勾选的情况

分类或标签、字典失效的菜谱：

| 表现 | 说明 |
| --- | --- |
| 数量气泡 | **暂不计入**可同步数量 |
| 抽屉列表 | **展示但置灰** |
| 勾选 | **不允许勾选** |
| 状态说明 | 明确显示「所属分类已停用」或「所属分类已删除」 |

租户将菜谱调整至有效分类、或恢复标签与字典后，该菜谱**恢复可同步**。

### 不可同步的其他情况

| 情况 | 结果 |
| --- | --- |
| 租户菜谱已下架 | 暂不可同步；租户重新上架后恢复同步资格 |
| 租户菜谱已删除 | 不可同步 |
| 授权已撤销 | 不可同步，且从可同步数量中移除 |
| 当前组织已同步 | 不允许重复同步，不出现在正常可同步列表中 |
<!-- anno:end id=sync-rows -->

<!-- anno:start id=sync-confirm -->
## 同步所选菜谱

按钮展示已选数量「同步所选菜谱（N）」，点击后批量同步。

### 同步结果

确认同步后：

- 在当前组织菜谱库形成**独立菜谱**；
- 来源显示「**租户授权**」；
- 同步租户**当前最新已发布版本**；
- 同步基础信息、用料、加工步骤、设备适配方案及相关内容；
- **初始状态为「已下架」**，由组织确认后自行上架；
- 当前组织获得编辑、上下架和删除权限；
- 待同步数量相应减少；
- **不影响**商户下其他组织的待同步状态。

### 部分成功与失败

批量同步**允许部分成功**：

| 场景 | 处理 |
| --- | --- |
| 勾选后租户菜谱被下架 / 删除 / 撤销授权 / 分类失效 | 该菜谱同步失败 |
| 其他仍有效的菜谱 | 可以继续同步 |
| 已成功同步的菜谱 | **不回滚** |
| 结果展示 | 成功数量、失败数量及**逐项失败原因** |


<!-- anno:end id=sync-confirm -->

<!-- anno:start id=sync-cancel -->
## 取消同步

关闭同步抽屉，放弃当前已勾选内容，不产生任何同步动作。

若在勾选过程中切换组织，需提示「已勾选内容将丢失」，确认后切换并重新加载目标组织的可同步范围与待同步数量。

## 新建与编辑菜谱规则

### 交互形式

与租户端保持一致的内容结构与主要交互：

- 使用**全高右侧抽屉**；
- 包含「1 基础信息」「2 用料明细」「3 加工步骤」三个页签；
- 加工步骤支持人工处理和设备加工切换；
- 设备加工支持按设备型号查看独立操作时间轴。

### 商户端差异

| 差异项 | 说明 |
| --- | --- |
| 数据范围 | 属于当前组织 |
| 分类、标签、字典 | **只可选择，不可维护** |
| 版本切换 | 租户授权来源菜谱可能出现「当前版本／最新授权版本」切换 |

### 可使用内容

组织自建与编辑菜谱**只能**使用：

- 租户当前有效的菜谱分类；
- 租户当前有效的菜谱标签；
- 租户当前有效的烹饪、菜系、工艺及设备参数字典；
- 当前可用的设备厂家和设备型号。

### 失效内容处理

分类 / 标签 / 字典失效后：

- 新建菜谱**不能选择**；
- 编辑并提交或重新上架时**必须更换为有效内容**；
- 再次编辑提交时应提示更换为有效内容。

## 菜谱分类选择

菜谱分类由**租户统一维护**，商户端仅可在有效分类中选择，**不支持新增、编辑、删除或排序**。

| 情况 | 表现 |
| --- | --- |
| 分类已停用 | 新建时**不可选择**；编辑并提交或重新上架时**必须更换**为有效分类；原分类显示「已停用」，租户恢复后标识自动消失 |
| 分类已删除 | 已同步菜谱保留原分类历史信息并显示「已删除」；编辑并提交或重新上架时**必须重新选择**有效分类 |
| 已上架菜谱 | 分类失效**不自动下架**，可以继续使用 |

**核心原则**：分类失效限制后续新建、编辑提交、重新上架和首次同步，但**不打断已经上架使用**的组织菜谱。

## 分类明细表

| --- | --- |

| 层级 | 一级分类 / 二级分类 |
| 上级分类 | 二级分类展示所属一级分类，一级分类展示「—」 |
| 状态 | 启用 / 已停用 / 已删除 |
| 最近更新 | 租户侧最近更新时间 |

### 分类失效对商户端的影响

**租户停用分类**：

- 已同步的组织菜谱**继续保留，不自动下架**；
- 菜谱原分类显示「已停用」；
- 已上架菜谱可以继续使用；
- **新建菜谱不能选择**已停用分类；
- 编辑并提交或重新上架时，**必须更换为有效分类**；
- 租户恢复分类后，「已停用」标识自动消失。

**租户删除分类**：

- 已同步菜谱**保留原分类历史信息**；
- 原分类显示「已删除」；
- 菜谱**不自动删除或下架**；
- 编辑并提交或重新上架时，**必须重新选择有效分类**；
- 商户分类页面不再将其作为正常分类展示，但历史菜谱仍可识别原分类。

**尚未同步的菜谱**：所属分类已停用或删除时，暂不计入可同步数量气泡，在同步抽屉中展示但置灰、不允许勾选，并明确显示「所属分类已停用」或「所属分类已删除」；租户将菜谱调整至有效分类后恢复可同步。
