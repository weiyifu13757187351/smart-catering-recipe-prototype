# 商户端 · 采购管理业务标注

> 事实来源：《商户端采购管理 PRD v1.0》（`商户端采购管理PRD.md`，含 §1 共用底座、§2 采购订单、§3 供货关系、§4 价格与金额、§5 边界与异常）。
> 范围：左侧「采购管理」下的**采购订单**（列表 → 详情两层）与**供货关系管理**（单层）。采购计划属于「计划管理」，不在本文范围。
> 本文只写原型看不出来、但实现或验收需要知道的规则。标「原型差异」的是 PRD 口径与原型现状不一致，**不要以原型为准**；标「待确认」的 PRD 未定，不要按惯例补齐。

<!-- anno:start id=pm-global-rules -->
## 采购管理共用口径

### 单据结构

- 一张订单 = **一个送达日期 + 一家供应商**；一次提交按（送达日期 × 供应商）拆成 N 张订单，**不存在采购单容器**。
- 订单是唯一单据：没有询价单、没有采购单号；来源只有两种：`直采下单` / `采购计划`。

### 状态机（全文只此一处）

- 状态链路：`待确认` → `已确认` → `待验收` → `验收中` → `已完成`。**没有已取消、没有退货中**。
- `待确认` 可删除（二次确认后物理删除）；进入 `已确认` 及之后**不可撤回、不可删除**。
- 删除订单、修改订单都只在 `待确认`；`已完成` 后验收量锁定，只能从商品行发起退货。
- 退货**不改变订单状态**，订单始终停在 `已完成`。

### 编号与幂等

- 订单号：`CG` + 送达日期 `yyyyMMdd` + 3 位随机数，**不随流水重置**；同日期撞号要重取。
- 退货单号：`RT` + 提交日期 + 3 位随机数，同一规则。
- 幂等键：`档口 + 供应商 + 来源单号 + 送达日期`；重复提交不得重复生单，转单重复点给「该计划已生成订单」。

### 金额与数量精度【规则】

| 项 | 口径 |
| --- | --- |
| 数量、单价 | 2 位小数，四舍五入 |
| 金额 | 2 位小数，**小数第 3 位起直接截断，不四舍五入**（只向下取，不允许进位虚增） |
| 计算顺序 | 用原始精度相乘/累加，**只对最终金额截断**；不允许先把单价四舍五入再相乘 |
| 截断范围 | 行总价、订单总金额、验收总金额、小计、合计、统计卡金额、当前验收金额全部适用 |

### 四种价格

- 预报价（供应商维护，直采用）/ 定标报价（采购计划定标结果，转单直接带入）/ 下单价（下单快照）/ 结算价（本期不做）。
- 订单生成后单价**不再变化**，供应商改报价也不影响已生成订单。

### 数据范围

- 所有数据按**档口**隔离：切档口只改数据范围，不改单据归属；越权档口不出现在下拉，直访要给无权限提示。
- 统计卡与列表同源同口径，**不允许前端自行累加或加减数字**。

## 本页规则（订单列表）

### 定位

- 入口：左侧「采购管理」→「采购订单」；面包屑「采购管理 / 采购订单」。
- 第 1 层只做筛选与跳转，改单、验收、退货都在第 2 层（订单详情）里做。

### 排序

- 固定排序：创建时间倒序 → 供应商升序 → 送达日期升序 → 订单编号倒序。不提供列排序。
- 同一次提交生成的多张订单 `createdAt` 相同，因此同一供应商的订单会排在一起。

### 分页【待确认】

- 原型一次性全量渲染，没有分页。正式版按 **20 条/页**，翻页保留筛选与页签条件，切档口或「重置」回第 1 页。

### 空态

- 该档口一笔单都没有：`暂无订单，点右上角「新建订单」开始`。
- 有订单但筛选/页签后无结果：`没有符合条件的订单，试试放宽送达日期、换个供应商或改状态页签`。两种空态不能混用。

## 统计卡（5 张）

| 卡片 | 口径 |
| --- | --- |
| 订单总数 | 该档口全部订单数 |
| 订单验收总金额 | Σ（行累计验收量 × 行单价）；未验收的行按 0 计 |
| 本月订单数 | 按订单**创建时间**落在本月统计，不是送达日期 |
| 本月订单验收总金额 | 上述本月订单的验收金额合计 |
| 待我验收完成订单数 | **状态不是「已完成」的订单数**，不是「待验收」状态的数量 |

### 【规则】统计卡不随筛选联动

- 5 张卡只跟**档口**走：改日期、来源、供应商、编号、状态页签、售后页签都**不影响**卡片数字。
- 卡片数值与列表数据必须同源；空数据时金额显示 `¥0.00`（列表里的验收金额空值显示 `—`，两者口径不同，不要混用）。

## 筛选条

| 筛选项 | 数据源 | 生效方式 |
| --- | --- | --- |
| 送达日期 起 / 止 | 默认 `[今天-15, 今天+15]` | 改动即时生效 |
| 来源 | 固定枚举：直采下单 / 采购计划 | 改动即时生效 |
| 供应商 | 该档口**已出现过**的供应商去重（直采取供货关系绑定、转单取计划定标供应商） | 改动即时生效；没有出现过时只保留「全部供应商」 |
| 订单编号 | 手输 | **必须回车或点「查询」才生效** |
| 查询 / 重置 | — | 重置恢复到默认日期区间与全部条件 |

- 日期起 > 止不报错，按交集为空处理，走无结果空态。
- 编号框模糊输入不会实时过滤，避免每敲一个字符就刷一次表。
<!-- anno:end id=pm-list-filters -->

## 两组页签（交叉生效）

- 第一组：订单状态 6 个页签（全部 + 5 个状态），每个页签带张数。
- 第二组：售后 3 个页签 `全部售后` / `有售后` / `无售后`（注意标签是「**全部售后**」，不是「全部」）。
- 两组页签**同时生效**（取交集），并与日期、来源、供应商、编号条件叠加。
- 张数基数是「经过日期/来源/供应商/编号筛选后的集合」，**不含页签自身条件、也不含另一组页签条件**。
- 计数为 0 的页签置灰不可点。
<!-- anno:end id=pm-list-tabs -->

## 订单表格（11 列）

| # | 列 | 口径 |
| --- | --- | --- |
| 1 | 订单编号 | `CG…` 号，点击进详情 |
| 2 | 供应商 | 该订单唯一供应商 |
| 3 | 来源 | `直采下单` / `采购计划` |
| 4 | 送达日期 | `MM-DD 周X` |
| 5 | 品项 | **不同 SKU 数** + 「项」，不是行数不是件数 |
| 6 | 订单总金额 | Σ（下单量 × 单价），截断到 2 位小数 |
| 7 | 验收总金额 | Σ（累计验收量 × 单价），截断；**一行都没验收过时显示 `—`** |
| 8 | 订单状态 | 状态标签 + 派生标签：`部分发货`（部分行已发货）、`已签名`（已完成且有签名） |
| 9 | 是否有售后 | `有` / `无` |
| 10 | 创建时间 | `MM-DD HH:mm` |
| 11 | 操作 | 见下 |

### 行操作

| 操作 | 出现条件 | 后果 |
| --- | --- | --- |
| 查看 | 恒有 | 进订单详情 |
| 修改 | `待确认` **且** 来源为直采 | 抽屉改收货人/地址；转单订单不可改商品清单 |
| 删除 | `待确认` | 二次确认（`我再看看` / 删除）后**物理删除，不可恢复**；非待确认状态直接拒绝 |

- 退货**不冲减订单总金额**；供应商认可后退货只冲减**验收金额**，所以「订单总金额」列不因退货变化。

## 本页规则（订单详情）

### 页头

- 左上 `← 返回订单列表`（回列表并保留原筛选与页签）。
- 摘要行：供应商 / 送达日期 / 订单金额 / 验收金额 / 已验收 x/y 行；验收金额一行都没验收时显示 `—`，不显示 `¥0.00`。
- 右上「更多信息」7 项，**默认收起**：下单方、来源、来源单号（直采显示 `—（直采下单无来源单）`）、创建时间与创建人、发货联系人、收货联系人、收货地址。
- 「修改订单」只在 `待确认` ∧ 直采 出现（与列表一致）。

### 状态提示条

| 状态 | 提示条 |
| --- | --- |
| 验收中 | `已完成 x/y 行验收` + 右侧「验收完成（签名）」，**全部行已验收才可点**，否则置灰 |
| 已完成 | 绿色横幅 `订单已完成并电子签名（时间 · 验收人），全部商品的验收量已锁定` |
| 其他状态 | 不出现提示条 |

### 下方三段

| 区块 | 规则 |
| --- | --- |
| 发货记录 | 3 列（预计发货时间 / 配送员 / 手机号）；**没有发货记录时不得编造预计发货时间**（旧原型会伪造 06:00，已废止） |
| 售后记录 | 7 列（售后单号 / 商品 / 退货量 / 退货原因 / 退货凭证 / 售后状态 / 申请时间），申请时间倒序；空态 `无售后记录` |
| 状态时间轴 | 每条 = 时间 + 文案，倒序；由后端写入、前端只展示，不可编辑 |

### 时间轴事件（全章统一）

- 订单生成、供应商确认、供应商发货、行级验收第 N 批、修改批次、删除批次、验收完成并签名、发起退货、供应商认可/不认可退货。

### 原型差异

- 底部「供应商模拟」区（确认订单 / 确认发货 / 认可或不认可售后）与售后记录里的「模拟售后单」按钮都是**原型专用**，正式版由供应商端接口驱动，必须删除。
<!-- anno:end id=pm-detail-rules -->

<!-- anno:start id=pm-detail-lines -->
## 商品明细（11 列，行级验收的入口）

- 列：`#` / 商品名称（+形态）/ 单位 / 规格 / 单价 / 总价 / 备注 / 下单量 / 实际发货量 / 实际验收量 / 操作。
- 总价 = 下单量 × 单价（截断 2 位小数）；退货**不改变**下单量与行总价，只影响验收量。

### 行状态标签

| 标签 | 判定 |
| --- | --- |
| `未验收` | 该行累计验收量为空 |
| `已验收` + `第 1 批` | 有验收量且只有 1 批 |
| `已验收` + `共 N 批` | 有验收量且批次数 > 1 |
| `已锁定` | 订单已完成，验收量不可再改 |

### 行操作（三件，按状态显隐）

| 按钮 | 出现条件 | 说明 |
| --- | --- | --- |
| 验收 | 状态 ∈ {待验收, 验收中} **且该行已发货** | 未发货置灰 + tooltip「供应商尚未发货」；已完成时消失 |
| 验收详情 | 恒有 | 看批次记录、差异原因、资质照片、签名 |
| 退货 | 已完成 ∧ 该行验收量 > 0 ∧ 无「待供应商确认」售后单 ∧ 从未发起过售后 | 有任意售后记录后变成「售后详情」；未完成时不给退货入口 |
<!-- anno:end id=pm-detail-lines -->

<!-- anno:start id=pm-detail-accept-head -->
## 验收完成（订单级收口）

- 前置：**所有商品行都已验收**，否则提示「还有 N 个商品未验收，请先完成验收」。
- 有「累计验收量 < 实际发货量」的行 → 先弹差异原因确认，再进电子签名；没有差异直接进签名。
- 完成后订单 → `已完成`，全部行验收量锁定，商品明细只读，只剩验收详情与退货/售后详情。
<!-- anno:end id=pm-detail-accept-head -->

## 第 1 步 · 送达日期与数量

### 日期区间

- 「起始日 ~ 结束日」，**区间最长 31 天**；每个日期单独下单，某天不填就不生成那天的订单。
- 每个日期一个页签（`MM-DD 周X`），页签右上 `×` = 删除该天（不生成该天订单），删除后出现「恢复已删除的 N 天」。

### 当天工具条

- `已选 N 个商品（已填量 M 个）· 当天小计 ¥X` + `复制` / `粘贴` / `+ 添加该日商品`。
- 「复制/粘贴」只在**本次向导内**、同档口同草稿的不同日期之间生效；不提供跨订单复制。

### 商品表格

- 12 列：图片 / 商品名称 / **供应商** / 单位 / 规格 / 品牌 / 单价 / 总价 / 形态 / 采购量 / 备注 / 删除。
- 供应商、单价、单位、规格、形态、品牌**全部只读**，来自供货关系管理与商品中心；只有采购量与备注可填。
- 总价随填随算（采购量 × 单价，截断 2 位小数）；未填显示 `—`。

### 合计行与校验

- 合计行：`将生成 N 张订单：… 中 X 天有需求 · 涉及 Y 家供应商（每家供应商每个送达日期各 1 张）· 合计 ¥Z`，合计按原始精度累加后截断。
- 一个商品都没添加 → 拦截：「请先添加商品」。
- 某天有商品但采购量为空 / 0 → 拦截「请至少填写 1 个商品的采购量」，并跳到第一个问题日期、把该行标红。
<!-- anno:end id=pm-wiz-days -->

<!-- anno:start id=pm-wiz-days-filters -->
## 日期区间控件

- 起 ≤ 止、跨度 ≤ 31 天，由日期控件限制，超出不生成页签。
- 改动任一端都会按新区间重算页签；已填的数量按日期保留，新出现的日期默认为空。
- 区间内日期被全部删除时给空态并给「恢复已删除的日期」入口。
<!-- anno:end id=pm-wiz-days-filters -->

## 第 2 步 · 总览

- 只统计「某天量 > 0」的日期与商品；总量为 0 的商品不参与拆单、不参与统计。
- 每张供应商卡片按**小计金额降序**排列。
- 卡片内的「每日数量」逐日列出 `MM-DD 量`，与订单拆单口径一致（一天一单）。

### 四个统计块

| 统计块 | 口径 |
| --- | --- |
| 送达日期区间 | `MM-DD ~ MM-DD`，共 N 天 |
| 有需求天数 | 有量的日期数（不是区间天数） |
| 订单张数 | 供应商数 × 有需求天数（每家每个送达日期各 1 张） |
| 涉及供应商 | 有量的供应商数 |
<!-- anno:end id=pm-wiz-overview -->

<!-- anno:start id=pm-wiz-overview-stats -->
## 摘要卡

- 合计金额（大数，截断 2 位小数）+ 4 个统计块；供应商 chip 行显示 `供应商名 · M 商品 · N 张订单`。
- 区间内没填任何数量时，chip 行显示 `区间内没有填写数量`，合计为 `¥0.00`。

<!-- anno:start id=pm-wiz-receiver -->
## 第 3 步 · 收货与提交

| 字段 | 规则 |
| --- | --- |
| 收货联系人 | **必填**；只能从**门店后厨人员**中单选，**不支持手工输入**；抽屉内可搜姓名 / 手机号，选后可「重选 / 清除」 |
| 收货地址 | 必填；**默认回显门店地址**，可修改 |

### 提交

- 点「提交下单」→ 二次确认：标题「提交下单」、文案「是否确认提交该次采购？」、按钮「确认 / 我再看看」。
- **「我再看看」停留在第 3 步，不生成任何订单**。
- 确认后按（送达日期 × 供应商）拆单，订单状态 `待确认`，来源 `直采下单`，来源单号为空，创建人 = 当前账号。
- 生成后回列表并**自动放开筛选**（清来源/供应商/关键词/页签，日期区间扩展到覆盖新单），toast：`已生成 N 张订单（X 个送达日期 × Y 家供应商），已按创建时间排在列表最前`。

### 校验

- 未选收货人 → `请选择收货联系人（门店后厨人员）`；地址为空 → `请填写收货地址`；区间内无任何数量 → `所选区间内没有填写任何数量`。
- 确认后按钮进入 loading，禁止重复提交（幂等键见共用口径）。

## 添加商品抽屉

### 候选池（核心口径，开发必读）

> 可添加的商品 = 该档口**已绑定供应商且有预报价的在售商品**。三个条件同时满足才出现：
> ① 该档口**在售** ② 该 SKU **已在供货关系管理绑定供应商** ③ 该绑定供应商对该 SKU **有预报价**。
> 缺一即不出现；未绑定的商品**不会出现在列表里**（不是灰掉，是不出现）。

- 候选为空的空态：`该档口还没有「已绑定供应商且有报价」的商品，无法下单` + 按钮「去供货关系管理」。
- 单价与供应商都取自供货关系管理，抽屉只做选择，不改价不改供应商。

### 交互

- 搜索框支持**商品名称与拼音首字母**（黄瓜 / hg / xhg），`↑` `↓` 移动高亮、`回车` 直接添加当前高亮；中文输入法上屏中的回车不触发。

## 行级验收抽屉

### 验收单元与批次

- 单元 = **商品行**；批次**累加**：本次 + 已验收 = 累计，**不是覆盖**。
- 「本次验收量」必填，提示：填「这一次」的收货量，会累加到已验收量；可分多次验收，差异原因在「验收完成」环节填写。
- 验收方式本期固定「手动验收」，只读展示。
- 前置：该行**已发货**；未发货时入口点不了，提示「供应商尚未发货」。

### 实时汇总三态

| 累计 vs 实际发货量 | 文案 | 处理 |
| --- | --- | --- |
| 累计 > 发货量 | `超出实际发货量 D 单位（超发 / 补送）` | **不拦截**，可保存 |
| 累计 < 发货量 | `少于实际发货量 D 单位，验收完成时需填差异原因` | 可保存，收口时补原因 |
| 累计 = 发货量 | `与实际发货量一致` | 可保存 |

### 验收照片【已确认】

- **选填，0～5 张**，不传也可保存；可逐张删除；达上限按钮变「已达上限 5 张」。
- 有历史批次时**回填上一批照片**，提示「已回填上一批 N 张，最多 5 张，可删除」。

### 历史验收（只读）

- 5 列：批次 / 时间 / 验收人 / 本次验收量 / 照片；**仅展示**，修改与删除统一在「验收详情」里做。
- 空态：`该商品尚未验收，本次为第 1 批`。

### 保存后的连带影响

1. 新增一条批次记录（批次号、时间、验收人、方式、本批量、改前累计、改后累计、照片数）。
2. 该行累计验收量 = 改后累计；行状态变「已验收」。
3. 订单状态 `待验收` → `验收中`（不动已完成）。
4. 写一条状态时间轴；关闭抽屉并刷新商品明细。
5. toast：`「商品名」本次验收 X 单位已记入（累计 Z 单位）`。

### 校验

- 未填 → `请填写本次验收量`；填 0 或负数 → `本次验收量必须大于 0`。

## 实时汇总条

- 未填时只显示 `已验收 Y 单位 · 待验收 P 单位`；待验收量 = 实际发货量 − 累计验收量。
- 超发/短缺只是提示与变色，**不阻断保存**，差异原因统一在「验收完成」时填。

## 发起退货（商品行）

### 四个前置条件

1. 订单已 `已完成`（未完成点不到入口，越权调用提示「需「验收完成」后才能发起退货」）。
2. 该行累计验收量 > 0。
3. 该行无「待供应商确认」的售后单（有在途单提示「该商品已有待供应商确认的售后单」）。
4. 该行从未发起过售后（有任一售后记录时行操作变成「售后详情」，在详情里重新发起）。

### 表单

| 字段 | 规则 |
| --- | --- |
| 退货量 | 必填，> 0 且 **≤ 该行当前累计验收量** |
| 退货原因 | 必填，下拉 9 项：`生鲜状态异常` / `变质腐败` / `存在病虫或异物` / `大小/重量不符` / `加工形态不符` / `少发/漏发` / `包装破损` / `以次充好` / `其他` |
| 其他原因 | 仅选「其他」时出现，必填、≤50 字 |
| 退货凭证 | 选填，最多 5 张，可逐张删除（照片 / 检测截图 / 聊天记录均可） |

### 校验与后续

- 量为空/≤0 → `请填写退货量`；量 > 验收量 → `退货量不能大于实际验收量（X）`；未选原因 → `请选择退货原因`；其他未填 → `请填写「其他」的具体原因`。
- 提交后售后单状态 `待供应商确认`，**此时金额不冲减**、订单状态不变。
- 轮次不设上限，按该行已有售后单数自动 +1，只记录轮次不限次数。
<!-- anno:end id=pm-return -->

<!-- anno:start id=pm-as-detail -->
## 售后详情抽屉

### 三态

| 状态 | 表现 |
| --- | --- |
| `待供应商确认` | 已提交等待供应商处理；订单仍是 `已完成`；**金额不冲减** |
| `供应商已认可` | 该行验收量扣减、标「有退货」；**只冲减验收金额，订单金额不变**；绿色横幅 |
| `供应商不认可` | 黄色横幅 + 不认可理由；**金额不冲减**；可「重新发起」（修改后再次提交） |

### 【规则】认可后的金额冲减

- 触发时点：**仅「供应商已认可」时冲减**；待确认、不认可、不认可后重新发起期间都不冲减。
- 冲减对象：**只冲减验收金额**（该行累计验收量扣减退货量，验收金额随之减少）。
- **订单金额与行总价一律不变**，仍等于下单时的「下单量 × 单价」快照。
- 冲减金额 = 退货量 × 该行单价（截断 2 位小数）；冲减后验收金额 = Σ(回写后累计验收量 × 单价)，与按公式重算结果一致。
- 多次退货：每次认可各冲减一次，累计冲减额 = Σ(每次认可退货量 × 单价)。
- 留痕：写时间轴「供应商已认可退货 {售后单号}，冲减验收金额 ¥Y」。

### 区块

- 商品信息 7 列：原验收量（退货前）/ 已退货量 / 当前验收量；原验收量 = 当前验收量 + 已退货量。
- 售后信息：售后单号 / 退货量 / 退货原因 / 申请时间与申请人 / 售后状态。
- 退货凭证：`本次共 N 张`，空态「本次售后未上传退货凭证」。
- 历史售后单（该行售后单 > 1 时）：售后单号 / 申请时间 / 退货量 / 退货原因 / 售后状态 / 不认可理由，倒序。
<!-- anno:end id=pm-as-detail -->

## 本页规则（供货关系管理）

### 定位

- 一条关系 = **档口 × 商品 SKU × 1 家供应商**，一对一；重复绑定即**覆盖**，不保留历史绑定。
- 它是**直采下单的唯一数据底座**：商品池、供应商、单价全部取自这里；没绑定就没有直采下单入口。
- 与**采购计划转单无关**：转单的供应商由计划定标结果决定，本模块不参与、不做校验。

### 页头说明

- 「按档口把商品 SKU 绑定到 1 家供应商；下架商品不清除绑定」。

### 空态

- 有 SKU 但筛选无结果：`没有符合条件的商品，试试放宽筛选条件`。
- 档口下没有可展示 SKU：`当前档口没有状态正常的商品 SKU`。

## 批量三动作【规则】

> 作用范围 = 该档口**全部在售 SKU**，**不受任何筛选影响**、也不认勾选（表格没有勾选列）。已下架 SKU 的绑定不会被这三个动作改动。

- 标题副文案：`{商品名} · 只能选择能供应「{形态}」的供应商`——**只列能供应本 SKU 形态的供应商**（如净菜 SKU 不会出现毛菜供应商）。
- 商品信息 6 项：商品名称（主+副名）/ SKU 编码 / 形态 / 规格与单位 / 商品分类（三级全路径）/ 最近一次采购（`MM-DD · 供应商`，无则 `—`）。
- 供应商候选表 5 列：单选 / 供应商（名 + 联系人）/ 供应类型标签 / **该商品报价** / 最近采购标记。

### 无报价的处理

- 该 SKU 有报价供应商存在时：**无报价的供应商整行单选锁定、点行也不选中**，报价列显示「该供应商无此商品报价」。
- 该 SKU 一个报价都没有：不列供应商，只给一行「该商品暂无供应商报价」+ 说明，**仍可保存**，保存后该商品记为「暂无报价」，等供应商报价后再改绑。
- 保存后列表的「当前供应商 / 最低报价 / 绑定状态」即时刷新，toast 反馈绑定结果。
- 校验：未选中任何一项 → `请选择供应商`。

### 覆盖语义

- 保存即**覆盖**该档口该 SKU 的原绑定，不保留历史绑定；不影响已生成订单（订单行是下单时快照）。

## 按形态批量绑定

- 两个必填：`商品形态`（一次只处理一个形态，默认取当前筛选形态，否则 `半成品`）+ `供应商`（只列能供应所选形态的供应商，选项带供应类型）。
- 切换形态会清空已选供应商并重算预览。
- 预览行：`将影响 N 个「形态」商品，其中 M 个已绑定其它供应商会被覆盖；绑定到 X`。
- 作用范围是该形态**全部在售 SKU**，与筛选无关；无在售商品时提示 `当前没有「形态」形态的在售商品`。
- 未选供应商 → `请选择供应商`。
