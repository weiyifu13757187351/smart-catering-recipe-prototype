## 1. 背景与目标

### 1.1 业务问题

| # | 问题 | 现状 |
| --- | --- | --- |
| 1 | 排餐计划已经能算出「这些天要做哪些菜、各做几锅」，但**没有人把这个需求折成"要买什么、买多少"** | 采购员靠手抄 / 凭经验估 |
| 2 | 菜谱用料的单位口径在 v1.0 下是混用的（克 / 千克 / 毫升 / 升 / 个），采购侧无法直接汇总 | 靠人工换算，口径不可追溯 |
| 3 | 对外询价没有单据：发微信、打电话，**价格与数量没有可追溯的对外口径** | 报价散落在聊天记录里 |
| 4 | 一份需求可能被重复询价 / 重复采购，且**没有机制保证同一时刻只有一个对外口径** | 无锁、无版本 |

### 1.2 本期目标

| # | 目标 | 验收落点 |
| --- | --- | --- |
| G1 | 采购员选定一段日期区间，系统自动框定这些天的菜并汇总成材料清单 | 第 5 章 |
| G2 | 材料清单可增删改；**先在「采购清单」把标准食材映射成商品**，再到「采购明细」逐天填预计采购量 | 第 7 章 |
| G3 | 可一键发起询价，生成**不可变快照**的询价单，同时发给多家供应商 | 第 8 章 |
| G4 | **同一采购计划同一时刻只允许一份在途询价单**，**发起后不可撤回、不可解锁**；要重来只能另建一份同期采购计划 | 4.2 / 4.7 / 8.2 |
| G5 | 询价单必设报价截止时间，到期未报价的供应商本轮自动出局 | 8.4–8.7 |
| G6 | 预报价只剩**一个角色**：供应商端的报价默认值（商户端参考价已作废，见 D7 / D18） | 第 9 章 |
| G7 | **采购与填写是按天发生的**：一天一个 tab，逐天看克数、逐天填量 | 7.3 |
| G8 | **系统不替用户换算包装**：只给克数事实，买多少由采购员看克数自行判断 | 7.4 |
| G9 | **价格信息只有一个入口**：报价比较抽屉（商品 × 供应商矩阵），明细表不再出现任何价格列 | 7.5 |

### 1.3 本期范围

- 采购计划：周期框定、范围预览、材料派生、映射、按天填量、增删改、重新生成；
- **三个并列页签**：`采购清单`（全局映射）/ `采购明细`（按天覆盖 + 按天填量）/ `询价单`；
- **报价比较抽屉**：商品 × 供应商的价格矩阵，最低价高亮；
- 询价单：发起（多供应商）、快照冻结、**发起即锁定不可撤回**、报价截止与超时处理、部分报价口径、**按天需求附表**；
- 供应商端报价页：**口径定稿**（第 8.9 节），界面下一轮；
- 菜单与页面：计划管理 → 采购计划（列表页 + 详情页 + 三个页签）。

> **本期明确不做的事**：① 任何形式的克 → 箱 / 袋 / 桶 折算与建议采购量（见 7.4 / D14）；
> ② **餐次维度** —— 采购计划恒取区间内该档口全部餐次，不让用户选（D19）。

### 1.4 本期不包含

| 不含项 | 说明 |
| --- | --- |
| 比价 / 定标页 | **定标已在原型落地**【V2.1 回填】：询价单页签「定标」按商品逐个选供应商，只对有报价的商品可定标，确认后询价单转「已定标」（终态）。**注意：「报价比较」抽屉仍只做矩阵展示与最低价高亮，不是比价结论、不能在这里选中标供应商**（D18 / Q3） |
| 采购订单 | 定标之后才有，后续轮次 |
| 供应商端报价页界面 | 本轮只定交互口径 |
| 库存台账 / 领用出库 / 财务对账 | 不涉及 |
| 短信 / 微信通知 | 仅站内（【沿用】既有口径） |
| 跨计划的询价待办视图 | 未来放「采购管理 → 询价单」，本轮不做 |

### 1.5 事实来源标注约定

| 标记 | 含义 |
| --- | --- |
| **【规则】** | 可验收的产品口径，实现与测试均以此为准 |
| **【原型】** | 页面呈现细节（样式、文案、位置），供对照，不构成额外需求 |
| **【已确认】** | 已评审拍板的决策 |
| **【沿用】** | 上游或既有文档已确认的口径，本文档不改写 |
| **【建议】** | 未单独评审的默认值，按此执行，可随时调整 |

## 2. 术语

| 术语 | 定义 |
| --- | --- |
| **采购计划** `PurchasePlan` | 档口针对一段**需求周期**（纯日期区间，**无餐次维度**，D19）形成的工作稿：材料清单（`items`）+ 全局映射 + 按天填量（`daily`）。草稿态可反复编辑与重新生成 |
| **询价单** `Inquiry` | 由采购计划发起、对外发出的**不可变快照**：发给哪些供应商、每个商品要多少（含按天需求）、报价截止时间 |
| **报价单** `Quote` | 供应商对询价单的应答，粒度 = `询价单 × 供应商 × 商品`。本轮只留表结构 |
| **在途询价单** | 状态为「询价中 / 已截止 / 已定标未下单」的询价单。同一采购计划下最多 1 份 |
| **需求周期** | 采购计划覆盖的**日期区间**（如「10/20~10/26」）。**不含餐次** —— 恒取该档口区间内全部餐次（D19） |
| **材料行 `item`** | 采购清单里的一行，`key` = `ing:{标准食材}` / `sku:{SKU编码}` / `manual:{...}`。携带 `basis`（派生依据）与全局映射 `skuCode` |
| **采购清单** | 页签一。**映射层，不填量**：把标准食材映射成商品 SKU，映射结果作用于所有日期（D17） |
| **采购明细** | 页签二。**按天填写层**：一天一个 tab，可对当天单独覆盖商品、逐天填预计采购量（D16 / D17） |
| **映射** | 「这个标准食材到底买哪个商品」的决策。全库级默认写在 `item.skuCode`，并按「档口 × 标准食材」记忆（`pp:ingmap`） |
| **按天覆盖** | 某一天用与全局不同的商品：写 `daily[date][key].skuCode`。采购清单里以「N 天已单独指定」提示；明细页可「恢复默认」撤销 |
| **按天需求** | 询价单明细行上附带的 `byDate`：`10-20 2箱 · 10-21 3箱`，只含有量的天（D20） |
| **预报价** | 供应商针对 `商户 × 商品` 维护的**参考单价数据**（【沿用】既有 D7b）。**V2.0 起只剩一个用途：供应商端的报价默认值**（商户端参考价已作废，见 9.1） |
| ~~参考价 / 参考金额~~ | ~~由预报价得到的单价与金额~~ **作废** → 商户端不再展示任何参考价，价格统一看「报价比较」（D18） |
| **报价比较** | 抽屉。行 = 询价单明细商品，列 = 本次受邀供应商；缺报价显示 `-`，每行最低价绿底高亮。**只展示、不做推荐结论**（D18） |
| **预计采购量** | 采购员在**某一天**为某商品填写的采购意图，单位 = 该商品当日的**下单单位**。**每天每一条有商品的行都必填**；某天不买请用「忽略（仅当天）」，**留空不再表示「这天不买」**，D10 / D16 |
| **当日用料（克）** | 某材料行在某一天的派生用量，单位**恒为克**，只读。全部日期之和 = 该行的「合计克数」 |
| **待映射行** | 菜谱用料挂的是「标准食材」、尚未选定商品的材料行（红标，**阻断发起询价**） |
| **忽略行** | 采购员标记「不采购」的材料行；在采购明细里点的是「**忽略（仅当天）**」，只影响当天。软删除、可恢复，重新生成时保留 |
| **手工行** | 采购员手动补的材料行，`source='manual'`、无排餐依据；**属于某一天**，重新生成时保留，清空数量也不消失 |
| **烹饪投料（计入）** | 菜谱中开启「计入烹饪投料」的加工步骤所包含的用料。**只有这一段进入采购测算**（【沿用】v2.0） |
| **过程用料** | 关闭「计入烹饪投料」的步骤里的用料，仅作加工过程记录，**不参与任何下游测算**（【沿用】v2.0） |
| **合并键** | 派生材料行的唯一键：标准食材按**食材名**、商品 SKU 按 **SKU 编码**、液体 / 粉末按**名称**（【沿用】v2.0 §4.4） |
| ~~覆盖率（拟询价供应商）~~ | ~~某供应商「有生效预报价的行数 ÷ 询价清单行数」~~ **作废**（D11 参考价列已删）→ 报价比较抽屉里改为「已报 M/N 项」（**实际回价**，不是预报价） |
| **不配送** | 「超时未报价」的语义：**本轮询价该供应商自然出局，因此本轮订单里不会出现它**。不是惩罚，不拉黑 |
| **次级组织 / 档口** | 商品与 SKU 挂在次级组织；档口不持有商品，使用所属次级组织的商品（【沿用】） |

## 3. 角色与场景

### 3.1 角色

| 角色 | 在本模块的职责 |
| --- | --- |
| **采购员** | 新建采购计划、选周期、选商品、填预计采购量、发起询价（**发起后不可撤回**，要重来只能另建同期计划） |
| **供应商** | 接收询价单、按行报价、提交；本轮只定口径，界面下一轮 |
| **系统** | 派生汇总用料克数；到截止时间自动置「超时未报价」；截止前 2 小时发一次催报价 |

> 角色权限矩阵本轮不另行定义，按商户端既有角色 / 按钮权限体系执行【沿用】。

### 3.2 典型场景

| # | 场景 | 关键口径 |
| --- | --- | --- |
| S1 | 采购员为「本周」生成采购计划 | 周期默认本周一~本周日；**不再选餐次**，恒取全部餐次 |
| S2 | 跨周采购（10/20 周二 ~ 10/26 周一） | 必须能跨两个排餐周聚合 |
| S3 | 同一份清单发给 3 家供应商比价 | 一张询价单多收件人，仍是 1 份在途；发完用「报价比较」横向看价 |
| S4 | 发出后发现数量填错，需要重来 | **不能撤回、不能解锁**：只能另建一份同期采购计划重新发起（列表标「同期第 N 份」），旧计划与旧询价单只读留痕 |
| S5 | 供应商超时不报价 | 自动置「超时未报价」，本轮不配送，不阻断其他家 |
| S6 | 供应商只供肉类，只报了一部分行 | 算有效参与，按行定标（本轮仅口径） |
| S7 | 饮用水这类可自采也可外采的用料 | 不排除、不特殊处理，由采购员在采购清单里映射商品或忽略 |
| S8 | 周四才临时要加一批排骨 | 到「采购明细」周四那天点「手工加行」，只影响周四 |

## 4. 端到端流程与状态机

### 4.1 三层对象职责

| 层 | 对象 | 职责 | 可编辑性 | 生命周期 |
| --- | --- | --- | --- | --- |
| L1 | **采购计划** | 选定周期、框定菜品、派生材料清单、映射商品、按天填预计采购量 | **草稿态可改**；**一经发起询价即永久锁定、不可解锁** | 长期存在；`档口 × 区间` 可并存多份（同期第 N 份，见 4.3） |
| L2 | **询价单** | 对外询价的**快照**：供应商名单、每商品数量（含按天需求）、报价截止时间 | **一经发起不可改、不可撤回** | 每次发起一份；已定标为终态 |
| L3 | **报价单** | 供应商应答 | 供应商侧 | 本轮不实现，只留表结构 |

> **报价比较**不是第四层对象 —— 它只是 L2 的一张横向视图，不落库、不产生新单据。

### 4.2 端到端流程

```
排餐计划（唯一人工录入口，按档口 × 自然周存）
      │ 选需求周期（纯日期区间，全部餐次）
      ▼
采购计划（草稿：可增删改、可反复重新生成）
      │ ① 采购清单：把标准食材映射成商品
      │ ② 采购明细：逐天填预计采购量（每天每行必填；这天不买用「忽略（仅当天）」）
      │ ③ 发起询价（快照冻结，可多选供应商）
      ▼
询价单 V1（在途，N 家供应商）—— 发起即锁定，不可撤回 ——
      ├── 到达报价截止时间 ──► 已截止（未报价者置「超时未报价」）
      ├── 全部供应商已报价 ──► 已截止（提前，close_reason=全部报价）
      └── 定标 ──► 已定标（终态）

已截止 ──► （后续轮次）比价 / 定标 ──► 采购订单

【重来】询价中 / 已截止 / 已定标都不能撤回，采购计划不可解锁；
       只能另建一份同期采购计划重新发起（列表标「同期第 N 份」）
```

### 4.3 唯一性约束

| 约束 | 口径 | 标记 |
| --- | --- | --- |
| 采购计划唯一键 | **`档口 × 需求起始日 × 需求结束日`，同区间允许多份**（实现：`plan.id = '{from}~{to}'`，同区间再建时追加 `#2` / `#3` 并记 `seq`，落盘 key `pp:plan:v2:{档口}:{from}:{to}`，序号段为 `:#序号`）。**V2.0 去掉了餐次维度**，同区间多份计划之间互不覆盖，列表与详情标「同期第 N 份」 | 【已确认 D19 / Q4】【规则】 |
| 计划之间的区间重叠 | 不同区间可以重叠（如 10/20~10/22 与 10/21~10/26 并存），各自独立采购，仅提示不阻断 | 【已确认 Q4】【规则】 |
| 在途询价单唯一 | 同一采购计划下同时**最多 1 份**状态为「询价中 / 已截止 / 已定标未下单」的询价单 | 【已确认 D2】【规则】 |
| 询价单供应商数 | ≥ 1，可多选 | 【已确认 D2】【规则】 |
| 询价单版本 | **同一采购计划下若存在多张询价单，按 `version` 倒序只读展示**；不再因「撤回重发」产生新版本（询价单页签「历史版本」区） | 【规则】 |

> **V2.0 的变化 + V2.1 的修正**：v1 的唯一键里带「餐次集合」，导致同一区间、不同餐次可以并存多份计划。
> 去掉餐次（D19）后唯一键回到「档口 × 区间」；**同区间重复新建时不拦人**：先弹强提醒列出冲突计划，
> 确认后照建为新的一份并标「同期第 N 份」（见 6.3 / 12.1 #12）。
> **这条路径在 V2.1 变得关键**：询价单发起后不可撤回、采购计划不可解锁，
> 想让同一档口同一区间重新询价一次，**只能另建一份同期计划**（见 8.2）。

> **锁的粒度钉在「采购计划」上**，不钉在「档口 × 商品」或「档口 × 周期」。
> 多供应商是**询价单内部的收件人列表**，不是多张单子。
> 若将来要支持「按品类拆多份询价并行」，只需把锁粒度改为 `采购计划 + 品类分组`，不推翻本文档。

### 4.4 采购计划状态机（4 态）

```
草稿 ──发起询价──► 询价中（此后没有回退分支）
  │                  │
  │                  └──定标──► 已定标（终态）
  └──作废──► 已作废
```

| 状态 | 能否编辑明细 | 能否发起询价 | 说明 |
| --- | --- | --- | --- |
| **草稿** | ✅ | ✅ | 可重新生成、可增删改、可填量 |
| **询价中** | ❌（整页锁定，**不可解锁**） | ❌ | 存在在途询价单；要重来只能另建同期计划 |
| **已定标** | ❌ | ❌ | **终态**：不可撤回、不可再发起，也没有「取消定标」入口 |
| **已作废** | ❌ | ❌ | 终态 |

> 「已完成」（定标后生成订单）属后续轮次状态，本表不列。

### 4.5 询价单状态机（4 态）

```
[草稿] ──发起──► 询价中 ──报价截止时间到──► 已截止 ──定标──► 已定标（终态）
                    │
                    └── 全部受邀供应商已报价 ──► 已截止（提前，close_reason=全部报价）

发起后不可撤回：「询价中」「已截止」「已定标」都没有回退分支（见 8.2）
```

| 状态 | 含义 | 是否算在途 |
| --- | --- | --- |
| **草稿** | 尚未发出（发起前瞬时态，不落库为独立单据） | ❌ |
| **询价中** | 已发出，未到截止时间 | ✅ |
| **已截止** | 到达截止时间，或全部供应商已报价而提前关闭 | ✅ |
| **已定标** | 已有定标结果，**终态**（只读，无「取消定标」入口） | ✅ |

> 「提前截止」不是独立状态，仍是**已截止**，通过 `close_reason = 全部报价` 区分
> （取值：`到期` ｜ `全部报价` ｜ `人工关闭`）。
> **「已撤回」已从产品中去掉**：不存在这个状态，也没有任何动作能把询价单变成它。

### 4.6 供应商应答状态机（3 态，单据内每家一份）

```
待报价 ──报价──► 已报价 ──┐
   │                       ├──► 参与本轮比价 / 可被定标
   └──截止时间到未报价──► 超时未报价（本轮不参与报价、不配送）
```

| 应答状态 | 含义 | 后续 |
| --- | --- | --- |
| **待报价** `PENDING` | 已收到询价，未回价 | 截止前可继续报价 |
| **已报价** `QUOTED` | 已回价（提交 ≥1 行即算） | 参与比价，可被定标 |
| **超时未报价** `MISSED` | 截止时间到仍一行未报，**系统自动置位** | 本轮不参与报价、不参与定标、不产生配送；**不接受补报** |

> **「不配送」的准确语义**【规则】：不是惩罚，也不是拉黑 —— 只是这一轮询价该供应商自然出局，
> 因此本轮生成的订单里不会出现它。**下一轮询价仍可正常邀请它，不受影响。**

### 4.7 能否再发起新询价的判定矩阵

| 在途询价单状态 | 能否再发起新询价 | 说明 |
| --- | --- | --- |
| 无询价单 | ✅ | 正常发起 |
| 询价中 | ❌ | **已发起即锁死，不可撤回**；要重来只能另建一份同期采购计划 |
| 已截止 | ❌ | 截止 ≠ 结束；未定标前都在途，**同样不可撤回**。要重来只能另建同期计划 |
| 已定标 | ❌ | **终态**：不可撤回、不可再发起，也没有「取消定标」入口 |

> **超时未报价不会解除在途锁**【规则】：截止后询价单仍是「已截止」（在途），
> 而且**没有任何撤回入口** —— 要重来**只能另建一份同期采购计划**（见 8.2）。
> 这样才不会出现「超时了 → 同一份计划再发一份 → 供应商端同时存在两份询价单」的漏洞。

### 4.8 锁判断口径（给研发）

```
发起询价前：
  if (plan.inquiries.some(x => ['inquiry','closed','awarded'].includes(effStatus(x))))
      block('该计划已有询价单，不能再发起')
```

> 锁**永不解除**（没有任何撤回入口）：命中即阻断，重来只能另建一份同期采购计划。

## 5. 与排餐计划的衔接

### 5.1 上游数据形态

排餐计划按 **档口 × 自然周** 落盘：

| 数据 | 形态 |
| --- | --- |
| `schedule[星期索引][餐次]` | 菜谱 ID 数组 |
| `pots[日期\|餐次\|菜谱ID]` | 锅数 |
| `activeDays` | 该周哪些天启用排餐 |

### 5.2 取数口径（对齐菜谱 v2.0）**【已确认 D12】【规则】**

| 口径 | 值 | 出处 |
| --- | --- | --- |
| **用料单位** | **统一为「克」**，含液体类；不再有毫升 / 升 / 千克 / 个 | v2.0 C7 / Q2 |
| **取数范围** | **只取「烹饪投料（计入）」段**；过程用料不参与任何下游测算 | v2.0 §3.2 / §7.1 |
| 用料对象 | 平台标准食材 **或** 商品 SKU（仅已发布且启用） | v2.0 C3 / §3.4 |
| 合并键 | 标准食材按食材名；商品 SKU 按 SKU 编码；液体 / 粉末按名称 | v2.0 §4.4 |
| 精度 | 两位小数；单步用量上限 9999.99 克 | v2.0 C8 / §4.6.3 |
| 数据形态 | 用料明细是加工步骤的**派生只读表**，不是独立录入数据 | v2.0 C2 |

采购侧取数公式：

```
某用料本次用量（克） = 该用料在菜谱里的「投料量（克，仅计入部分）」 × 该菜锅数
```

> **采购侧不引入任何新系数、不做单位换算** —— 上游给的已经是克，汇总出来还是克。
> 采购计划的职责只有一件事：**告诉采购员这些天这些用料一共多少克（并且每天各多少克）**；
> 买什么商品、按什么规格单位买、买多少，由采购员决定。
>
> 注意区分两个「换算」：本节说的是**上游单位归一**（v2.0 已把 ml/个 统一成克，采购侧沿用它、不再二次换算）；
> 7.4 / D14 说的是**克 → 商业包装**的折算（箱/袋/桶），那个系统完全不参与。

### 5.3 周期选择器

**必须支持跨周区间** —— 排餐按周存，采购按任意日期区间取，二者粒度不同：

```
采购周期：10/20(周二) ~ 10/26(周一)
  → 拆成两个排餐周：10/19 周一那周 + 10/26 周一那周
  → 逐日取数据（全部餐次，不筛餐次）
```

| 元素 | 设计 | 标记 |
| --- | --- | --- |
| 主输入 | 开始日期 ~ 结束日期，默认「本周一 ~ 本周日」 | 【原型】 |
| 快捷项 | 本周整周 / 明天 / 今天起 3 天 / 本周剩余 / 自定义 | 【原型】 |
| ~~餐次~~ | ~~全部餐次 / 多选~~ **作废（D19）**：采购计划**恒取该档口区间内全部餐次**，界面上不出现餐次选择 | 【已确认 D19】【规则】 |
| 上限 | 区间 ≤ **31 天**，防误选整年，超出阻断 | 【建议】【规则】 |
| 重叠 | **允许**与其他采购计划区间重叠，发起询价时仅提示、不阻断 | 【已确认 Q4】【规则】 |
| 同区间重复 | 同档口同区间**允许多份计划**：再次新建时先弹强提醒列出冲突计划，确认后照建并标「同期第 N 份」（见 4.3 / 6.3） | 【规则】 |

> **为什么去掉餐次**（D19）：采购要买的是「这一天全部餐次的料」。让用户勾餐次既多余（默认就得全选，
> 否则漏买），又会把唯一键复杂化。餐次概念只保留在排餐计划里。

### 5.4 范围预览（「框定这些天要做的菜」）**【规则】**

选完范围后，页面必须先给出预览带，再生成清单：

```
本次范围：10/20 ~ 10/26（全部餐次）
命中 5 天 / 7 天 · 共 45 道次 · 其中 2 天无排餐（10/25、10/26）
```

> **必须有这一层**【规则】：区间内可能「这天排餐了但没排菜」「这天计划根本没建」。
> 不显式提示，采购员会误以为漏算，反而手工加行补量 → 重复采购。

### 5.5 范围 → 材料派生规则**【规则】**

1. 区间内每一天 → 找到该日所属排餐周（`monday(date)`）→ 读该档口该周计划；
2. 该日不在 `activeDays` 内 → **整日跳过**；
3. 遍历该档口**全部餐次**（`meals()`；为空时回退 `['午餐']`），该餐次无菜 → 跳过；
4. 每道菜按 `锅数` 展开用料（锅数为 0 / 空 → 跳过），**只取「烹饪投料（计入）」段**，过程用料不取；
5. 计算出克数 ≤ 0 的项**不产生依据条目**；
6. 按合并键汇总成**材料行**（标准食材按食材名 / 商品 SKU 按 SKU 编码），每行携带 `basis[{date, meal, recipe, pots, gram}]`；
7. **只取已保存的排餐**（【沿用】）；未保存改动下游不可见；
8. 历史日期按已保存内容算，不随时间变化（【沿用】）。

### 5.6 聚合与按天切片示例（单位：克）

周一午餐：宫保鸡丁 2 锅、红烧肉 1 锅、番茄炒蛋 2 锅（均为「计入烹饪投料」）

| 材料行（合并键） | 挂的是 | 宫保鸡丁 | 红烧肉 | 番茄炒蛋 | **周一合计（克）** | 采购清单里这一行 |
| --- | --- | --- | --- | --- | --- | --- |
| 鸡胸肉 | 标准食材 | 7200×2 | — | — | **14400** | 待映射 → 选「冷鲜鸡胸肉」 |
| 五花肉 | 标准食材 | — | 9000×1 | — | **9000** | 待映射 |
| 鸡蛋 | 标准食材 | — | — | 2600×2 | **5200** | 待映射 |
| 生抽 | **商品 SKU** | 400×2 | 1200×1 | — | **2000** | 直接带入 SKU「海天生抽 500ml×12」 |
| 食盐 | 标准食材 | — | — | 80×2 | **160** | 待映射（也可忽略） |
| 食用油 | **商品 SKU** | — | — | 300×2 | **600** | 直接带入 SKU「一级大豆油 5L×4/箱」 |

该表演示五件事【规则】：

1. **两种来源类型**：生抽 / 食用油走 SKU 直挂（进「已直挂商品」卡），其余走标准食材待映射（进「标准食材」卡）；
2. **跨菜合并**：生抽 800 + 1200 = 2000 克汇成一行材料行；
3. **单位恒为克**，采购侧**不做任何换算**（见 7.4 / D14）；
4. **克数只是依据**，「预计采购量」才是采购员按天填的内容；
5. **同一批数据按天切开就是采购明细**：若周二午餐做同样的菜，则
   采购清单里鸡胸肉显示「合计 28800 克」，采购明细里是「周一 14400 克」「周二 14400 克」两个 tab 各一行。
   **数据只有一份（`items[].basis`），采购明细只是按 `date` 分组后的视图**（见 7.3）。

### 5.7 上游口径对齐前提**【规则】**

采购计划按 v2.0 取数（克 + 只取计入），但现有排餐原型种子 BOM 仍是 v1.0 形态：

| 差异 | 现状（v1.0） | v2.0 要求 | 对采购的影响 |
| --- | --- | --- | --- |
| 单位 | `g` / `ml` 混用（食用油 300 `ml`） | 统一克 | 汇总会串单位 |
| 计入开关 | 没有 | 每步骤有「计入烹饪投料」 | 过程用料被算进采购量 → **直接多买** |
| 用料明细 | 可独立录入的 BOM 数组 | 加工步骤的派生只读表 | 取数入口不同 |

> **【已确认 Q10】**：商户端只读的用料明细**随 v2.0 一并同步**（单位统一克 + 增加「计入烹饪投料」）。
> **采购侧不做任何临时折算**（如「毫升按 1:1 折克」这类隐含假设不允许出现）。

## 6. 信息架构

### 6.1 菜单结构**【已确认 Q11】**

```
计划管理
├─ 排餐计划          已有 · 单页 + 周切换
├─ 生产计划          已有 · 单页 + 日切换
└─ 采购计划          新增
     ├─ ① 列表页    本档口的采购计划
     └─ ② 详情页（三个并列页签）
          ├─ 页签一「采购清单」   映射层：标准食材 → 商品 SKU，不填量
          ├─ 页签二「采购明细」   按天层：一天一个 tab，按天覆盖商品 + 按天填量
          └─ 页签三「询价单」     发起 / 回价 / 定标（发起后不可撤回）
     （详情页底部常驻）重新生成 · 报价比较 · 发起询价

（未来，本期不做）采购管理
├─ 询价单列表   ← 跨计划的待办视图（催报价 / 回价跟踪）
└─ 采购订单
```

| 规则 | 口径 | 标记 |
| --- | --- | --- |
| 采购计划位置 | 计划管理下第三个二级项 | 【已确认 Q11】【规则】 |
| 询价单 | **不单独开菜单**，为采购计划详情页的**第三个**页签 | 【已确认 Q11】【规则】 |
| 菜单项总数 | 计划管理下依次为「排餐计划 / 生产计划 / 采购计划」，**没有独立的「询价单」菜单** | 【规则】 |
| 报价比较 | **不占菜单、不占页签**，是详情页上的一个抽屉（底部操作栏 + 询价单页签各一个入口） | 【已确认 D18】【规则】 |

**为什么采购计划放「计划管理」**：它是排餐计划的直接派生，与生产计划同一上游、同一套范围切换器；排餐（需求）→ 生产（执行）/ 采购（补给）在既有文档里本为一组。

**为什么询价单不单独开菜单**：

1. 它与采购计划是 **1:1 在途关系**（4.3 的锁）—— 不存在「多份并列管理」的需求；
2. 同一份计划的询价单（含历史上存在过的其它版本）天然属于这份计划，放在计划里看上下文最完整（哪份计划、哪一轮、截止了没有、定了标没有）；
3. 单独开菜单会出现两个入口，都要先切档口再找计划，**多一层跳转却不增信息**；
4. 询价单的对外性与采购订单同族，真要独立列表应归到「**采购管理**」，属下一轮跨计划待办视图。

### 6.2 为什么需要列表页**【已确认 Q12】**

排餐是「一档口一周一份」，单页 + 周切换器够用。采购计划周期是**任意日期区间**，同档口天然并存多份：

```
档口 A：10/20~10/24（已询价）· 10/25~10/31（草稿）· 10/20~10/24 同期第 2 份（重来用的新计划）
```

这些区间互相重叠，**无法用一个「当前周期」表达**，必须有列表。列表默认按当前范围（组织 / 档口）过滤。

> **演进口子**【规则】：将来若需「跨计划看哪些询价快截止了」，在「采购管理」下加「询价单」列表（与采购订单并列）。
> 本轮不做，但数据形态不阻碍 —— 询价单数据本就在 `pp:inq:*` 里，换个入口读即可。

## 7. 采购清单与采购明细的规则

### 7.1 两个页签的分工（谁在哪里改什么）**【已确认 D15 / D17】【规则】**

V1.x 是「一张明细表同时承担映射和填量」，V2.0 拆成两层：

| | 采购清单（页签一） | 采购明细（页签二） |
| --- | --- | --- |
| 一行是什么 | 一个材料行（跨全部日期） | 某天 × 某材料行 |
| 克数口径 | **整段区间合计** | **当日用量** |
| 映射 | ✅ **全局默认**，作用于所有日期 | ✅ **可以按天覆盖**（只影响当天） |
| 预计采购量 | ❌ 不填 | ✅ **只在这里填，粒度 = 天** |
| 手工加行 | 在采购明细里加（归属某一天） | ✅ |
| `报价比较` 入口 | ✅ 底部操作栏 | ✅ 底部操作栏 |
| `发起询价` 入口 | ✅ 底部操作栏 | ✅ **底部操作栏（就地发起，不必切回清单）** |

> **为什么映射和填量必须分开**：映射是一次性决策（这个东西到底买哪款，管全程），
> 填量是逐日决策（今天买不买、买多少）。混在一张表上，用户会在选完商品后才发现量不对、回头再改，两个决策互相打断。

### 7.2 采购清单：全局映射**【已确认 D9 / D17】【规则】**

#### 7.2.1 材料行的粒度

材料行 = **合并键**（标准食材按食材名 / 商品 SKU 按 SKU 编码），跨菜、跨天合并。

| 场景 | 处理 |
| --- | --- |
| 菜谱用料挂 **商品 SKU** | 直接带入该 SKU，进「已直挂商品（无需选择）」卡，采购员**无需任何操作** |
| 直挂 SKU 想某天换一款 | **允许**：直挂的 SKU 只是**默认值**，到「采购明细」某一天点「更换商品（仅当天）」即可临时改成别的商品（例如当天改用另一家到货），其余天不受影响。**这是有意设计，不是漏改**（D9 补充） |
| 菜谱用料挂 **标准食材** | 进「标准食材（需选商品）」卡，红标「待选择」，**必须映射**才能发起询价 |
| 同一标准食材出现在多道菜 / 多天 | 合并为 1 行，**映射一次即可**，不用逐个选 |
| 同一标准食材要买两种商品（自来水 + 矿泉水） | 靠「按天覆盖」拆开：默认买自来水，某天单独指定矿泉水（见 7.3） |
| 不需要买 | 直接「忽略」该行（软删除，重新生成时保留） |

#### 7.2.2 商品选择与记忆

| 项 | 口径 |
| --- | --- |
| 记忆 | 在采购清单里选一次，按 `档口 × 标准食材` 记住（`pp:ingmap:v1:{档口}`），下次自动带出 |
| 候选范围 | 该档口所属**次级组织的私域商品**，已发布且启用；候选按「关联标准食材」筛选，同商品多个 SKU 时全部列出（名称 / 规格 / 下单单位） |
| 可改 | 可随时更换；**换商品后该行已有的按天数量数值保留**，单位跟随新商品 |
| 未映射能否发起询价 | **不能**，阻断并列出未映射的食材名（见 7.8 #2） |
| 无候选商品 | 提示「商品库中没有关联该食材的可用商品」，可去商品中心建，或忽略该行 |
| 按天覆盖不影响记忆 | 按天覆盖只写 `daily[date][key].skuCode`，**不写进 `pp:ingmap`**，因此不会污染其它计划 |

> **这条规则承接 D5**：`饮用水` 是标准食材 → 系统不知道你要自来水还是农夫山泉 →
> 采购员在这一行映射「自来水（按吨）」或「农夫山泉 550ml×24（箱）」。
> **一个「选商品」的动作，把自采判断也一并解决了。**
>
> **不再需要的旧机制**【规则】：毛净率、形态系数、投料状态推断、三层形态策略（菜谱指定 / 系统推断 / 人工选定）
> 对本轮**均不适用** —— 形态已内含在所选 SKU 里。

#### 7.2.3 「N 天已单独指定」标记

若某材料行的商品在部分日期被单独覆盖（`daily[date][key].skuCode ≠ item.skuCode`），
采购清单里在该行食材名后挂「**N 天已单独指定**」。

| 项 | 口径 |
| --- | --- |
| 标记含义 | 这行有 N 天用了别的商品，全局映射**只对剩余的天生效** |
| 是否阻断 | 不阻断，只是提示 |
| 怎么撤销 | 到采购明细对应日期点「恢复默认」，该天回到全局映射 |
| 例外天数口径 | 只统计**该行有料的天**里有覆盖的天数（`daysOf` 内） |

### 7.3 采购明细：按天覆盖与按天填量**【已确认 D16 / D17】【规则】**

#### 7.3.1 日期 tab

| 项 | 口径 |
| --- | --- |
| tab 内容 | `MM-DD 周X`，横向可滚动（区间上限 31 天） |
| 哪些天出 tab | **只出有料的天**：① 该天有排餐用料（当日克数 > 0）② 该天有手工行。两者皆无 → **不出 tab** |
| 默认选中 | 「今天」；今天不在区间内或当天没料 → 落**第一个有料的天** |
| 无料但区间内 | 空 tab 不存在，因此不会出现「点进去一片空白」的困扰 |
| 整段区间都无料 | 整页空态：「这段区间没有可用用料，可能区间内没有排餐，或排餐未保存」 |

#### 7.3.2 当天明细表

| 列 | 性质 | 说明 |
| --- | --- | --- |
| 商品（当日生效） | 只读 | `skuOfDay(item, date)` = 当日覆盖优先，否则全局映射。未映射 → 食材名红字 + 「待映射」 |
| 规格 / 下单单位 | 只读 | 取当日生效 SKU |
| **当日用料（克）** | 系统算、**只读** | `gramOfDay(item, date)`；手工行显示 `—` |
| **预计采购量** | **人填、必填** | 按该商品当日下单单位填写；**每天每一条有商品的行都必须填**，表头带红色 `*`、placeholder「必填」、空值浅红边框；某天不买 → 点该行「忽略（仅当天）」，**不是留空**；未映射时输入框禁用 |
| 操作 | 可写 | 更换商品（仅当天） · 恢复默认 · 忽略（仅当天） |
| 「更换商品（仅当天）」的适用面 | **所有行都提供**（含菜谱直挂 SKU 的行与手工行） | 直挂 SKU 只是默认值，按天临时换商品是正常业务（D9 补充） |

| 项 | 口径 |
| --- | --- |
| 行的范围 | **只列当天有料的材料行**（+ 当天手工行），按当日克数倒序。不是把 25 个商品全列出来 |
| 表尾合计 | 当日用料克数合计 + 「**已填 X/Y 项**」（Y = 当天有商品的行数；**X < Y 时数字转橙色**；表尾行，**不是统计卡**） |
| 必填语义 | **必填**：任意一天任意一条有商品的行没填量 → 发起询价时**阻断**（见 7.8 #3）。**留空不再表示「这天不买」**，也无法与「忘了填」区分 |
| 输入约束 | `min=0 step=0.01`；负数/非数字 → 归 0（0 视为「没填」） |
| 按天覆盖 | 点「更换商品（仅当天）」→ 只写当天，其余天仍用全局映射；有覆盖时该行出现「恢复默认」 |
| 手工行 | 点「＋ 手工加行（加到这一天）」→ 加一个 `source='manual'` 的行，**归属当前日期**；手工行清空数量也不消失，只能显式「删除」，**它同样计入必填校验** |
| 忽略 | 点该行「**忽略（仅当天）**」→ 该行**当天**不参与采购与询价（不计入必填），其余天照常；误点可恢复（见 6.5 卡3） |

> **为什么改成必填**（D10 / D16）：留空和「忘了填」系统分不出来；一旦允许留空，
> 「这天该买但漏填」就会以「这天不买」的形态悄悄进询价单。所以每天每条有商品的行都必须填，
> **这天真不买请用「忽略（仅当天）」** —— 它是明确的动作，可恢复。
> **校验口径**：任意一天任意一条没填就阻断（不再有「某商品所有天都留空才阻断」这种口径）。

> **为什么不做「按合计平均分摊到每天」**：那是换算，而且分摊出来的数是假的
> （哪天用多少取决于排餐，不是平均值）。系统只提供克数与填写位，不给分配建议。

#### 7.3.3 询价数量怎么来

询价单的每行数量 = **该商品在所有天、所有映射到它的材料行上的数量之和**：

```
quantity(商品) = Σ(date ∈ 有料的天) Σ(item: skuOfDay(item, date) == 商品) qtyOfDay(item, date)
byDate(商品)   = [{ date, qty, gram }]   ← 只含有量的天，按日期升序
```

| 项 | 口径 |
| --- | --- |
| 商品归集 | 按**当日生效 SKU** 归集；同一材料行在某天被覆盖成另一个 SKU → **自然拆成两行商品** |
| 数量为 0 的商品 | **不进入询价单**（`qty <= 0` 跳过） |
| 按天需求 | 随行写入 `byDate`，在询价单明细上以「按天需求：10-20 2箱 · 10-21 3箱」展示（D20） |
| 克数 | 行上同时带合计克数（`gram`），只作信息，不参与计算 |

### 7.4 不做任何单位换算**【已确认 D14】【规则】**

**系统不把克折成箱 / 袋 / 桶，一格都不折。** 这是本轮明确的产品判断，不是尚未实现。

```
菜谱投料量（克，仅计入）× 锅数  →  当日 / 合计用料（克）  →  ？？？
                                                            ↑ 这一步系统不参与，
                                                              采购员看克数自己决定
```

| 项 | 口径 |
| --- | --- |
| 用料单位 | **恒为克**，不折算、不进位、不换单位；**不得出现 ml / L / kg** |
| 预计采购量单位 | **永远是该商品的下单单位**（箱 / 袋 / 桶 / 吨） |
| 克 → 商品单位的折算 | **系统完全不提供**：不显示「≈3.2 箱」、不给建议值、不进抽屉、不进表格、不进提示 |
| 商品主数据 | **不再维护「每下单单位多少千克」这类换算基数** —— 见下 |
| 液体 / 粉末 | 同样按克（v2.0 已覆盖液体） |
| 计量精度 | 两位小数，去无意义尾零；与菜谱侧一致 |
| 校验 | 不存在「换算关系缺失」这类校验，因为**根本不做换算** |

**为什么不换算（写进 PRD 的理由）**【规则】：

| # | 原因 |
| --- | --- |
| 1 | **包装重量不固定**：同为「10kg/箱」，散装、冰衣、毛净差异会让实际净重差出 10%–20%；按基数折算出来是**错的**，而错了比没有更危险 —— 采购员会照着系统给的数下单 |
| 2 | **克是"用量事实"，箱/袋是"商业包装"**，两者之间没有可靠换算关系。真实决策还要考虑损耗、余量、起订量、库存，这些系统都不掌握 |
| 3 | **显示折算值会形成隐性承诺**：一旦系统给出「≈3.2 箱」，用户会默认这是系统算过的，出错由系统背；不给，责任与判断都在采购员，符合后端采购的实际作业方式 |
| 4 | 用户原话：**「功能内去掉所有帮助用户换算的内容，实际情况是没法换算。具体实际要买多少，用户依据克数，自行思考决定采购的量和规格单位」** |

> **所以商品库/商品主数据里要去掉的字段**：任何形如「每下单单位 = X 千克 / 毫升 / 个」的换算基数。
> 保留的是 SKU 自身的**规格描述**（如「10kg/箱」，它是包装标识，不是换算关系）与**下单单位**。

### 7.5 报价比较（唯一的看价入口）**【已确认 D18】【规则】**

明细表**不再有任何价格列**（v1 的「行 × 供应商」参考价列已作废），所有价格信息在报价比较抽屉里看。

| 项 | 口径 |
| --- | --- |
| 入口 | 详情页底部操作栏 + 询价单页签，各一个「报价比较」按钮 |
| 数据源 | 该计划**版本号最大**的那张询价单（在途 / 已截止 / 已定标都可看） |
| 无询价单 | **按钮 disabled**，title「请先发起询价单，再比较报价」 |
| 行 | 询价单明细里的商品（即 `qty > 0` 的生效商品） |
| 列 | 该询价单**实际受邀**的供应商（不是全量供应商池） |
| 缺价显示 | 未报价 / 超时未报 → `-`（弱化样式） |
| 最低价 | 每行最低价绿底高亮；同价并列都高亮；该行无任何报价则不标 |
| 覆盖率 | 每家表头副行显示「已报 M/N 项」（**实际回价**，不是预报价） |
| 只读边界 | **只展示、不出结论、不能选中标供应商**；比价与定标不在本期范围 |

> **为什么把参考价列整个删掉**（D11 → D18）：行 × 供应商展开成列，列数随供应商数量膨胀；
> 而且必须先选供应商，否则整列不可用 —— 用户在"还没决定邀请谁"的时候就被迫先选。
> 改成一个抽屉后，明细表回到纯粹的清单形态，看价变成一个明确的主动动作。

### 7.6 材料行与数量的增 / 删 / 改**【规则】**

| 动作 | 在哪做 | 设计 | 要点 |
| --- | --- | --- | --- |
| **增（映射）** | 采购清单 | 给待映射的标准食材选商品 | 选一次全局生效，并按「档口 × 标准食材」记忆 |
| **增（手工行）** | 采购明细 | 「＋ 手工加行（加到这一天）」：选商品 → 选 SKU → 填数量 | `source='manual'`，**归属当前日期**，无排餐依据（当日用料显示 `—`） |
| **删（忽略）** | 采购明细 | 软删除：点该行「忽略（仅当天）」，标记该行当天 `ignored`，**重新生成时保留** | D5 的主要消费口：水 / 盐不需要买 → 直接忽略。忽略的行当天不参与采购与询价，也不计入必填；**采购清单里不提供「忽略」按钮，只提供「恢复」** |
| **恢复（反忽略）** | 采购清单 | 卡3「已忽略」里的「恢复」 | 误点后不必重建计划 |
| **删（手工行）** | 采购清单 / 采购明细 | 真删除该材料行 | 只有 `source='manual'` 的行能删 |
| **改（映射）** | 采购清单 | 换商品 | 数量数值保留，单位跟随新商品 |
| **改（按天覆盖）** | 采购明细 | 更换商品（仅当天）/ 恢复默认 | 只影响当天；写入 `daily[date][key].skuCode` |
| **改（数量）** | 采购明细 | 按天填/改预计采购量 | 人填的值，**不另打「人工调整」标**；**必填**，某天不买请用「忽略（仅当天）」而不是留空 |

> **必须两边一致的点**：忽略标记与手工行由两个页签共享同一份 `plan.items`，任一侧改动另一侧立即可见。

### 7.7 重新生成**【规则】**

| 项 | 口径 |
| --- | --- |
| 触发 | **手工点「重新生成」**；排餐变更后**不自动重算**（快照思路），只在顶部提示「排餐计划已变更」 |
| 保留 | 人工添加行、忽略标记、**全局映射（已选商品）**、**按天覆盖**、**所有已填的按天数量** |
| 新增 | 排餐变化带出的新材料行 → 映射与数量都是空的，待处理 |
| 清理 | **`pruneDaily()`**：删掉指向「已消失材料行」的按天记录（含数量与覆盖），并清掉空掉的日期节点。**不清理仍存在的材料行** |
| 手工行 | **永远保留**（没有 basis，不参与 `sigOf`，不会被判定为"消失"） |
| 复核提示 | 某材料行的合计克数变了 → 派生签名（`sig`）不一致 → 顶部提示可重新生成，**但不自动改人填的数量** |
| 幂等 | 连续点两次重新生成，结果一致（除 `updated` 时间） |

> **为什么标「依据已变更」而不自动改量**：量是人拍的，系统擅自改等于替人做决定；
> 但完全不管又会让采购员漏掉「排餐翻倍了但量还是老数」的风险。标出来、让人复核。

### 7.8 发起询价的校验（两类，分开放）**【规则】**

校验按「求值时点」分成**两类**，这是本节的核心规则：

| 类别 | 求值时点 | 表现 | 放哪些 |
| --- | --- | --- | --- |
| **A. 计划状态类** | **渲染期**（`launchErrors(plan)`，只依赖计划自身数据） | 一进页面就该拦住 → 抽屉顶部一次性列出全部问题，**「确认发起」按钮 disabled** | 清单是否就绪、映射是否完成、数量是否填过 |
| **B. 抽屉输入类** | **提交期**（点「确认发起」的回调里逐项校验） | 用户还没操作的字段**不能**算进 A 类，否则按钮会先灰掉、用户填完又不会重新求值 | 供应商选择、报价截止时间 |

#### 7.8.1 A 类：计划状态类（渲染期就拦住）

| # | 校验 | 说明 |
| --- | --- | --- |
| 1 | 采购清单为空（没有任何材料行） | 「采购清单为空，无法发起询价」 |
| 2 | 存在**未映射**的标准食材行（`source='ing'` 且 `skuCode` 为空），忽略行不计 | 「还有 N 项标准食材未选择商品：xxx、yyy…」—— **只列前 5 个食材名 + 「等」，不得把二十几个名字全铺出来**，否则一条提示就能把抽屉撑爆 |
| 3 | **预计采购量没填满**：任意一天、任意一条**有商品**（当日生效 `skuCode` 非空）的行 `qty` 为空或 ≤ 0 | 「预计采购量为必填：还有 N 项没填（10-22 饮用水（自来水）、… 等），涉及 M 天）」—— **只列前 5 项 `日期 + 商品名` + 「等」，不得把全部项铺开**（N = 没填的（行 × 天）条数，M = 涉及的天数） |
| 4 | 没有任何可询价的商品（`effectiveSkuCodes` 为空） | 「没有任何可询价的商品」 |

> **A 类只判"计划自己准备好没有"**。它必须是**纯函数**（只读 `plan`），这样同一份计划在采购清单和采购明细两个页签底部都能得到一致的结论。

#### 7.8.2 B 类：抽屉输入类（提交时才校验）

| # | 校验 | 说明 |
| --- | --- | --- |
| 5 | **未选供应商** | 「请至少选择 1 家供应商」。**这条绝不能挪进 A 类** —— 见下面的理由 |
| 6 | 未填报价截止时间 / 截止时间 ≤ 当前时间 | 见 8.3 / 8.4 |
| 7 | 存在在途询价单 | 「该计划已有询价单，不能再发起」（在点「确认发起」时拦，文案不带单号） |
| 8 | 与另一份采购计划周期重叠 | ⚠️ 提示不阻断。提示位置在**「新建采购计划」的范围预览**里，发起询价时不再重复提示 |

> 🔑 **为什么「供应商」不能进 A 类**（原型里踩过的坑）：`plan.supplierIds` 只有**发起成功后**才会被写入，
> 而「发起询价」抽屉**每次打开只求值一次**。若把「至少选 1 家供应商」算进渲染期的阻塞项，
> **首次发起时按钮会一进来就置灰，而勾选供应商又不会触发重新求值** —— 用户永远点不下去，流程直接卡死。
> 所以它属于"用户还没做的输入"，只能在提交时校验。

> 拒发提示的呈现：A 类在抽屉顶部整段列出；B 类用即时 toast（如「请至少选择 1 家供应商」「请填写报价截止时间」）。

**明确不是校验项的三件事**【规则】：

1. **预报价有没有、覆盖多少，都不阻断发起询价** —— 预报价只是供应商端的报价默认值，不是准入门槛；
2. **不对「量与克数是否匹配」做校验** —— 系统不做任何单位折算（7.4 / D14），填多少由采购员判断；
3. **不存在「换算关系缺失」这类校验** —— 系统不做任何单位折算（见 7.4 / D14），自然没有换算前置条件。

### 8.2 发起即锁定与「重来」的唯一出路（需求第 2 条的落地）

**发起即锁定**【规则】

1. 询价单一经发起就**不可撤回、不可修改**：「询价中」「已截止」「已定标」三个阶段**都不提供撤回入口**，已定标是终态；
2. 采购计划随之锁定，而且是**永久锁定、不可解锁** —— 采购清单与采购明细整页只读（见 6.4「锁定态」）；
3. 因此页面上**没有撤回按钮、没有撤回原因输入、没有撤回二次确认**；
4. 供应商已收到的报价全部保留（不置作废），随询价单一起只读留痕。

**要重来怎么办**【规则】

1. **只能另建一份同期采购计划，重新发起一份新的询价单** —— 同一档口同一区间允许并存多份计划：新建时弹强提醒列出冲突计划（见 6.3 / 12.1 #12），确认后照建，列表与详情标「**同期第 N 份**」；
2. 新计划是一份**独立的计划**，它自己的询价单 `version` 从 1 开始；**不会因为「重来」在原计划下产生 V2**；
3. 原计划与原询价单永久保留、只读，报价记录仍可在「报价比较」里查看（追溯上一轮各家报了多少）；
4. 新计划可以重新选供应商（换一批人问，不必沿用上一轮），也可以改映射与填量。

> **为什么彻底去掉撤回**：撤回会让「一份计划对外只有一份口径」这个前提变成可逆操作 ——
> 撤一次就能改数量重发、再撤一次再重发，供应商端同时存在多份口径，事后也分不清哪一版是对外承诺。
> 改成「另建计划」后，旧单据作为**不可变的事实**留在原地，新的意图用**新单据**表达，两条线各自可追溯。

### 8.3 报价截止时间怎么设**【已确认 D6】【规则】**

| 项 | 口径 |
| --- | --- |
| 必填性 | **必填**，发起询价时校验 |
| 默认值 | 发起时刻 **+24h**（可改） |
| 快捷项 | 今日 18:00 / 明日 12:00 / 明日 18:00 / 自定义【原型】 |
| 下限 | 必须晚于当前时间（建议 ≥ 1h，太短供应商来不及） |
| 上限 | 建议 ≤ 7 天，防忘记截止 |
| 展示 | 商户端与供应商端显示同一时刻的「剩余 X 小时 Y 分」 |

### 8.4 到期时的三种情况**【规则】**

| 情况 | 判定 | 询价单 | 后续 |
| --- | --- | --- | --- |
| **全部报价** | N/N 家已回价 | 自动 `已截止`（`close_reason = 全部报价`），**不必等截止时间** | 直接进入比价 / 定标 |
| **部分报价** | M/N 家回价 | 到点 `已截止`（`close_reason = 到期`）；已回价的继续有效 | 未回价者置 `超时未报价`，**本轮不配送**，不阻断定标 |
| **无人报价** | 0/N 家回价 | 到点 `已截止`（`close_reason = 到期`），全部置 `超时未报价` | **无法定标，也无法撤回**；要重来只能另建一份同期采购计划重新发起（可换供应商、重设截止时间） |

### 8.5 超时未报价的处理规则**【已确认 D6】【规则】**

1. **系统自动置位**，无需人工操作：`now > reply_deadline` 且 `answer_status = 待报价` → `超时未报价`；
2. **不接受补报价**：截止后仍回价的请求直接拒绝，供应商端该询价单转为只读「已超时」；
3. **不参与比价、不参与定标**：人工也无法选中它 —— 这是「不配送」的落地方式；
4. **不产生任何惩罚性数据**：不记违约、不拉黑、不影响下轮被邀请；
5. **留痕**：询价单详情永久展示「3 家报价 / 2 家超时未报价（XXX、YYY）」；
6. **不影响在途锁**：超时未报价**不会**关单、**也不会**解除锁定，锁永久在（没有撤回入口）；要重来**只能另建一份同期采购计划**（见 8.2）。

### 8.6 截止前催报价（必做）**【已确认 Q5 连带】【规则】**

| 项 | 口径 |
| --- | --- |
| 触发 | 截止前 **2 小时**，仍未报价的供应商 |
| 方式 | 站内待办 + 角标（不做短信 / 微信【沿用】） |
| 频次 | 每份询价单每家最多 1 次 |
| 记录 | `notified_at` |
| 不做的情况 | 该供应商已提交过部分报价 → 不催（避免打扰已在推进的人）；已标记「整行不供」者亦不催（该功能为可选能力，见 8.9） |

> **为什么是必做**：截止时间不能延长（8.7），催报价是唯一的补救手段。

### 8.7 截止时间不可延长**【已确认 Q5】【规则】**

**截止时间属不可变快照的一部分，一旦发起即锁死。**

| 项 | 口径 |
| --- | --- |
| 截止前 | **不允许**改 `reply_deadline`；页面**没有延长入口，也没有撤回入口** |
| 截止后 | 更不允许 |
| 唯一出路 | **另建一份同期采购计划重新发起**：新计划的新询价单自己重新设截止时间，旧单只读留痕（见 8.2） |
| 理由 | 延长会破坏「一份询价单一个对外口径」的前提，也给了"先发出去再拖延"的操作空间 |

> **连带要求**【规则】：既然不能延长，**8.6 催报价为必做**；
> 且 **8.5 第 6 条（超时不解除锁）为硬要求** —— 否则在同一份计划下就能再发一份，等于变相延长。

### 8.8 部分报价**【已确认 Q7】【规则】**

供应商实务上常只供某一类货（肉类 / 蔬菜 / 调料），不可能每行都报：

| 项 | 口径 |
| --- | --- |
| 报价粒度 | **按行报价**，可分批保存草稿 |
| 「已报价」判定 | 截止时**已提交至少一行有效报价** → 算 `已报价`（不要求报全） |
| 未报的行 | 视为该供应商对该商品无报价，该行少一个候选，**不算超时** |
| `超时未报价` 判定 | **一行都没报**才算，整家出局 |
| 展示 | 询价单上标「部分报价 3/10」，不阻断 |
| 对定标的影响 | 定标粒度是**行/品类**，不是整单选一家 → 部分报价天然可用 |

> **供应商侧不要求做「一键不供」的强制标记**（可选提供，便于表达"这类我不做"）。

### 8.9 供应商端报价交互（口径定稿，界面下一轮）

本轮不做供应商端页面，但口径必须先定，否则询价单发出去没人能高效回价。

```
询价单 XJ20261022-001 · 报价截止 10/23 12:00（剩余 18h）
┌────────────────────────────────────────────────────────────┐
│ 商品      数量/单位   预报价      我的报价     状态         │
│ 鸡胸肉    14,400 克   ¥12.00/kg  [¥12.00]   来自预报价     │
│ 五花肉     9,000 克   ¥18.50/kg  [¥18.50]   来自预报价     │
│ 土豆       3,600 克    —          [      ]   待填写       │
│ 食用油       600 克   ¥8.00/kg   [¥8.60]    已调整       │
├────────────────────────────────────────────────────────────┤
│ [全部按预报价填写]  [批量调价 ±%]  [整行不供]  [保存草稿]  [提交报价] │
└────────────────────────────────────────────────────────────┘
```

| 元素 | 口径 | 标记 |
| --- | --- | --- |
| 预填 | 有生效预报价 → 预填，标「来自预报价」 | 【规则】 |
| 手改 | 改过的行标「已调整」，与原值可对比 | 【规则】 |
| 一键填充 | **「全部按预报价填写」**——回复率关键，**不允许省略** | 【规则】 |
| 批量调价 | 可选：在预报价基础上整体 ±X% 后填入（如行情普涨） | 【规则】 |
| 整行不供 | 该行标记"不供"，比价时无候选；**不影响"部分报价"仍算有效** | 【规则】 |
| 保存草稿 | 截止前可反复保存，**不算「已报价」** | 【规则】 |
| 提交报价 | 提交后进入 `已报价`；截止前可再次修改覆盖（**以最后一次为准**） | 【规则】 |
| 超时 | 截止后页面转只读，提交按钮消失 | 【规则】 |
| 数量单位 | 供应商看到的是询价行的**下单单位与数量**（= 采购计划的预计采购量），不是克 | 【规则】 |

### 8.10 报价是否回写预报价——默认不回写**【已确认 Q8】【规则】**

| 方案 | 结论 |
| --- | --- |
| 默认不回写（预报价只能在报价管理页维护，询价只是引用） | ✅ 采纳 —— 避免一次临时询价意外改掉长期报价 |
| 提交时勾选「同步更新我的预报价」（默认**不勾**） | ✅ 采纳为兜底选项 —— 兼顾"这格以后就按这个来" |

> **最终口径**：默认不回写，但提供**默认不勾**的勾选框。
> **勾选后只更新本次实际报过价的那些商品**，未报的行不动。

### 8.11 到期判定在原型里怎么落

纯前端原型没有定时任务，用**渲染时判定**，效果与后端定时任务一致：

```
const effStatus = inq.status === 'inquiry' && now >= inq.reply_deadline ? 'closed' : inq.status;
// 供应商应答：未报价 且 已过截止 → 展示为「超时未报价」
```

> 正式版由后端定时任务在截止时刻落 `MISSED`，前端只读；原型用上面这段保证"不刷新也显示正确"。

## 9. 预报价的作用（V2.0 已收窄）

### 9.1 只剩一个角色**【已确认 D7（收窄）】**

V1.x 的 D7 写的是「预报价有两个角色」。**V2.0 起角色 ① 作废，只有角色 ②**：

```
                   供应商端：报价管理页维护
                             │
                             ▼
             供应商端：收到询价单时的报价默认值
                （预填、可改、单位不一致不填）

   ① 商户端参考单价 —— 作废（D18）。商户端不再显示任何预报价，
      价格信息唯一入口是「报价比较」抽屉，看的是供应商的实际回价。
```

| 角色 | V2.0 状态 | 落地位置 |
| --- | --- | --- |
| ① 商户端参考单价 / 参考金额 | **作废** | —— （原 9.2 / 9.5 / 9.7 全部废止） |
| ② 供应商端报价默认值 | **保留** | 9.3 |

### 9.2 商户端参考价为什么作废**【已确认 D18 / Q3】**

| 原设计（D11） | 问题 |
| --- | --- |
| 参考价是「行 × 供应商」的二维量，必须先选供应商才显示 | 列数随供应商数量膨胀；且在"还没决定邀请谁"的时候就被迫先选供应商 |
| 每家没报的行显示「未报价」，汇总条标注「覆盖 M/N 行」 | 覆盖率是**预报价**的覆盖，与真实回价是两回事，用户容易混读成"这轮能报多少" |
| 需在页面顶部维护「拟询价供应商」多选条 | 与「发起询价」抽屉里的供应商选择**重复**，两处状态要同步 |

**现在的做法**：明细表里**一行价格都不出现**；价格统一在「报价比较」抽屉里看，数据源是**询价单的实际回价**。

> **一个必要的补偿**：没有询价单时，商户端确实"看不到任何价格"。这是有意的 ——
> 宁可没有，也不给一个来源不明确、单位可能对不上的预报价数字。
> 询价单发出后，「报价比较」能给出所有真实价格。

### 9.3 供应商端：报价默认值**【已确认 D7】【规则】**

供应商打开收到的询价单，明细行**自动带出该供应商对该商户该商品的预报价**：

| 场景 | 供应商看到 |
| --- | --- |
| 有生效预报价 | 单价列**预填**预报价，标「来自预报价」；可直接确认，也可改 |
| 预报价已停用 / 过期 | 不带出（或带出但灰显 + 「预报价已过期」），必须重填 |
| 从未维护预报价 | 空，必须手填 |
| **预报价存在但单位与询价行不一致** | **不直接带出**，提示「单位不一致，请重填」【已确认 Q9】 |

> 一份询价单动辄几十行，逐行敲价不可持续。带默认值后「全部按预报价填写」成为一次点击。
> **也正因为不是每家都报全，这个默认值只是"能填的都填上"，剩下的仍需手填。**

> **按天需求不参与报价**：供应商报价的对象仍是「商品 × 单价」，
> `by_date` 只是供货节奏信息（哪天送多少），不改变报价粒度（D20）。

### 9.4 覆盖率提示放在哪**【规则】**

覆盖率（该供应商有生效预报价的项数 ÷ 本次询价商品数）**只出现在「发起询价」抽屉的供应商候选列表里**，
作为**加价便利度提示**，帮助判断邀请谁：

```
☑ 上海鲜配    毛菜 / 净菜          已报 13/20 项   ▓▓▓▓▓▓░░░░
☑ 绿源蔬菜    毛菜                已报 18/20 项   ▓▓▓▓▓▓▓▓▓░
☐ 城东批发    毛菜 / 净菜 / 半成品  已报 0/20 项    ░░░░░░░░░░
```

| 规则 | 口径 |
| --- | --- |
| 位置 | **只在发起询价抽屉里**；详情页顶部不再有供应商条，明细表不再有覆盖率 |
| 分母 | 本次**生效商品**数（`effectiveSkuCodes`） |
| 覆盖率 < 50% | 标黄提示「对本次清单覆盖不足，多数商品需手填报价」 |
| 覆盖率 = 0 | **不阻断**，提示「无预报价，报价需逐行手填」 |
| 是否阻断 | **永不阻断** —— 预报价是加速器，不是准入门槛 |
| 报价比较里的是另一回事 | 报价比较抽屉表头显示「已报 M/N 项」= **实际回价覆盖率**，与本节无关（见 6.8） |

### 9.5 预报价缺失时的降级**【规则】**

| 场景 | 结果 |
| --- | --- |
| 供应商从未维护预报价 | 全部手填，流程照常（**不阻断**） |
| 覆盖率 0 的供应商 | 仍可勾选，仅提示需手填 |
| 某些商品有、某些没有 | 逐行预填，混合展示，不提示错误 |
| 商户端 | **看不到预报价**（已作废，见 9.2）；要看价格就发询价单，然后看「报价比较」 |

## 10. 数据模型

### 10.1 落盘 Key（原型）

| Key | 粒度 | 内容 |
| --- | --- | --- |
| **`pp:plan:v2:{档口}:{from}:{to}`**（同区间第 N 份为 `…:{from}:{to}:#N`） | 档口 × 周期 × 同期序号 | 采购计划：`items[]`（材料行 + 全局映射 + 依据）、`daily{}`（按天覆盖 + 按天数量 + 按天忽略）、`sig`、`supplierIds` |
| **`pp:inq:v2:{档口}:{planId}`** | 采购计划 | 询价单数组（含历史版本），带 `status`、供应商列表与快照明细（含 `by_date`） |
| `pp:ingmap:v1:{档口}` | 档口 | 标准食材 → 商品的选择记忆（**未升版**：语义与 v1 完全一致，只做全局映射记忆） |
| ~~`pp:plan:v1:*`~~ / ~~`pp:inq:v1:*`~~ | —— | **已废弃**：v1 key 带餐次段且数据模型不兼容，**模块加载时直接清除** |

> 沿用排餐「按范围分片落盘」的做法，`STORE_V` 进 key，结构一变旧数据自动失效。

### 10.2 采购计划的内部结构（V2.0 双层）

```js
plan = {
  id,            // '{from}~{to}'；同区间第 N 份追加 '#2' / '#3'
  seq,           // 同期序号（1 = 第一份；>1 时列表与详情标「同期第 N 份」）
  stallId, from, to,          // 无 meals 字段
  supplierIds: [],            // 上次发起询价选过的供应商（回填用）

  items: [{                   // 材料层（采购清单）
    key,        // 'ing:鸡蛋' | 'sku:SKU000601' | 'manual:{sku}:{ts}'
    ingName,    // 标准食材名（manual 行用商品名）
    source,     // 'ing' | 'sku' | 'manual'
    skuCode,    // 全局映射（'sku' 有初值；'ing' 初始为空）
    basis: [{ date, meal, recipe, pots, gram }]   // 只读派生根
  }],

  daily: {                    // 按天层
    '2026-10-20': {
      'ing:鸡蛋': { skuCode: 'S1101', qty: 2 }    // skuCode 有值 = 当天覆盖；qty = 当天预计采购量（必填）
      // 某天不采购：{ ignored: true }（按天忽略，金额与克数都不进当天询价）
    }
  },

  sig,        // 派生签名（材料行 key=克数 拼串），用于"排餐已变更"提示
  createdAt, updated
}
```

**派生单一入口（不得在别处重算）**：

| 函数 | 语义 |
| --- | --- |
| `gramOfDay(item, date)` | 该材料行在该天的克数（`basis` 按 date 求和） |
| `skuOfDay(plan, item, date)` | **当日生效商品** = `daily[date][key].skuCode \|\| item.skuCode` |
| `qtyOfDay(plan, item, date)` | 该材料行在该天的预计采购量；**未填 → 0**（必填校验与表尾计数都以 `qty > 0` 判断「填过没有」） |
| `totalQtyOf(plan, skuCode)` | 该商品所有天、所有映射到它的材料行的数量之和 |
| `byDateOf(plan, skuCode)` | `[{date, qty, gram}]`，**只含有量的天**，日期升序 |
| `daysOf(plan)` | 有料的天（当天克数 > 0）+ 有手工行的天 |
| `dayItemsOf(plan, date)` | 该天要展示的材料行（有料 + 当天手工行，忽略行排除），克数倒序 |
| `ignoredOfDay(plan, item, date)` | 该材料行在该天是否被「忽略（仅当天）」：`daily[date][key].ignored` |
| `exceptionDaysOf` / `hasException` | 被单独覆盖过商品的天 |
| `pruneDaily(plan)` | 重新生成时清掉指向已消失材料行的按天记录 |

### 10.3 实体关系

```
采购计划 (1) ──── (N) 材料行 items[]      # 全局映射 + 派生依据
材料行   (1) ──── (N) 按天单元 daily{}    # 按天覆盖 skuCode + 按天 qty
采购计划 (1) ──── (N) 询价单             # 同一时刻最多 1 份在途
询价单   (1) ──── (N) 询价明细           # 发起时快照；每行带 by_date[]
询价单   (1) ──── (N) 询价-供应商        # 每家一条，承载应答状态
询价明细 (1) ──── (N) 报价               # 本轮只留结构
标准食材 (N) ──── (1) 商品 SKU           # 选商品记忆，按 档口 × 食材
```

### 10.4 关键字段来源

| 字段 | 来源 |
| --- | --- |
| `demand_from` / `demand_to` | 采购计划周期（**无 meals**） |
| `qty` / `unit` | `totalQtyOf(plan, skuCode)` + 该 SKU 下单单位 |
| `by_date[]` | `byDateOf(plan, skuCode)`，**只含有量的天** |
| `gram` | `byDateOf` 各天 gram 之和 |
| ~~`ref_price`~~ | **作废**（D18）：快照不携带价格 |
| `answer_status` | 系统按截止时间与报价提交情况维护 |
| `close_reason` | `到期` / `全部报价` / `人工关闭` |

## 12. 异常与边界

### 12.1 明细生成与编辑

| # | 场景 | 处理 | 标记 |
| --- | --- | --- | --- |
| 1 | 区间内某天无排餐 / 该日无菜 | 跳过该天，**范围预览显式提示**（命中 X/Y 天、无排餐 N 天）；**该天也不出日期 tab** | 【规则】 |
| 2 | 区间超过 31 天 | 阻断，提示调整区间 | 【建议】【规则】 |
| 3 | 区间内完全无排餐数据 | 整页空态「这段区间没有可用用料」，不生成材料行 | 【规则】 |
| 4 | 排餐在生成后被修改 | 顶部标「排餐计划已变更，当前清单仍是上次生成的依据」+ 重新生成入口；**不自动重算** | 【规则】 |
| 5 | 重新生成后某行依据变了 | 保留采购员填的映射与按天数量，只更新克数；派生签名不一致时给「依据已变更」提示 | 【规则】 |
| 6 | 某用料无可用商品 SKU | 采购清单提示「商品库中没有关联该食材的可用商品」，可去商品中心建，或忽略该行；不阻断其他行 | 【规则】 |
| 7 | 采购员不知道「这么多克该买几箱」 | **系统不提供折算**（D14）；克数照常展示，量由采购员自行判断填写 | 【已确认 D14】【规则】 |
| 8 | 手工加行 | `source='manual'`，无排餐依据（当日用料显示 `—`），归属当前日期；重新生成后保留 | 【规则】 |
| 9 | 忽略后再重新生成 | 保持 `ignored`，**不复活** | 【规则】 |
| 10 | 大数量用料（饮用水类） | **照常成行、不隐藏、不特殊标记**；可忽略、可映射、可记忆 | 【已确认 D5】【规则】 |
| 11 | 小量调料 | 系统不强制按包装取整，也不给"买 1 袋"这类建议；取整由采购员判断 | 【规则】 |
| 12 | 同档口同区间重复新建 | **允许新建**：先弹强提醒列出区间有交集的计划（含完全相同），确认后建为新的一份并标「同期第 N 份」，已有计划不被覆盖；`id` 用 `区间#2/#3`，落盘 key 末尾加 `:#序号`（老数据零迁移） | 【已确认 Q4】【规则】 |
| 13 | 旧版（v1）数据 | 模块加载时清除 `pp:plan:v1:*` / `pp:inq:v1:*`，不读取、不迁移（模型不兼容） | 【规则】 |
| 14 | 删除计划 | 有在途询价单时禁止删除；删除时同时清掉该计划的询价单数据 | 【规则】 |

#### 12.1.2 采购明细（按天层）**【已确认 D16】【规则】**

| # | 场景 | 处理 |
| --- | --- | --- |
| 21 | 区间内某天无料 | **该天不出日期 tab**，不会出现"点进去一片空白" |
| 22 | 某天只有一道菜 | 照常出 tab，表内 1 行 |
| 23 | 🔑 **某天某个商品不买** | 点该行「**忽略（仅当天）**」：该行当天不参与采购、不计入必填、不进询价单；**不要留空** |
| 24 | 🔑 **某天某条有商品的行没填量** | 发起询价时**阻断**：「预计采购量为必填：还有 N 项没填（…等），涉及 M 天」（见 7.8 #3）；表尾 `已填 X/Y 项` 里也一眼能看出差几项 |
| 25 | 手工行数量被清空 | **行不消失**（`source='manual'` 不受克数派生影响），只能显式「删除」；**但它同样计入必填校验**，不买请删除或用「忽略（仅当天）」 |
| 26 | 手工行归属哪天 | 加在哪一天的 tab 就属于哪天；在其它天的表格里不出现 |
| 27 | 当天覆盖后想改回全局映射 | 操作列的「恢复默认」把它清回全局映射；该按钮**只在当日有覆盖时出现** |
| 28 | 未映射的行 | 商品列显示食材名 + 红标「待映射」，**预计采购量输入框 disabled**（避免填了量却不知道买什么） |
| 29 | 忽略行 | 该行**当天**不再出现在明细表、不计入必填、不进询价单；其它天照常。误点可在采购清单卡3「已忽略」恢复 |
| 30 | 锁定态（有在途询价单） | 两个页签都只读：输入框 disabled、映射按钮与手工加行 disabled；日期 tab **仍可切换**（只是看图） |
| 31 | 排餐改动后切到某天 | 与采购清单一致**不自动重算**，顶部提示已变更 |
| 32 | 按天克数 vs 采购清单合计 | 同一批数据（`items[].basis`）的不同切法，**合计必须一致**；不一致按数据 bug 处理 |
| 33 | 日期 tab 过多（31 天） | 横向滚动，不做折叠；默认落今天或第一个有料的天 |

### 12.2 询价与截止

| # | 场景 | 处理 | 标记 |
| --- | --- | --- | --- |
| 34 | 已有在途询价单再点发起 | **阻断**，toast「该计划已有询价单，不能再发起」 | 【规则】 |
| 35 | 超时未报价后想重发 | 仍**阻断**：锁不因超时解除，也**没有撤回入口**；要重来只能另建一份同期采购计划（8.2） | 【规则】 |
| 36 | 已定标后想重发 | 阻断：**已定标是终态**，不可撤回、不可再发起，也没有「取消定标」入口；要重来只能另建同期计划 | 【规则】 |
| 37 | 截止前想改截止时间 | **没有延长入口，也没有撤回入口**；要重来只能另建同期采购计划，新单重新设截止时间 | 【已确认 Q5】【规则】 |
| 38 | 截止后供应商补报价 | 拒绝，供应商端转只读「已超时」 | 【规则】 |
| 39 | 截止时 0 家报价 | 全部「超时未报价」，**无法定标、也无法撤回**，要重来只能另建同期计划；**报价比较抽屉给出明确提示**（「本轮所有供应商都没有提交报价（超时未报价）。需要重来时请另建一份同期采购计划重新发起」）【原型】 | 【规则】 |
| 40 | 只报了一部分行的供应商 | 算「已报价（部分）」，不算超时、不出局；报价比较里其余行显示 `-` | 【已确认 Q7】【规则】 |
| 41 | 全部供应商已报价 | **提前自动截止**，不等截止时间 | 【规则】 |

## 13. 与既有文档的差异与回改清单

现有三份文档采用「**供应商预报价 → 采购计划取价 → 提交即生成正式订单**」，**没有「询价单」**。本 PRD 已拍板为**询价为主、预报价兜底**，需改动下列口径。

### 13.1 模式差异

| 对比 | 预报价模式（既有文档，作废为主链路） | 询价单模式（本 PRD，主链路） |
| --- | --- | --- |
| 报价时机 | 供应商提前常驻维护 | 按每份计划临时发起 |
| 价格粒度 | `商户 × 商品` 长期有效 | `询价单 × 供应商 × 商品` 一次一价 |
| 订单触发 | 采购计划提交即生成订单 | 询价 → 比价 → 定标 → 订单（**触发点后移**） |
| 预报价的新角色 | 主价格来源 | ~~① 明细页参考价~~（V2.0 作废）② **供应商报价时的默认值** |

### 13.2 回改清单（8 条）

| # | 目标文档 · 章节 | 回改内容 |
| --- | --- | --- |

## 附录 B 评审结论（Q1–Q12）

| # | 问题 | 结论 |
| --- | --- | --- |
| Q1 | 定标后能否重开询价 | **不能**：已定标是终态，不可撤回、不可再发起，也**没有「取消定标」入口**；要重来只能另建一份同期采购计划 |
| Q2 | 询价单发起后能否改明细 / 自动重算 | **不能改**（整页锁定、不可解锁）；「重新生成」只在草稿态可用，**不自动重算**，只提示 |
| Q3 | 本轮是否包含「比价/定标」页 | **不包含**，只到询价单 |
| Q4 | 周期上限与重叠 | **≤ 31 天**；**允许重叠但提示**，不阻断 |
| Q5 | 截止前能否延长截止时间 | **不能延长**：没有延长入口，也**没有撤回入口**；要重来只能另建一份同期采购计划重新发起 |
| Q6 | 仅 1 家 / 0 家有效报价 | **≥1 家可定标**（提示仅 1 家）；**0 家无法定标、也无法撤回**，只能另建同期采购计划重新发起 |
| Q7 | 部分报价是否算有效参与 | **算**；提交 ≥1 行即有效，逐行定标；不做「一键不供」强制标记 |
| Q8 | 提交报价是否回写预报价 | **默认不回写**；给默认不勾的勾选框，只更新本次报过价的商品 |
| Q9 | 询价行与预报价单位不一致 | **不带出默认值**，提示供应商重填 |
| Q10 | 商户端菜谱用料是否随 v2.0 同步 | **同步**（统一克 + 计入开关）；采购侧不做临时折算 |
| Q11 | 询价单放哪里 | **采购计划详情页第二个页签**，不单独开菜单 |
| Q12 | 采购计划页形态 | **列表页 + 详情页** |

> Q5 是本轮唯一与推荐相反的决定，其连带效应：**催报价由可选升为必做**；**超时不自动解除锁成为硬要求**。
