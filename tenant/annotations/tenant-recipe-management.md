## 菜谱管理工作台

> 来源：`../租户端菜谱管理与授权PRD.md#5. 菜谱管理工作台`

### 入口范围
- 菜谱中心下分「菜谱管理」与「菜谱授权」两个一级入口；本页是「菜谱管理」的入口卡片页，只做导航，不展示数据列表。
- 三个卡片去向：菜谱库、分类管理、菜谱标签与字典。

### 统一菜谱对象
- 菜谱是唯一业务对象，不再区分「标准菜谱」与「设备菜谱」两套栏目。
- 是否含设备加工由加工步骤自动判定，**用户不能单独选择菜谱类型**。

### 本页不包含
- 菜单、套餐、排产、后厨设备下发、成本核算均不属于菜谱中心范围。

## 菜谱库本页规则

> 来源：`../租户端菜谱管理与授权PRD.md#6. 菜谱库`、`#6.8 批量操作`、`#6.9 下发记录`

### 数据范围
- 列表同时承载两类菜谱：租户「自行创建」与运营端「授权下发」，不分区展示，靠「来源」区分。
- 列表**不分页、不排序**：无页码控件、表头无排序入口，一次性展示数据范围内全部菜谱，筛选只做前端显隐。

### 批量操作口径
| 环节 | 规则 |
| --- | --- |
| 可勾选范围 | 仅当前可见且非禁用的行；**待完善、草稿状态的行勾选框禁用**，不能被选中 |
| 统计与操作口径 | 「已选择 N 个菜谱」与批量上架／下架的作用对象**都只取当前可见行**；被筛选或折叠隐藏的行即使仍是勾选态，也不计数、不参与操作 |
| 全选 | 只作用于当前可见且非禁用的行；部分勾选呈半选态 |
| 批量上架／批量下架 | 对已选中且状态与目标不同的菜谱执行；状态一致项自动跳过 |
| 无有效变更 | 提示「所选菜谱均已上架／均已下架」，不弹确认、不改数据 |
| 执行前确认 | 有实际变更时二次确认「确认上架 N 个菜谱？」，有跳过项时追加「另有 M 个状态无需变更，将自动跳过。」 |
| 执行结果 | 提示「批量操作完成：成功 N 个」，有跳过时追加「，跳过 M 个」 |

### 下发记录
- 头部「下发记录」打开运营端历次授权下发批次列表；每条记录对应运营端的一次授权下发批次。
- 记录包含：下发批次号、运营端操作人、菜谱数量与菜谱名摘要、下发时间；点击「查看」进入批次明细。
- 下发记录**只记录授权的有效批次**；运营端下发新版本后，处于生效中（正常）状态的批次号会显示在下发记录中。
- **最新授权版本的接收与覆盖（本期确定）**：运营端下发新版本后，**须由租户在菜谱详情的「查看」中手动更新才生效**，不自动覆盖；**未处理期间旧版本继续可用**，「有新版本」提示保留。

## 默认筛选项

> 来源：`../租户端菜谱管理与授权PRD.md#6.2 筛选项（默认可见）`

### 筛选项与语义
| 筛选项 | 可选项 | 默认 | 筛选语义 |
| --- | --- | --- | --- |
| 关键词 | — | 空 | 对「菜谱名称 + 别名 + 菜谱编号」做不区分大小写的包含匹配 |
| 来源 | 全部来源／自行创建／运营端授权下发 | 全部来源 | 精确匹配 |
| 状态 | 全部状态／待完善／草稿／已上架／已下架 | 全部状态 | 精确匹配 |
| 菜谱分类 | 全部菜谱分类／热菜·大荤／热菜·小荤／热菜·素菜／汤粥·汤类 | 全部菜谱分类 | 精确匹配「一级／二级」组合；**分类为空的菜谱在选择任一具体分类时都不命中** |
| 加工方式 | 全部加工方式／纯人工／含设备加工 | 全部加工方式 | 精确匹配系统判定结果 |

### 交互语义
- 条件之间为 **AND**；关键词随输入即时生效，下拉在值变化时生效。
- 结果通过逐行隐藏实现，不重新请求数据。
- 重置：清空全部条件（含更多筛选与时间区间），并立即重新筛选；**不折叠更多筛选面板、不弹确认**。
- **「全部菜谱分类」下拉的候选项由「分类管理」动态生成（本期确定）**：只出现状态为启用的分类，按「一级 / 二级」全路径展示；分类停用或删除后不出现在候选项中。原型为固定枚举，实现以分类管理数据为准。

## 列表字段与特殊标记

> 来源：`../租户端菜谱管理与授权PRD.md#6.5 列表字段`、`#6.6 列表特殊标记`

### 列定义
| 列 | 展示类型 | 业务说明 | 约束与备注 |
| --- | --- | --- | --- |
| 勾选框 | 复选框 | 批量操作入口 | 待完善、草稿状态禁用 |
| 菜谱信息 | 名称 + 角标 + 副行 | 主行为名称，副行为「编号 · 别名」 | 别名有值才显示；名称后可能带「有新授权版本」角标 |
| 菜谱分类 | 文本 | 「一级 / 二级」组合 | 为空时显示 `待完善` |
| 来源 | 标签 | 自行创建／运营端授权下发 | 列表内「运营端授权下发」显示为 **运营端授权** |
| 加工方式 | 标签 | 纯人工／含设备加工 | 系统判定，只读 |
| 适配设备 | 文本 | 设备加工步骤中配置的型号 | 无设备显示 `—`；型号数量**按去重后计算**，多个型号显示「首个型号 等N种」 |
| 用料 | 文本 | 用料明细条数 | 展示为「N项」；数据缺失时显示「0项」 |
| 菜谱标签 | 数量 + 悬浮详情 | 默认只显示标签数量 | 悬浮显示按分组后的完整标签；无有效标签显示 `-`（标签被停用／删除后不再计入数量与悬浮内容） |
| 版本 / 状态 | 版本 + 状态标签 | 上行版本号，下行状态 | 状态取值：待完善／草稿／已上架／已下架 |
| 更新信息 | 更新人 + 时间 | 上行更新人，下行更新时间 | 更新时间缺失时回落到更新日期 |
| 操作 | 按钮组 | 随状态变化 | 见「行操作与状态机」 |

### 特殊标记
| 标记 | 触发条件 | 说明 |
| --- | --- | --- |
| 有新授权版本 | 存在尚未处理的租户新版本 | 名称后角标，悬浮提示可在「查看」中对比并选择是否更新；**操作区不提供单独的处理入口，版本处理统一从「查看」进入** |
| 待完善（分类列） | 菜谱分类为空 | 「待完善」状态即分类未补齐 |
| 运营端授权（来源列） | 来源为运营端授权下发 | 简称展示，与「自行创建」区分 |

- **列表展示口径（本期确定）**：「适配设备」列的型号数量**按去重后计算**（同一型号在多个步骤重复配置只计 1 种）；「用料」列在用料数据缺失时**显示「0项」**（不显示 `—`）。
- **标签失效口径（本期确定）**：标签被租户停用／删除后，菜谱不再展示该标签，也不计入标签数量与悬浮内容；该菜谱**全部标签失效或原本没有标签时，标签列显示 `-`**。

## 行操作与状态机

> 来源：`../租户端菜谱管理与授权PRD.md#6.7 行操作`、`#4. 状态机与操作矩阵`

### 状态定义与可执行操作
| 状态 | 含义 | 可执行操作 |
| --- | --- | --- |
| 待完善 | 运营端下发后尚未完成租户侧必要内容 | 查看、去完善 |
| 草稿 | 已保存尚未提交发布 | 查看、编辑、提交、删除 |
| 已上架 | 已发布，可用于授权 | 查看、编辑、下架、授权 |
| 已下架 | 暂停使用及新增授权 | 查看、编辑、重新上架、删除 |

### 动作与结果
| 动作 | 条件与结果 |
| --- | --- |
| 查看 | 打开只读详情抽屉；有新版本时在此处理版本更新 |
| 去完善／编辑 | 打开编辑抽屉；**已上架、已下架状态不提供「保存草稿」** |
| 提交 | 打开编辑抽屉，提交校验通过后转为已上架 |
| 下架 | **二次确认**：「确认下架菜谱“{名称}”？下架后该菜谱将退出已授权商户的可同步范围；商户已同步形成的私域菜谱不受影响。」确认后转为已下架 |
| 重新上架 | **二次确认**：「确认重新上架菜谱“{名称}”？」，确认后转为已上架 |
| 授权 | 仅已上架状态出现；跳转「菜谱授权」页并打开新建授权向导，**自动勾选该菜谱**，停在第一步 |
| 删除 | 二次确认后删除；**仅草稿、已下架状态提供**，已上架状态无删除按钮 |

### 状态迁移与版本
| 起点 | 操作 | 终点 | 版本变化 |
| --- | --- | --- | --- |
| 待完善 | 保存草稿 | 草稿 | 不递增，置 `—` |
| 待完善／草稿 | 提交（校验通过） | 已上架 | 空或 `—` 置 `V1` |
| 草稿 | 提交（校验通过） | 已上架 | 保留原版本号 |
| 已上架 | 提交（校验通过） | 已上架 | 数字位 +1 |
| 已上架 | 下架 | 已下架 | 不变 |
| 已下架 | 重新上架 | 已上架 | 不变 |

### 行操作约定
- 行内**不提供「复制」**：菜谱一律通过「新建菜谱」创建，避免复制产物在编号、分类归属与授权状态上产生歧义。
- **下架与重新上架均需二次确认**；下架确认文案必须写明对已授权商户同步范围的影响。
- 「授权」入口只在已上架状态出现，与「授权对象必须是已上架菜谱」一致。

### 删除已授权菜谱的影响（本期确定）
- 删除已被授权的菜谱**直接影响商户的可同步范围**：该菜谱在商户侧不再可见、不可再同步。
- **不影响商户已经同步形成的私域菜谱**：商户已同步的菜谱继续保留，可独立维护与使用。

## 新建与编辑菜谱：抽屉、提交与版本

> 来源：`../租户端菜谱管理与授权PRD.md#7. 新建 / 编辑菜谱`、`#7.7 提交校验`、`#7.8 保存草稿与提交`

### 抽屉结构
- 新建与编辑使用全高右侧抽屉，标题为「新建菜谱」／「编辑菜谱」，副标题固定「菜谱中心 · 租户私域数据」。
- 主体含三个页签：`1 基础信息`、`2 用料明细`、`3 加工步骤`；切换页签不校验、不清空已填内容。
- 关闭方式：头部 × 或底部「取消」；**无关闭前确认**。

### 保存草稿与提交的差异
| 动作 | 校验 | 结果 |
| --- | --- | --- |
| 保存草稿 | **完全不校验** | 状态转为草稿，提示「菜谱草稿已保存」；草稿不能用于授权 |
| 提交 | 全量校验 | 校验通过后按状态机迁移状态与版本；提示「菜谱已提交」／「菜谱修改已提交」 |

- 保存草稿与提交发布是不同结果；**草稿尚未正式发布，不能用于菜谱授权**。
- 已上架、已下架状态编辑时**不提供「保存草稿」**，只能提交。

### 提交校验清单
1. 基础信息必填项完整（见「基础信息字段」）。
2. 至少一条有效用料，且每行必填项齐全。
3. 至少保留一个加工流程。
4. 设备加工步骤必须已配置设备型号，且**每个型号至少配置一个设备操作步骤**。
5. 所使用的分类、标签与加工字典均处于有效状态；被停用／删除的标签、字典项不作为有效内容。

- 校验不通过：抽屉不关闭，出错页签出现错误角标并自动切到第一个出错页签，提示「存在未完成的必填内容，请完善后提交」。

### 标签／字典失效时的编辑与提交（本期确定）
| 场景 | 表现 |
| --- | --- |
| 标签被停用／删除 | 该标签不再出现在标签选项中，原勾选自动取消；受影响菜谱的标签列与详情显示 `-` |
| 字典项（烹饪分类／菜谱省份／菜系分类）被停用／删除 | 候选项中不再出现该项，原值位置显示「请选择」 |
| 打开编辑时 | 基础信息页签顶部提示「该菜谱原使用的 … 已被停用或删除，请重新选择有效内容」 |
| 提交时 | 必填内容缺失时提示「存在未完成的必填内容，请完善后提交」，须更换为有效内容后方可提交 |
| 授权 | **不受影响**：标签、字典失效不阻断、不撤销授权关系，受影响菜谱仍出现在授权向导的可选菜谱中 |

## 基础信息字段

> 来源：`../租户端菜谱管理与授权PRD.md#7.3 基础信息字段`、`#7.4 外语菜谱名弹窗`

### 字段定义
| 字段 | 展示/输入类型 | 业务说明 | 约束与备注 |
| --- | --- | --- | --- |
| 图片 | 上传 1 张 | 菜谱主图 | 必填；PNG／JPEG／WebP |
| 菜谱名称 | 文本 | — | 必填 |
| 别名 | 文本 | — | 必填 |
| 外语菜谱名 | 弹窗配置 | 固定 10 语种，各语种选填 | 入口显示「已配语种 N/10」 |
| 烹饪分类 | 下拉 | 炒／炖／蒸／煮／烤 | 必填；来源为租户字典 |
| 菜谱省份 | 下拉 | 全国／四川／山东／广东／江苏／浙江 | 必填；来源为租户字典 |
| 出餐成品系数 | 数值 + % | 默认 100 | 必填；范围 0.01–999.99，两位小数 |

## 保存草稿与提交

> 来源：`../租户端菜谱管理与授权PRD.md#7.7 提交校验`、`#7.8 保存草稿与提交`

### 底部操作
| 元素 | 内容 | 规则 |
| --- | --- | --- |
| 取消 | 关闭抽屉 | 不保存任何内容，无确认 |
| 保存草稿 | 保存为草稿 | **不做任何校验**；提示「菜谱草稿已保存」 |
| 提交 | 提交发布 | 全量校验；不通过时抽屉不关闭 |

### 关键差异
- 保存草稿成功后状态转为**草稿**；草稿不能用于菜谱授权。
- 提交校验通过后：待完善／草稿 → 已上架（版本置 `V1` 或保留原值）；已上架 → 版本号数字位 +1；已下架 → 不改变状态与版本。
- 已上架、已下架状态编辑时**只有「提交」，没有「保存草稿」**。
- 校验失败统一提示「存在未完成的必填内容，请完善后提交」，并自动切到第一个出错页签。
- **并发编辑**：多人同时编辑同一菜谱时的冲突处理**本期不考虑**（不做冲突检测、编辑锁或自动合并）。

## 菜谱详情：结构与版本处理

> 来源：`../租户端菜谱管理与授权PRD.md#8. 菜谱详情`、`#8.2 版本切换`、`#8.3 更新到此版本`

### 结构
- 右侧只读抽屉，标题「菜谱详情」，副标题「菜谱编号 · 菜谱名称」；关闭方式为头部 × 或底部「关闭」。
- 内容页签：基础信息／用料明细／加工步骤；**非最新授权版本模式下另有「营养预览」**。

### 版本切换
| 元素 | 规则 |
| --- | --- |
| 显示条件 | 该菜谱存在尚未处理的租户新版本（来源为运营端授权下发且有新版本） |
| 当前版本页签 | 基础信息、用料明细、加工步骤、营养预览 |
| 最新授权版本页签 | 基础信息、用料明细、加工步骤；**不含营养预览** |
| 底部按钮 | 仅「最新授权版本」页签下显示「更新到此版本」 |

### 更新到此版本
| 环节 | 规则 |
| --- | --- |
| 确认文案 | 菜谱当前已上架时额外提示：更新后新内容将立即生效；随后确认「确认更新到最新授权版本吗？」 |

| 影响范围 | 不影响其他组织（商户侧数据不因此改变） |
| 更新后提示 | 「菜谱已更新至最新授权版本」 |

### 暂不更新
- 用户可以暂不更新：当前版本继续使用，「有新版本」提示保留，后续仍可通过查看详情处理更新。

### 接收与覆盖（本期确定）
- 运营端下发新版本后，**必须由租户在本页手动「更新到此版本」才生效**，**不自动覆盖**。
- **未处理期间旧版本继续可用**，「有新版本」提示保留，后续仍可处理。
- 下发记录**只记录授权的有效批次**，生效中（正常）状态的批次号会显示在下发记录中。

## 分类管理本页规则

> 来源：`../租户端菜谱管理与授权PRD.md#9. 分类管理`、`#9.5 停用与删除`

### 页面结构
- 左右分栏：左侧「分类结构」树用于筛选，右侧分类明细表。
- 头部唯一按钮为「＋ 新增一级分类」；二级分类从右栏标题栏的「＋ 新增二级分类」或一级分类行的行内入口创建。

### 分类体系
- 分类由租户统一维护，支持**一级、二级**两级；租户菜谱与商户组织菜谱共用同一套租户分类。
- 菜谱编辑中的「菜谱分类」来自本页数据。

### 失效分类的业务后果
| 状态 | 列表展示 | 对已上架菜谱的影响 |
| --- | --- | --- |
| 启用 | 启用 | — |
| 已停用 | **已停用** | **不自动下架**；原分类显示「已停用」；新建不可选；编辑提交、重新上架必须改用有效分类；恢复后标识自动消失 |
| 已删除 | **已删除，仅保留历史归属** | **不自动下架、不自动删除**；历史菜谱保留原分类归属并显示「已删除」，不得把历史归属静默改判到其他分类 |

### 历史数据保留（本期确定）
- 停用与删除**只改状态、不从列表移除记录**：分类名称、层级、上级关系与排序值全部保留。
- 已停用／已删除的分类**不出现在菜谱新建与编辑的分类下拉中**，也不能用于提交、重新上架或首次同步。
- 删除分类不会下架或删除任何已上架菜谱，其分类字段保持原值。
- 一级分类下仍有二级分类时**禁止删除**，需先处理二级分类。

### 排序能力（本期确定）
- 分类结构左栏**不提供拖拽排序**；顺序由分类的「排序值」字段决定（见「分类明细与操作」的排序值字段与编辑动作）。

## 菜谱标签与字典本页规则

> 来源：`../租户端菜谱管理与授权PRD.md#10. 菜谱标签与字典`、`#10.6 停用与删除`、`#10.7 字典编码规则`

### 维护范围
- 菜谱标签、烹饪分类、菜系、工艺及设备参数字典由**租户统一维护**。
- 商户端只能选择租户当前有效内容，**不能在菜谱编辑过程中新增**分类、标签或字典项。

### 五类字典与编码前缀
| 类型 | 结构 | 编码前缀 | 示例 |
| --- | --- | --- | --- |
| 菜谱标签 | 一级 + 二级 | `TG`（二级为 `{父编码}-{序号}`） | `TG001`、`TG001-002` |
| 烹饪分类 | 单级 | `CK` | `CK001` |
| 菜谱省份 | 单级 | `PV` | `PV001` |
| 菜系分类 | 单级 | `CU` | `CU001` |
| 工艺处理 | 工艺类型 + 工艺名称 + 处理步骤 | `PR` | `PR001` |

- 编码前缀**按字典类型唯一分配**，不同类型不得复用同一前缀。
- 编码在租户内按类型唯一，新增时按该类型已有记录数递增生成。

### 标签使用约束与父子级联动（本期确定）
- 菜谱标签采用一级、二级结构，**业务选择时只能选择二级标签**。
- 一级标签**删除**时，其下二级标签**一并删除**；一级标签**停用**时，其下二级标签**一并停用**。
- 一级标签**启用**时，其下二级标签**仍保持当前状态**，不随父级启用而启用。
- 二级标签**启用**时，**父级一并启用**；二级标签**停用**时，**不改变父级状态**。
- 二级标签删除不影响父级，父级保留。

### 字典失效后的影响（本期确定）
| 对象 | 租户端菜谱 | 授权给商户 | 商户端 |
| --- | --- | --- | --- |
| 标签被停用／删除 | 引用该项的菜谱不再展示该标签，全部失效时显示 `-`；再次编辑提交时提示「存在未完成的必填内容，请完善后提交」 | **不受影响**：不阻断、不撤销既有授权关系，受影响菜谱仍可被选择授权 | 已同步菜谱显示 `-` 并提示存在未完成的内容；**未同步菜谱仍可同步**，同步后显示 `-` |
| 字典项（烹饪分类／菜谱省份／菜系分类）被停用／删除 | 同上；对应下拉候选项中不再出现该项，原值显示「请选择」 | 同上 | 同上 |

- 停用与删除**只改状态、不从列表移除记录**：字典编码、名称与层级关系保留，保证历史菜谱的归属可追溯。
- 删除后行保留并显示「已删除」，操作列不再提供编辑／停用／删除。
- 已删除的项不能作为菜谱候选内容；租户恢复（启用）后可恢复选择，已被替换的历史内容不自动恢复。

### 二级标签编码与重名（本期确定）
- 二级标签编码沿用上表的「{父编码}-{序号}」形式。
- **同父标签下的重名约束本期不考虑**，不做校验限制。

- 工艺处理字典中状态为「启用」的条目，会出现在菜谱编辑的人工处理步骤「工艺名称」选择器中；停用后该项在编辑器下拉中立即消失。

## 菜谱授权本页规则

> 来源：`../租户端菜谱管理与授权PRD.md#11.1 授权列表页`

### 授权前置条件
- **只有状态为「已上架」的菜谱可被授权**；待完善、草稿、已下架，以及使用了无效分类或无效字典的菜谱不可选择。
- 授权粒度止于商户：一次授权可选择多个目标商户。

### 授权结果
- 授权成功后菜谱进入商户的**可同步范围**，**不直接写入**商户下所有组织菜谱库；各层组织自行决定是否同步。
- 同步后形成可独立维护的商户私域菜谱。
- **重复授权不得在同一商户内产生重复的可同步菜谱记录。**

### 列表结构
- 列为：授权批次／授权菜谱／授权商户／创建时间／状态／操作。
- 生效中批次提供「查看」与「撤销」；已撤销批次只读，仅提供「查看」。

### 撤销
- 撤销前二次确认：「确认撤销授权批次 {批次号}？撤销后，尚未同步的组织将不能再同步；已同步形成的组织私域菜谱不受影响。」
- 确认后**批次状态立即变为「已撤销」**：状态列置灰，该行不再提供「撤销」入口，仅保留「查看」。
- 撤销后：未同步组织不再允许同步；已同步形成的组织私域菜谱**不被自动删除、下架或覆盖**。

### 商户筛选能力（本期确定）
- 授权列表提供**按商户名称搜索**。
- **不提供**商户全选与按组织架构筛选。

### 状态定义
| 状态 | 含义 | 对商户的影响 |

## 新建菜谱授权：三步向导

> 来源：`../租户端菜谱管理与授权PRD.md#11.2 新建授权（三步向导）`

### 步骤与拦截
| 步骤 | 内容 | 拦截 |
| --- | --- | --- |
| 1 选择菜谱 | 按分类或条件筛选后勾选一个或多个已上架菜谱 | 未选择菜谱时提示「请至少选择一个菜谱」，不能进入下一步 |
| 2 选择商户 | 选择一个或多个目标商户 | 未选择商户时提示「请至少选择一个商户」，不能进入下一步 |
| 3 授权确认 | 核对菜谱明细与商户明细后提交 | 提交后生成授权批次，提示「菜谱授权创建成功」 |

### 关键规则
- **筛选只缩小当前结果，不应清除已选的其他有效菜谱**——跨筛选条件累计选择。
- 确认后生成「生效中」的授权批次，把所选菜谱加入各目标商户的可同步范围，**不是直接创建组织菜谱**。
- 授权关系条数 = 菜谱数 × 商户数（重复组合需去重）。
- 若菜谱在授权过程中失效（被下架或使用无效字典），授权应失败并说明原因。

### 商户筛选能力（本期确定）
- 第二步「选择商户」支持**按商户名称搜索**。
- **不提供**商户全选与按组织架构筛选。

## 选择可授权菜谱

> 来源：`../租户端菜谱管理与授权PRD.md#11.2.1 第一步：选择菜谱`

### 结构与规则
| 区域 | 元素 | 规则 |
| --- | --- | --- |
| 左侧 | 菜谱分类树 | 「全部菜谱」+ 各分类分组；**分组与计数取自「分类管理」中状态为启用的分类**，计数按上架菜谱实时计算；仅展示有上架菜谱的分组；「清空」用于取消已选；**分类仅用于筛选，不做选择** |
| 右侧 | 搜索 | 按菜谱名称、别名或编号搜索 |
| 右侧 | 已选计数 | 「已选择 N 个菜谱」 |
| 右侧 | 全选 | 「全选当前结果」，副文案「当前共 N 个；仅展示已上架菜谱」 |
| 右侧 | 表格 | 勾选框／菜谱信息／菜谱分类／加工方式／适配设备／版本／操作 |
| 右侧 | 行内查看 | 打开只读预览，提示当前为查看模式、仅已上架菜谱可选择授权 |

### 准入约束
- **候选集合只包含「已上架」状态的菜谱**：待完善、草稿、已下架的菜谱不出现在列表中，也不计入「当前共 N 个」与分类树计数。
- 已停用／已删除的分类不出现在分类树中。
- **标签、字典失效不影响授权**：菜谱标签或字典项被停用／删除后，菜谱**仍在可选范围内**（候选集合只看「已上架」状态），失效不阻断、不撤销既有授权关系。
- 分类筛选与勾选相互独立：切换分类不应丢失之前已选的其他有效菜谱。

## 授权详情本页规则

> 来源：`../租户端菜谱管理与授权PRD.md#11.3 授权详情`

### 展示范围
- 授权详情需保留批次状态、授权菜谱、目标商户及历史信息。

### 撤销后的影响
- 已同步形成的组织私域菜谱**不因撤销被自动删除、下架或覆盖**。

- 批次撤销后**允许**对同一批菜谱与商户再次发起授权。

## 第一期范围边界

> 来源：`../租户端菜谱管理与授权PRD.md#14. 第一期不包含`

### 明确不包含
- 菜谱审批流程。
- 商户维护租户分类、标签或加工字典。
- 租户版本自动覆盖组织菜谱。
- 上级组织自动向下级组织继承菜谱。
- 组织之间自动同步菜谱。
- 真实后厨设备下发与状态回传。
- 跨租户共享菜谱。
- 菜谱成本核算及定价。

### 影响当前页面的推论
- 租户端不存在「审批中」状态；菜谱状态只有待完善、草稿、已上架、已下架。
- 租户端不做向设备的真实下发，设备相关仅停留在菜谱内容维护。
- 撤销授权不等于删除商户侧菜谱，也不触发跨组织级联操作。
<!-- anno:end id=scope-boundary -->
